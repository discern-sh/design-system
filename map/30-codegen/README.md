# Codegen

How [`generate.ts`](../../scripts/generate.ts) turns Component Metadata, kind-family Metadata, and package assets into committed authorities under [`src/generated/`](../../src/generated/). The Catalogue's ignored example registry is a build output: [`build.ts`](../../scripts/build.ts) regenerates it under `catalogue/generated/` before bundling or verification consumes it.

Kind codegen is a family framework: [`kind-family.ts`](../../scripts/kind-family.ts) owns discovery, anatomy/stance/corpus validation, and generation for any enrolled kind family, and a family is a configuration — its lowercase word and Pascal type stem (which derive every generated symbol name, error-code template, and message), kind root, budget-remedy, release-posture, and CLI-stance vocabularies, generated file names, and the module specifiers its generated sources import. The diagram family is the first client: `generate.ts` supplies its configuration and writes the six generated files. A second family enrols by adding a configuration, never by copying the machinery.

Each folder under a family's kind root — [`src/diagram/kinds/`](../../src/diagram/kinds/) for diagrams — has one fixed anatomy and one `*.meta.ts` enrollment fact. The framework validates that anatomy, guidance, numerical budgets, deeply frozen release corpus, and the family's CLI stance pairing (description-or-enhanced for diagrams) before emitting the authored `DiagramSpec` union, the distinct normalized union returned by validation, public Metadata and Markdown author guide, exhaustive semantic dispatch, fixture/corpus registry, CLI registry, and type export barrel together. Every corpus must cover the family's declared postures — minimal, representative, structural, long-text, maximum-density, and semantic-role for diagrams — plus invalid cases and an over-budget refusal whose dimension and remedy agree with Metadata; Catalogue and CLI examples derive from the same specs. Generated dispatch is the only projection switch; kind implementations and callers never patch it. [`generator_test.ts`](../../tests/diagram/generator_test.ts) builds synthetic future kinds, malformed inventories, and a synthetic second family with its own vocabularies, so adding a kind cannot silently omit a projection or release posture and a new family cannot fork the machinery.
