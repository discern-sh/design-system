# Terminal applications

Start with `runTerminalApplication` from `@discern-sh/design-system/cli/interactive` when a screen stays open while data changes. Use `requestSelection({ presentation: "menu" })` for a single action choice outside an application. See [the public consumer guide](../../README.md#terminal-applications), [the demonstration](../../scripts/playground/application.ts) with [its layers](../../scripts/playground/application-layers.ts), [ADR 0050](../_adr/0050-applications-compose-a-grouped-list-a-following-detail-and-modal-layers.md) for the ownership decision, which supersedes [ADR 0046](../_adr/0046-own-terminal-applications-through-bounded-regions.md), [ADR 0051](../_adr/0051-layers-own-focus-and-make-the-safe-choice-one-key-away.md) for layer focus and safe confirmation, [ADR 0054](../_adr/0054-the-markdown-browser-runs-on-the-application-runtime.md) for Markdown reading bodies and nested applications, and [ADR 0055](../_adr/0055-applications-run-background-commands-beside-the-screen.md) for background commands.

The caller supplies an immutable `TerminalApplicationView` and replaces it to update the screen. Names follow two tiers: the runtime and its records — view, state, options, context, model, frame, command — are `TerminalApplication*`, and the vocabulary a view is built from is `Application*` (`ApplicationList`, `ApplicationDetail`, `ApplicationSheet`, `ApplicationKeyBinding`, `ApplicationRun`), so no bare name such as `ListSpacing` meets a consumer's or another entry point's type. The package owns everything that moves: selection by item identity, filtering, folds, zoom, scroll, column dropping, list width, density, the settle window, message timing, focus inside layers, field values, disclosures, read progress, painting, the window title, mouse modes, terminal modes, and cleanup. The caller never computes selection, focus, or scroll; it reads the read-only `context.state` when building a view or saving preferences. The view vocabulary lives in [`view.ts`](../../src/cli/interactive/application/view.ts) and [`layer-view.ts`](../../src/cli/interactive/application/layer-view.ts); the pure model in [`model.ts`](../../src/cli/interactive/application/model.ts) and [`layer-model.ts`](../../src/cli/interactive/application/layer-model.ts); the frame in [`frame.ts`](../../src/cli/interactive/application/frame.ts) and [`layer-render.ts`](../../src/cli/interactive/application/layer-render.ts); mouse input in [`mouse.ts`](../../src/cli/interactive/application/mouse.ts); the effects in [`runtime.ts`](../../src/cli/interactive/application/runtime.ts).

## The view

A view has a header bar, one body, an optional message line, key hints, up to two modal `layers`, an optional plain-text `windowTitle`, `input` preferences — `mouse` turns mouse input on, and `selectionHint` replaces the words shown once when it does — and `copy`, which replaces any of the words the package itself writes. [`copy.ts`](../../src/cli/interactive/application/copy.ts) holds every such word in one `TerminalApplicationCopy` table with English defaults (`DEFAULT_TERMINAL_APPLICATION_COPY`): generated hint labels, empty and pending states, counts such as `3 of 11`, overflow words, the challenge hint, `Then`, and the too-small notice; counts are functions so another language can inflect them. A field the caller already writes — liveness labels, a sheet's `readHint`, an editor's label, `ApplicationDetail.pending` — wins over the table. [The copy test](../../tests/cli/application_copy_test.ts) renders a matrix of scenes with every entry replaced by a marker, fails if a package-only English word survives, and fails if an entry is never shown. Where the package fits one line to its room it cuts in one of two ways ([`paint.ts`](../../src/cli/interactive/application/paint.ts)): a name — a title, a label, a cell, an identifier — where the room runs out, and prose — a message, the selection hint, a hints block's or menu item's description, a detail row's text, an unavailable item's sentence, a sheet's busy line, footnote, or disabled reason — after its last whole word, so it reads as abbreviated rather than broken; it is cut mid-word only where the word cut would keep less than half of what fits — a first word wider than the room, or a short word before a long token, as in `Add manual-co…` where a word cut would leave `Add…`. [The prose test](../../tests/cli/application_prose_test.ts) renders each prose surface at several widths and fails any cut that splits a word a whole-word cut could have kept, and walks every room to hold the half rule.

- **Header bar.** `leading` runs sit at the left gutter; `chips`, `trailing` runs, and the liveness word sit on the right. Liveness names four states — idle, busy, retrying, stale — with caller words; busy shows a moving spinner only once it has lasted `busyAfterMs`, and stale shows an attention mark. When space runs out, the gaps between chips tighten and chips drop from the end while the leading runs stay whole. Then the side the header's `yields` names gives way first: by default the leading runs close their own wide gaps and shorten to a floor of eight cells, the gap before the right side tightens, and only then do the trailing runs drop, as an identity beside counts wants; with `yields: "trailing"` the trailing runs drop while the leading runs stay whole, as a title beside its path wants. Shortening drops whole segments from the end first — the runs after a separator run such as `·`, a branch after a project's name — and cuts a run with an ellipsis, never just after a space or separator, only when its first segment alone does not fit, so a name shown whole carries none. A liveness word that is not idle — a state the person must see, such as stale — goes last either way, and below that the leading runs shorten past the floor; an idle word says the least on the line, so it goes once the identity has closed its gaps and before it shortens. [The geometry tests](../../tests/cli/application_geometry_test.ts) walk every width and fail a header that drops the counts before its identity reached the floor, a non-idle liveness word before the counts, or an idle word after the identity's last segment, or that cuts a name it could have shown whole. While a list filter applies, the left side becomes the filter field: the filter's `label`, the query with a cursor while it is being edited, and `N of M`.
- **Body.** `master-detail` is a grouped list with a `ApplicationDetail`; `list` is a grouped list alone; `reading` is one scrolling document remembered by id — a `CliBlock`, or Markdown whose links a reader follows (see [Reading bodies](#reading-bodies)); `empty` is a title, a short explanation — one paragraph of runs, or several lines of runs, each wrapped and centred on its own, so two sentences can read one per line — a selected primary hint whose action Enter runs, secondary hints, and an optional list below — Down moves from the primary into that list and Up returns.
- **Message line.** One row above the footer, only while a message is present; below 14 rows it replaces the footer. An `optional` message — a teaching line that reads only whole — shows only where its runs and trailing runs fit the line whole, and never in the footer's place; while it is not shown, Escape passes it by and state reports omit it. A message dismisses after its `dismiss.afterMs`, at the next key when its `dismiss.onKey` is true, or with Escape. Each dismissal is reported through `onDismiss` and the package hides the message at once; see [Dismissal](#layers) for when a view must omit it.
- **Key hints.** `footer` is a `KeyHints` value laid out by [`layoutKeyHintsCli`](../../src/cli/key-hints.ts) inside two-cell gutters. A hint only names a key; what the key does is bound elsewhere, so every key the footer, `zoomFooter`, or an empty body's hints advertise must be one the body reserves, Escape, Ctrl+C, or a base keymap binding — a view that advertises a key nothing handles is refused. An empty body's `primary` and a reader's `keys` are `ApplicationActionHint`s: they carry the action their key runs. While the filter field owns input the package shows its own editing hints and keeps only non-printing right-cluster hints; while the detail is zoomed it adds Up/Down after the primary and Back on the right, unless the body supplies `zoomFooter`. While a layer is open the footer is the layer's own, described under [Layers](#layers).

`validateTerminalApplicationView(view, { keymap, viKeys, state })` returns every broken rule as data — duplicate ids, a detail that follows another list, cells for undeclared columns, glyphs wider than one cell, the keymap's own rules and its collisions with what the view reserves, a message or layer the `state` lists as dismissed and the view still declares, and the layer rules below — and the runtime refuses a view with any issue: inside a callback the update throws, and from the mailbox the session fails with the same error after cleanup. An application that builds layers from observed data can keep its session instead by supplying `onViewRejected(issues, context)`: then a rule broken inside a layer — any issue under `layers[N]`, or a layer-scoped binding that collides with that layer's keys — refuses that layer alone. The package adopts the view without it, reports it to `onDismiss` as `refused`, so the caller drops it like any dismissed layer, and hands the issues to `onViewRejected`; background commands run on, and a corrected version of the layer opens as new. A rule broken outside the layers still fails the session. `TerminalApplicationConfig.refuseBrokenLayers` turns the same refusal on for a pure model. [The refusal tests](../../tests/cli/application_refusal_test.ts) break one rule of each family per layer kind and require the layer alone to be refused. A caller can build the whole context from the package's own state, whose `dismissed` lists what the next view must omit. The model a pure caller holds, `TerminalApplicationModel`, is opaque: only `createTerminalApplicationModel`, `updateTerminalApplication`, `transitionTerminalApplication`, `renderTerminalApplication`, `terminalApplicationState`, and `terminalApplicationDeadline` read or advance it, so its bookkeeping stays free to change.

## Grouped lists

A `ApplicationList` has a stable id, groups in display order, trailing `columns`, a `minTitle`, roomy and tight `spacing`, an optional `filter`, optional `density`, and a `settleMs`. Empty groups are hidden.

**Rows.** An item row is a selection bar, its one-cell marker glyph, its title with any faint `titleSuffix` kept through truncation, and its cells in declared columns. The selected row carries the accent bar, a bold title, and the selection fill across the list's width; on a selection, faint text rises to muted so it stays legible. At 16 colours or without colour no fill paints, and the bar (or `>` in ASCII) with the bold title carries selection. A receded selection uses the muted selection fill and a faint bar. A cell fits its column by dropping whole trailing runs, then truncating the first. Columns drop lowest `priority` first while the title would be narrower than `minTitle`; a column without a priority never drops. A list is roomy beside a wide detail or when it fills a terminal at least `spacing.tightBelowColumns` (56) wide, and tight otherwise.

**Groups.** A fixed group's header shows its bold title, its count, and its `aside`, and navigation skips it. A foldable group's header is selectable; folded, it becomes a fold row (`▸ Paused 3`). Enter folds or unfolds either. `initiallyFolded` applies the first time a group appears. While a group row holds the selection the package owns what the screen says about it: the detail and the strip list the groups the row stands for with their counts and asides and what Enter does, the strip drops the Space key because a group does not zoom, and the footer becomes `↵ Show` or `↵ Hide` and `↑↓ Move` beside the caller's right cluster, since the caller's item hints would promise actions a group row does not take.

**Headless groups.** A `headless` group shows its items with no header row, as entries pinned above the titled groups want — an overview, a way to every command — and its title is never drawn. Its items are ordinary rows: they take the selection, which starts on the first of them when the group leads, carry the following detail, match the filter, run their `primary` with Enter or a click, and zoom, where the breadcrumb names the item alone. Tab and Shift+Tab reach the group as they reach any group, and it stands apart from the next group by the same blank row, which goes with the others when the list is tight. It never folds — not with Enter, not to fit a short screen — while its rows still count toward fitting. A headless group declares none of the fields only a header or summary row shows (`shortTitle`, `count`, `foldable`, `initiallyFolded`, `aside`), and a density `foldOrder` never names it; the field table in [`validate-rules.ts`](../../src/cli/interactive/application/validate-rules.ts) names every group field's role, so a new field must say which side it is on. Whether a group shows a header is structure: a group that becomes headless, or stops being so, waits for the settle window as a membership change does. A group with `counted: false` holds the application's own entries rather than the list's content: a filter passes over its items, which hide while one applies and count toward neither its matches nor its total, and zoom numbers only counted items, showing no position on these; they still take the selection, walk in zoom, and count in the overflow markers. [The headless tests](../../tests/cli/application_headless_test.ts) hold the contract.

**Navigation.** Up and Down move between selectable rows without wrapping; Home and End reach the ends; Tab and Shift+Tab reach the first row of the next and previous group. With `viKeys`, j and k move too. The list scrolls only when the selection comes within one row of an edge, never centring it. A group whose header has scrolled away keeps it as a sticky first line, a slice that starts inside a headless group gives its first line to the upper marker, which an item row has no room for, and a header never ends the viewport while its rows are hidden below: the list shows one more row when the selection keeps its line and margin, and otherwise holds the header's row blank. `↑ N more` and `↓ N more` count hidden items, those a summary row holds included. Unfolding a group scrolls its rows into view as far as the selection allows.

**Filter.** `/` turns the header into the filter field. Typing narrows the list by title and keywords (substring by default, in-order fuzzy when asked), while Up and Down keep moving through matches. Enter keeps the filter and returns keys to the list; Escape clears it. Groups never fold while a filter applies.

**Density.** When the list does not fit, blank separators go first; then, if `density` is declared, quiet groups fold into one summary row (`▸ Scheduled 1 · Idle 1 · Paused 3`) in `foldOrder`, by default bottom-up. Headless groups, `neverFold` groups, and the group holding the selection never fold. Density is decided only on a resize or a membership change, and as if no message were shown, so neither a key nor a passing message refolds the list — except that a decision counts the row of a message that stays (one with no timeout and no key dismissal) and, in a list's first decision, of any message shown, so a first frame folds a quiet group rather than scroll groups out of sight. When the folds leave the separators room, they stay. Enter on a summary row unfolds every group in it; a caller selection with `reveal` unfolds only its own.

**Settle window.** Membership and order changes wait until no key has been pressed for `settleMs` (1500 ms); content updates at once. A caller selection of an item that is still settling applies the pending membership.

**Identity.** Selection is anchored to item id. When the selected item moves to another group, the selection follows it and keeps its screen line where possible. When it disappears, or joins a folded group, the selection moves to the next item that stays in its group, otherwise the first row of the next group, otherwise the previous row. `onSelectionMoved` reports either move as `regrouped` or `removed`. Group-level rows have selection identity too, so a fold row stays selected as it opens.

## Following detail

`ApplicationDetail` names the list it follows and holds detail blocks by item id; an item without content shows the `pending` label. One block builder renders `heading` (the aside beside the title on wide screens and in zoom), `state` (glyph, bold toned label, muted qualifier), `text` (muted sentences), `facts` (a label column that grows to the longest label), `meter`, `marks` (each `ApplicationDetailMark` with optional `lines` hanging two cells under its text, such as the files a step touched; a `compact` block sets its text one space after the mark and its lines at the text's own column, as an evidence list in a narrow column wants), `rows` (`ApplicationDetailRow`s: a fixed `lead` cell, text that takes the rest and truncates, and trailing `columns` that drop by priority like a list's), `hints` (the wide tier only, in the split and in zoom alike, because the footer already names the keys; sibling hints blocks share one key column), `block` (any Component `CliBlock`), an `ApplicationMarkdown` (Markdown read as a reading body reads it, at the detail's width, but from the detail's text column rather than centred at its measure, so it lines up with the blocks above it), `pending`, and `section` (a faint title, count, and caption over its blocks, shown only while one of them shows: when every block renders nothing, such as hints below the wide tier, the section renders nothing either). Blocks are one blank line apart, and a block that renders nothing leaves no blank line behind, except that text or a meter directly after a state belongs to it. Lines that fit keep their spacing; longer ones wrap with hanging indents. While lines stay hidden below, a detail viewport ends after a whole unit — a mark with its wrapped text and lines, a fact with its values — and never on a blank row or a title (a heading block, a section's title, a Markdown heading and its rule), which moves below the fold with the lines it heads; `↓ N more · PgDn` sits directly beneath the last line shown, and the rows that frees stand blank beneath it. Only a unit too tall to show whole beneath its title is cut. [`viewportEnd`](../../src/cli/interactive/application/detail-render.ts) is the one rule the detail, zoom, reading bodies, and every panel's body share.

The detail never takes focus. Page Up and Page Down scroll it a page and Shift+Up and Shift+Down a line; the package remembers scroll per item id. A page continues from where the last one ended: the frame records in the model's geometry the scroll at which Page Down shows the first hidden line first and the furthest scroll back from which Page Up still reaches the first line shown, so a viewport that ended early never makes paging skip a line. `↑ N more · PgUp` and `↓ N more · PgDn` name hidden non-blank lines, the upper one on the top padding row when there is one. Space zooms the detail to the whole body with a breadcrumb (`Group  ›  Item`, the item alone in a headless group, and `i of n`, or the caller's `breadcrumb` runs); Up and Down then walk items only, and Space, Escape, or Left return. The position counts exactly the counted items that walk reaches — those a filter matched, less any folded away — so every count is a step away; an uncounted item walks like any other and shows no position. Zoom lays the detail out roomily, as the wide tier does, but shows the blocks the split shows at the width tier, larger: below the wide tier its hints stay hidden. [The geometry tests](../../tests/cli/application_geometry_test.ts) walk zoom to its end at every pinned height and check its hints at each tier.

Below `collapseBelowColumns` the detail becomes a strip above the footer: the item's `strip.title` runs with the Space key at the end, then whole `strip.facts` joined by a separator. Below `strip.shortBelowRows` it is one line of facts (or the title when no fact fits). Without surface fills a rule introduces a two-line strip; a one-line strip gives that row to the list.

## Reading bodies

A reading body scrolls one document with the arrows, the page keys, Home, and End, and the package remembers its scroll by the body's id. Its content is a Component `CliBlock`, or an `ApplicationMarkdown`: Markdown source, optional diagram and chart resources, and a readable `measure` (default `DEFAULT_APPLICATION_READING_MEASURE`, 72; at least 16) at which the package renders it through the Markdown authority and centres it in wider bodies; as a detail block it starts at the detail's text column instead. [`markdown-reading.ts`](../../src/cli/interactive/application/markdown-reading.ts) renders the document and derives each link's identity, destination, and cells from the neutral Markdown document and the shared cell projection, and each heading's row; [`reading-model.ts`](../../src/cli/interactive/application/reading-model.ts) owns link focus.

Markdown reads in the headings' reading treatment: the first level carries no motif marker and a quiet rule, and the second no rule, because in an application the accent marks selection and focus. A page ends as a detail viewport does — never on a blank row or a heading while lines beneath it are hidden, the lower marker directly beneath the last line shown — and pages continue from where the last one ended; the overflow markers end at the document's right edge rather than the window's, so they sit beside the text they count. A Markdown document's links are its controls. Tab focuses the first link on screen or below it, then the next; Shift+Tab the last on screen or above it, then the previous; both stop at the ends. The focused link carries a non-colour marker and is always on screen; scrolling, by key or wheel, leaves it. Enter follows the focused link and a click follows the link under it: a fragment naming a heading of the same document scrolls there, and every other link reaches `onLink`. Escape leaves the links before it closes anything else. While a link has focus the footer is the package's — Enter Open, Tab and Shift+Tab Next, Escape Done — keeping the caller's right-hand hints for other keys; otherwise, when the document has links, the package adds Tab Links after the caller's left hints. A new width rewraps the document, and the package finds the line that was at the top again by its text, choosing the match nearest the proportional position so repeated rows never pull it to the first duplicate. `context.reveal(readingId, target)` restores a `scroll` position the state reported, brings a `heading` to the top, or focuses a `link` and brings it on screen. `TerminalApplicationState.readingFocus` names each reading body's focused link, and `focusedControlId` reads `<reading>:link:<link>` while one has focus. [The reading tests](../../tests/cli/application_reading_test.ts) hold this contract; [ADR 0054](../_adr/0054-the-markdown-browser-runs-on-the-application-runtime.md) records why it exists.

## Geometry

`ApplicationSplitRules` (default `DEFAULT_APPLICATION_SPLIT_RULES`) govern a master-detail body:

| Columns                              | Layout | List                                  | Detail                                               |
| ------------------------------------ | ------ | ------------------------------------- | ---------------------------------------------------- |
| at least `wideAtColumns` (100)       | split  | `clamp(needed, 36, cols − 48)`, roomy | the rest, padding 3 and 2                            |
| at least `collapseBelowColumns` (80) | split  | `clamp(needed, 36, cols − 39)`, tight | the rest, padding 2 and 1                            |
| below                                | strip  | full width                            | a strip of two lines, one below 14 rows; Space zooms |

Where fills do not paint, a faint rule in the detail's first padding cell parts it from the list. `needed` is the width at which no column drops and the longest title, capped at `maxTitle` (32), fits whole; a title shorter than the list's `minTitle` still reserves `minTitle`, because a narrower title share would drop a column; `share` sizing instead takes a fraction of the width. The width is decided with density, on resize and membership change only. From 20 rows a blank row separates the header and the body; below 14 rows the detail loses its top padding and a message replaces the footer.

The minimum is 32 × 10 (`TERMINAL_APPLICATION_MINIMUM`). Below it the screen shows "Too small", the size it needs, and the view's `tooSmallHints`, each of which must name a base binding and draws as a key in ink, since no hint there is what Enter does; navigation waits while the bindings in force still run exactly as at full size — the top layer's while one is open, and only `inFields` bindings while a field, a palette's query, or a filter owns input — and growing restores the screen with its state. The review sizes — 120 × 30, 80 × 24, 60 × 20, 40 × 20, 80 × 13, and 32 × 10 — are one list, `APPLICATION_REVIEW_SIZES` in [the demonstration](../../scripts/playground/application.ts), which the geometry tests, the layer sweeps, the capture script, and the benchmark's resize sweep all iterate. The [geometry tests](../../tests/cli/application_geometry_test.ts) pin each in five colour postures and fail a review size without an expectation: every frame fills its viewport exactly, the layout, flag, and age columns match the tier, and every visible row's label and age end on one column.

## Layers

A layer is a sheet, a menu, a palette, a form, or a reader, declared in `view.layers` bottom to top, at most two deep (`APPLICATION_LAYER_DEPTH`). Only the view opens or removes a layer. The top layer owns every key; the body and any lower layer recede — every tone becomes faint, weight drops, and the selection keeps its muted fill — and keep every decision they made without the layer, so closing it restores them exactly. A receded backdrop cannot scroll, so it draws no overflow markers and gives their rows to content — the list fills to its last row, cutting a group partway with its header kept, and the detail shows its next line — and a receded list keeps the blank row between groups even where its density gave it up, showing fewer rows instead.

**Placement.** Beside a wide master-detail list (from `wideAtColumns`), every layer occupies the detail column unless its `anchor` says otherwise: sheets, menus, and forms size to their content from the top of the column and the receded detail shows below in whole blocks only, starting with the first block the layer did not cut across and set directly beneath it, so no section's tail shows without its title and no blank rows stand before a block; where no whole block fits, the layer takes the rows to the column's foot instead; palettes and readers fill the column. Elsewhere sheets, menus, and forms sit at the bottom across the full width, sized to content; a palette sits at the top and a reader takes the body. An `item` layer at the bottom leaves one row, and the receded list above it scrolls so the selected item stays in view. Below 56 columns every layer takes the body. A layer that names `anchor: "detail"`, a palette included, gets exactly the default: the detail column at the wide tier, and its own place below it. Layers never clip list rows: they take whole rows or the whole detail column.

**Panels.** [`layer-render.ts`](../../src/cli/interactive/application/layer-render.ts) draws every layer as one panel on the raised surface: pinned head rows (the title and aside, a banner, the busy line), a scrolling body with `↑ N more · PgUp` and `↓ N more · PgDn`, and pinned foot rows. Where surfaces paint, the frame is fill; at 16 colours and without colour it is a rounded box (`╭╮╰╯`, ASCII `+-|`) with the same geometry. Content starts three cells in (two below 56 columns), and a selected or focused row carries the selection bar in the frame's first inner cell. The foot is sized from the variant the frame draws — the overflow line only while body rows are hidden — so no rows stand empty for a longer foot; on a short screen blank rows go first, and the body keeps at least one row. The title's gap goes when that lets the body fit or the body would keep under three rows — so a reader or palette that scrolls either way keeps the row between its title or field and its first line — and in a sheet or form as soon as the body overflows, since a body that ends at a whole unit gives its spare row back to that gap; a section title that would end a scrolling viewport takes the title's gap for its first row. A sheet's or form's foot names what the body hides on a row of its own directly beneath the body's last row, and while rows stay hidden that body ends at a whole unit — a mark with its wrapped text and lines, a fact with its values, a challenge's label — and never on a blank row; the rows it leaves free fall beneath that marker, the first restoring the title's gap ([`layoutDetailBlocks`](../../src/cli/interactive/application/detail-render.ts) records which lines continue a unit). Its upper marker then sits at the start of the row to match; a menu, palette, or reader, whose markers both sit in the body, keeps them against the end. A reader's body ends at a whole unit the same way, never on a blank row or a title, with its lower marker directly beneath; the rows that frees fall beneath the marker, the first restoring the title's gap. A menu's or palette's lower marker stays on the panel's last row, so no row inside its frame stands empty, and there a viewport that ends on a blank separator takes the foot's gap for one more row. Once scrolled, an upper marker takes the first row and stands for the line beneath it as well, so every step reveals a new line at the bottom; detail, zoom, and reading viewports follow the same rule. A section title in a menu or palette keeps with its first row the same way a list's group header does: a viewport that would end on it shows one more row when the highlight stays in view, and otherwise gives the title's row to the lower marker. [The widow tests](../../tests/cli/application_widows_test.ts) hold all three rules, and [the viewport-end tests](../../tests/cli/application_viewport_end_test.ts) walk the detail, zoom, a reading body, and readers at every review size, checking each ends after a whole unit with its marker directly beneath and that paging both ways shows every line.

**Sheets.** A sheet states consequences first in `body` blocks, which are never elided or shortened. Its `state` is `loading`, `ready`, `changed`, `gone`, `working`, or `failed`; `loading`, `changed`, and `gone` disable every button but the safe one, and `loading` and `working` show the `busy` line with a spinner. With `requireFullRead` (the default when a confirm or destructive button exists), confirm and destructive buttons stay disabled until every body line has been on screen while the sheet was the top layer — the package records which lines each frame showed, so a jump with End or a three-line wheel step never counts the lines it skipped; the row beneath the body then reads `↓ N more · PgDn` and the sheet's `readHint`, the footer offers PgDn, and the footnote — the sheet's closing sentence — stays with the buttons. The gate lifts once per review. A review is the time a sheet spends out of `loading`, so a sheet can open at once and fill in when its plan arrives: nothing a loading sheet shows counts as read, and a sheet entering or leaving `loading` starts its review over exactly as a new sheet starts it — nothing read, the challenge's text empty, no two-click arm, focus on its initial control (a challenge that arrives with the plan takes focus), and the body at its top; only open disclosures stay. Nothing read, typed, or focused before the plan arrived, or against an old plan, answers the new one, and [the layer tests](../../tests/cli/application_layers_test.ts) require a sheet after either crossing to report exactly the state of one opened fresh. A `challenge` adds a field whose value the package owns; a destructive button with `requiresChallenge` enables only on an exact match, and the package shows how many characters remain, `Matches`, or `Does not match` unless the challenge supplies its own hint. In progress mode, `activity` (`ApplicationActivity`) replaces the body and the challenge: waits, each step with its glyph, the active step's running time and finished steps' durations, `Then` lines, and a meter against `typicalMs`; the title row shows the total, and the buttons are the safe one and at most one destructive one. A progress sheet may set `buttonRow: false`: the row is not drawn, Enter does nothing, and Escape stays the safe choice.

**Buttons.** Exactly one button is `safe`; Escape, the safe button, and a click outside the layer all dismiss. Buttons are padded words of constant width: focused `› Label ‹` on the focus fill (the danger fill for destructive), resting on the control fill, disabled faint on the surface fill; without fills, focused is bold `› Label ‹`, resting `[ Label ]`, disabled `( Label )`. A focused button that cannot run keeps its markers around a faint label (`›(Label)‹` without fills), and its `disabledReason` replaces the footnote while it has focus. Only `alternative` buttons take a `key`. [`renderButton`](../../src/cli/interactive/application/layer-render.ts) is the one authority. Buttons sit right-aligned on one row, with the footnote or a focused button's disabled reason beside them or wrapped above them; when they do not fit one row the gap between them closes to one cell, and then they stand one per row, so no button is left alone beneath the others. A foot that would take the rows the body's first three lines need instead packs as many buttons to a row as fit and cuts the footnote to a line, and shorter still names what the body hides in the footnote's place. [The sheet layout tests](../../tests/cli/application_sheet_layout_test.ts) hold the foot, the whole-unit end, and the button and disclosure rows.

**Disclosures.** A `ApplicationDisclosure` folds content such as a technical plan behind one row and one key. Closed disclosures share one row while they all fit it, and otherwise stand one per row with their keys against the end, as an open one does; an open one takes its own row, its content follows, and opening scrolls its row to the top. Its `key` works while focus is outside a text field, and its `fieldKey` in every focus state; whenever a text field can own focus, every disclosure needs a `fieldKey`, so each stays one key away.

**Menus.** Items run their action with Enter or Right (source `menu`). With `columns: 2` on a panel at least 56 cells wide, sections fill the first column, then the second, never splitting, and Up and Down move in that reading order; Tab reaches the next section. `lettersActivate` lets an item's key run it. `/` filters by label. `unavailable` items fold into one section that Enter opens; Enter on one of them shows its sentence and never activates. A section's own `unavailable` items sit after its items with their `reason` beside them — a short phrase such as `not installed`, else the sentence cut to fit — and like the folded section's they explain themselves on Enter with the full `sentence` and never run. The highlighted item's `description` shows beneath the menu, in a space sized for the longest one so movement never shifts the panel — an item without one names itself there — and a menu `footnote` follows it. While choices hide below, the rows a shorter description leaves go to them; otherwise they stand above the description, so the panel never ends on empty rows.

**Palette.** The query field always owns input. A blank query lists every section; typing ranks items across sections by an in-order fuzzy match on label, context, and keywords (word starts and consecutive runs rank higher), and the best match is highlighted. Up and Down move while typing, Enter runs the highlighted item, and Escape clears the query before it closes. An item's meta and key render in their own columns.

**Forms.** Text fields (single or multi-line, with a hint and `required`), choice fields (Left and Right move between options, skipping disabled ones), and folded field groups (`kind: "group"`), then caller `preview` blocks, disclosures, a footnote, and buttons. Focus starts in the first text field; Enter there moves to the safe button, Tab and Shift+Tab cycle every control, and Up and Down move between fields. Confirm buttons stay disabled while a required field is blank. A multi-line field's `editor` chord runs its action, which returns a foreground command; the caller writes the edited text back with `context.setField(layerId, fieldId, value)`. Written text is normalised as typing would leave it — line breaks become newlines in a multi-line field and spaces elsewhere, tabs become spaces, and other control and format characters drop, keeping the joiners emoji need — and a choice field accepts only an option that can be chosen; any other value fails the session like an invalid view. Every change reaches `onField`, so the caller rebuilds the preview from it.

**Readers.** A title, blocks that scroll — in two `columns` read top to bottom when the reader is at least 70 cells wide, split where the taller column is lowest and never inside a block, each column with its own key column — optional focusable `rows` (a `ApplicationList` whose selection follows identity like any list and whose Enter runs an item's `primary`; its id must differ from every other list on screen, because selection is remembered by list id), `keys` whose actions run while the reader is on top, and a `footnote` after everything. Escape or Left goes back.

**Focus.** The top layer owns focus, and only the package moves it. A control that receives focus scrolls into view — on opening, when a review starts over, and when a focused control disappears too — and so does a field each time it handles a key, so text never lands in a field the person cannot see. A sheet still opens at the top of its body, so consequences read first: its challenge sits after them while they fit, and while they overflow it pins above the buttons, beneath the line that counts what the body hides, so the consequences read from the top and the challenge's field takes keys in sight; only on a screen too short to keep three body rows beside it does the body scroll just far enough to show the field. Opening a layer focuses its initial control: a sheet's challenge or a form's first text field, else the safe button; a menu's `initialItemId` or first item; a palette's query, with its `initialItemId` or first item highlighted and in view; a reader's rows. Closing a layer returns focus to the layer beneath with its remembered position. View updates never change the open layer or its focus; a focused control that disappears gives focus back to the initial control. `context.state.layers` reports each layer's focused control, highlight, query, open disclosures, and scroll; `fields` its field values; `fullyRead` each sheet's read progress.

**Keys.** `terminalApplicationLayerKeys(layer)` names the keys a layer handles while focus is outside a text field: sheets and forms use the arrows, page keys, Home, End, Tab, Shift+Tab, Enter, Space, and Escape; menus add Right and drop Space, and claim `/` unless `filter: false`; palettes keep only movement, Enter, and Escape because the query takes the rest; readers use movement, Left, Tab, Enter, and Escape. Disclosure, alternative, menu item, and reader keys are claimed per layer, and a `{ layer }` keymap entry may take none of them; letters never reach a confirm or destructive button, and no alternative button, external-editor chord, or layer binding may carry the identical action of a confirm or destructive button on its layer, since one key would then run it around its gates. The layer's footer is generated: what Enter does now first (the focused button's label, `Buttons` from a field, `Show` or `Hide`, `Why` on an unavailable item, a menu's `enterLabel` or highlighted item), then the layer's keys — field chords instead of letters while a field has focus, and a disclosure's `openHint` while it is open — then the caller's `hints`, and last Escape with the layer's `escapeLabel`, else the safe button's label or the copy's close or back word. As the footer narrows, generic hints — `←→ Choose`, a field's Tab, disclosure keys, `PgDn Read more`, the caller's hints — drop first, then the keys of buttons on screen, and Escape's hint last; once only those ranked hints remain the primary's label shortens to eight cells before one of them drops (`KeyHint.rank`), so the way out and a visible button's key stay in sight at every size. The footer's primary is what Enter does: when Enter does nothing — a progress sheet without its button row, a disabled button focused, a palette or menu with nothing highlighted, a reader without rows — Escape's hint leads instead, so the way out is the last hint to drop, and the footer sets `primary: false`, so no key takes the accent Enter's hint owns. A caller hint must name a key the layer handles or a `{ layer }` binding, so a layer never advertises a key that does nothing.

**Dismissal.** Escape, the safe button, and a click outside report `onDismiss({ layer }, via)` with `escape`, `safe`, or `click-outside`, and a layer refused for breaking a rule reports `refused`; the package hides the layer at once. One input may dismiss a message and a layer together, and a view supplied by an earlier callback of that input may still declare what a later one reports, so the package judges the view that stands once the input's callbacks finish: if any callback replaced the view, that last view must omit every message and layer reported dismissed. A caller that does not replace the view keeps the dismissed parts hidden, and its next view must omit them. Keys typed after the key that opened a layer land on that layer, because a view updated inside a callback applies before the next key is decoded.

## Mouse

Mouse input is off unless the view sets `input.mouse`. While it is on, the painter turns SGR button and wheel reports on with the paint, and the first frame shows the selection hint (`Shift-drag to select text`, or `selectionHint`) on the message row until the next input or six seconds. Each frame records where it put every clickable thing ([`hits.ts`](../../src/cli/interactive/application/hits.ts)); mouse input resolves against exactly that frame. A click selects a list row, and a click on the selected row is Enter (source `click`). The wheel over a list moves its selection, over the detail or a reading body scrolls three lines, a click on a link in a Markdown reading body follows it, and over a layer scrolls a sheet or form or moves like the arrows elsewhere. A click on a key hint presses its key, and a click on a header chip with an action runs it (source `chip`). Inside the top layer, a click focuses a field, toggles a disclosure or field group, or highlights a menu or palette item, and a second click on the highlighted item runs it. A safe, plain, or alternative button activates on one click; a confirm or destructive button takes one click to focus and a second to activate, and any key, any click elsewhere, or a change of the sheet's state in between starts over, so the second click always answers the review the first one saw. A click anywhere outside the top layer is the safe choice. Releases and buttons other than the left one do nothing. When the screen is released while reports are on, or after mouse input was observed, the painter turns reports off and the runtime drains reports already queued behind a cursor-position fence, so none reach a foreground child; mouse events read before the handoff are dropped, because their targets belong to a frame that is gone, while keys typed ahead apply when the screen returns.

## Input and callbacks

The runtime decodes one input event at a time. For each it applies the package's transition, then calls `onField`, `onSelectionMoved`, `onSelectionChange`, `onDismiss`, and `onAction` or `onLink` in that order; `onLink` returns a command as `onAction` does. `context.update(view)`, `context.select(listId, itemId, { reveal })`, `context.setField(layerId, fieldId, value)`, and `context.reveal(readingId, target)` inside a callback apply at once, so the next key already sees them; from elsewhere they wait in a coalescing mailbox and apply only between inputs. Callbacks that keep changing the selection fail instead of spinning. `start(context)` runs once after the first frame and returns subscription cleanup; the package delivers the initial selection change after it.

The keys the package reserves depend on the body, and `terminalApplicationReservedKeys(body, { viKeys })` names them: a list reserves Up, Down, Home, End, Page Up, Page Down, Tab, Shift+Tab, and Enter, and `/` only when it declares a filter; a master-detail body adds Shift+Up, Shift+Down, Space, and Left; a reading body reserves the arrows, page keys, Home, and End, and a Markdown one Tab, Shift+Tab, and Enter too; an empty body reserves Enter, and its list's keys when it has one; j and k join with `viKeys`. A `ApplicationKeyBinding` binds any other key to an action, so a plain list may bind Space, Left, or `/`. Base entries apply only while no layer is open, and `{ layer }` entries only while that layer is on top. A key that names no decodable key, repeats in a scope, or is a printing or editing chord marked `inFields` throws when the session starts; a base binding on a key the adopted view's body reserves is a view rule, checked each time a view is adopted, so switching bodies cannot silently shadow a binding. An `inFields` binding also fires while the filter field owns input; it must be a non-printing chord outside `APPLICATION_EDITOR_KEYS` and the editing keys. The package handles Escape first — clear the filter, leave zoom, dismiss the message — and an Escape binding receives it only when nothing is left to close. The package never exits on Escape; only a binding that returns `exit` does. Ctrl+C throws `InteractionCancelled` after restoration unless a base binding claims it; layers cannot bind it, so it means one thing under every layer and at every size. Enter runs an item's `primary` action with source `enter`; bindings run with source `key`.

`onAction` returns nothing, `{ kind: "foreground", handoff?, run }`, `{ kind: "background", id, run(report, signal) }`, `{ kind: "exit", epilogue? }`, or a nested command from `nestTerminalApplication`; the kinds are one set checked against the command union. A foreground command releases the terminal, prints its handoff line on the normal screen, runs, and resumes the same state; keys read before the handoff wait for the return. A background command runs while the screen stays live and never reads input: each `report(steps)` reaches `onReport(id, steps)` between inputs, coalesced to the newest per command; while a foreground operation owns the terminal reports wait, and the first paint after it returns already shows the newest. `onCommandSettled(id, outcome)` reports `completed`, `aborted`, or `failed` with its error. Its `signal` aborts only through `context.abort(id)`, an exit, or the session ending — never because of a key or a terminal signal — and the session settles only once every background command has; nothing reaches the caller after the end. During a foreground operation the package installs no SIGINT handler, so isolating a background command's own child processes from the terminal's process group is the caller's job; [ADR 0055](../_adr/0055-applications-run-background-commands-beside-the-screen.md) records this policy, and [the background tests](../../tests/cli/application_background_test.ts) hold it. Starting a command whose id is still running fails the session. An exit prints its epilogue after restoration. Both the handoff line and each epilogue line ([`released-lines.ts`](../../src/cli/interactive/application/released-lines.ts)) wrap to the terminal at word boundaries, continuations hanging two cells under the line's own indentation, so they read like the package's other prose in the scrollback; an epilogue line is a string or `ApplicationRun`s (`ApplicationEpilogueLine`), printed without tones, and a `code` run never breaks, so a command or path stays one line to copy — one wider than the terminal is left to the terminal's own wrap, which most terminals copy as one line. Any other return throws. Ctrl+C, EOF, and abort throw `InteractionCancelled`; rendering, callback, provider, and foreground failures reject after cleanup. Missing TTY or ANSI cursor control refuses before changing modes. The raw-terminal lifecycle cancels outstanding native input before relinquishing ownership; Deno restores canonical input flags, cursor, and alternate-screen state, not every host-specific `stty` bit.

## Nested applications

`nestTerminalApplication(options, onExit?)` returns a command that runs another application on the same screen, in place of the one whose action returned it, without releasing the terminal; [`session.ts`](../../src/cli/interactive/application/session.ts) holds each application's model, callbacks, mailbox, and background work, and the runtime keeps a stack of them with the front one painted and receiving input. The nested view and keymap are checked when the command is made, so a broken one fails the action that returned it. While the nested application runs, the one beneath keeps its model untouched — selection, layers, scroll — and its mailbox, background reports, and timers wait, exactly as they do during a foreground handoff; its background work keeps running. The nested application's `exit` closes it: its background commands abort, its `start` cleanup runs, and the application beneath catches up on what waited, then runs `onExit` with the nested final state as one of its own callbacks, so a view it supplies applies before the first frame back. A nested exit prints no epilogue and refuses one. An unbound Ctrl+C in a nested application closes it and reaches the application beneath as Ctrl+C, so a binding there — a quit sheet, say — answers it, and with no binding anywhere the whole session cancels. EOF, abort, `context.fail`, and a fault in either end the whole session. Opening and closing paint keyframes, because each application on the stack is its own composition, and clicks read before either resolve against a screen that has gone, so they are dropped while typed keys carry over. A nested application can open another. [The nested tests](../../tests/cli/application_nested_test.ts) hold the contract, and [ADR 0054](../_adr/0054-the-markdown-browser-runs-on-the-application-runtime.md) records the decision; the [Markdown browser](README.md#markdown-browser) opens inside an application this way.

## Painting and liveness

[ADR 0053](../_adr/0053-applications-paint-incrementally-and-animate.md) records the decision. [`TerminalScreenPainter`](../../src/cli/interactive/painter.ts) writes each paint as one write: DECSET 2026 begin (`CSI ? 2026 h`), an optional window title, an optional state report, the body, and the matching end. Terminals without synchronized output ignore the brackets. A keyframe body erases the display, homes the cursor, and writes every row joined by CR LF. A row body moves to each changed row (`CSI <row> ; 1 H`), erases it (`CSI 2 K`), and writes it. A keyframe follows the first paint in each raw-terminal bracket, every resize notification — even one that ends at the size already painted, since the round trip may have truncated the screen — a new composition, and the first changed paint at least `keyframeEveryMs` (30 s) after the previous keyframe. The application's composition is its layout — split, strip, zoom, list, reading, empty, or too small — and the ids of its open layers, so opening or closing a layer paints a keyframe while a layer's own changes write rows. A frame with unchanged rows, report, and title writes nothing, so an idle screen never repaints. Every row the painter writes first passes the complete-frame checks: one row per viewport row, closed styling and hyperlinks, no control character that would move the cursor, and no cell beyond the width. A failed write forces the next paint to be a keyframe. `runtime.paint` accepts partial `TerminalPaintOptions` to turn off synchronization or row diffs.

The painter saves the window title on the terminal's title stack (`CSI 22 ; 0 t`) before setting the first one (`OSC 2`), restates it with every keyframe and whenever it changes, and restores it (`CSI 23 ; 0 t`) when a view drops it, before foreground work, on exit, and on signal restoration. Mouse reports follow the same rule: a paint whose `mouse` changes turns SGR button and wheel reports on (`CSI ? 1000 h`, `CSI ? 1006 h`) or off (`CSI ? 1006 l`, `CSI ? 1000 l`), every keyframe restates them while they are on, and `release` turns them off before the screen is handed back.

A marker or detail glyph with `animation: "spinner"` moves through the bound motif's spinner while it is visible, and so does the busy liveness glyph. `terminalGlyphFrame` in [`glyph-motion.ts`](../../src/cli/glyph-motion.ts) resolves the cell for a phase. ASCII keeps the static fallback, and reduced motion keeps the resting form. The frame reports `animated` when a visible glyph moves. [`TerminalAnimationTicker`](../../src/cli/interactive/clock.ts) then schedules one repaint 250 ms (`TERMINAL_ANIMATION_INTERVAL_MS`) after that paint and advances one shared phase. The tick stops when no visible glyph moves, below the minimum size, during foreground work, and on exit. `runtime.reducedMotion` never starts the animation; a visible clock, such as a running step's time in a progress sheet, still repaints once a second (`clock` on the frame). An `ApplicationRun` with `clock` (`ApplicationRunClock`: `since`, and a `clock` or `duration` format) is such a clock wherever runs show — a list cell, a detail fact, the header: the package paints the time elapsed since `since` from the frame's own time, so every clock on screen reads the same second, a row beneath a layer ticks as well, and the caller never rebuilds its view to tick one. The caller freezes a glyph by omitting `animation`. `runtime.clock` (`TerminalClock`) supplies time for the tick, keyframe intervals, settle windows, message timeouts, liveness delays, and the key reader's lone-Escape window (`TERMINAL_LONE_ESCAPE_DELAY_MS`, 100 ms); `terminalApplicationDeadline` names the next timed transition and the runtime keeps exactly one timer for it. Tests pass `ManualTerminalClock` and advance it without real delays: a lone Escape arrives once the clock passes the window after the reader has taken the byte, and bytes that follow inside the window still complete a sequence. Only the fence that drains mouse reports at a handoff runs on process time, and it ends as soon as the terminal answers its cursor-position query; a fake terminal answers by queueing the reply.

When `TerminalCapabilities.applicationStateReports` is true, each paint opens with a private OSC 7719 sequence carrying flat JSON (`TerminalApplicationStateReport`): `topLayerId` while a layer is open, `focusedControlId` (inside a layer `<layer>:<control>` such as `review:button:keep` or `palette:input`; otherwise the list id, `<list>:filter` while the filter field owns input, `primary` on an empty body's primary hint, a reading id, or `<reading>:link:<link>` while a link in it has focus), and the body's `listId`, `selectedItemId`, and `zoomed`. It also says what the screen still waits on, so a journey's readiness keys on identities rather than prose: `topLayerState` (a sheet's state) and `topLayerPending` (a sheet still `loading`, or a `pending` block among what the layer shows), `detailPending` (the selected item's detail has no content yet or holds a `pending` block), `messageId` (the message on the message line), and `liveness` (the state the header shows, `busy` only once it has lasted `busyAfterMs`). [The state report tests](../../tests/cli/application_state_report_test.ts) hold each field. Readers ignore fields they do not know. Detection enables reports only for `TERMINAL_APPLICATION_STATE_REPORTS=1`.

## Capture a fixture

The optional testing entrypoint replays the package's paints through its screen model, [`replay-testing.ts`](../../src/cli/interactive/replay-testing.ts). Replay starts at the transcript's last keyframe, together with the synchronized-update, title, and report prefix of its paint. It applies keyframes, row writes, titles, mouse modes, and reports, and stops at the first restoration boundary (`CSI ? 25 h` or `CSI ? 1049 l`); a title restoration, mouse reports turning off, and the cursor-position query (`CSI 6 n`) that fences their late input may precede it. Earlier output, earlier sessions, and foreground children never reach the frame. A synchronized update is a transaction, so one still in flight at the end leaves the previous settled frame. A keyframe accepts any run of CRs before each LF between its rows, because a PTY's line discipline may add them — one when it expands LF, and on some transports more. Any other control, a row outside the viewport, an open style, or a settled frame that does not fill the viewport exactly throws. The replay is not a terminal emulator.

`captureTerminalFrame` returns the styled `frame`, plain `text`, `html`, `geometry`, the `state` report when one was emitted, the window `title` in force, and `mouse: true` while mouse reports were on. `paintedAfter` requires the settling paint to end after a transcript offset. A phase's own output usually holds only row writes, so a readiness condition replays the whole standard output: `ptySettledFrame(size, description, test)` does that and requires a paint after the phase began. For example, against a fixture whose header leads with `Studio`:

```ts
import {
  captureTerminalFrame,
  ptySettledFrame,
  runPtyProcess,
} from "@discern-sh/design-system/cli/interactive/testing";

const size = { columns: 80, rows: 24 };
const ready = ptySettledFrame(
  size,
  "settled Studio frame",
  (capture) => capture.text.includes("Studio"),
);
const result = await runPtyProcess({
  command: Deno.execPath(),
  args: ["run", "--allow-env", "fixture.ts"],
  cwd: Deno.cwd(),
  env: { TERMINAL_APPLICATION_STATE_REPORTS: "1" },
  geometry: size,
  input: [{
    waitFor: ready,
    capture: { name: "overview", when: ready },
    steps: [{ bytes: "q" }],
  }],
});
const captured = captureTerminalFrame(result.keyframes.overview!, size);
console.log(captured.state?.selectedItemId);
await Deno.writeTextFile("overview.html", captured.html);
```

With state reports enabled, a condition can key on `capture.state` identities instead of prose. The caller grants command/file permissions and selects environment facts. `readinessTimeoutMs` bounds the complete input plan (readiness, captures, and scripted steps); `timeoutMs` starts after that plan completes. Each defaults independently to 15 seconds, and timeout diagnostics name the expired phase and its budget. `ptyOutputContains` is useful for positive child markers. macOS/BSD and Linux/util-linux use their respective `script` invocation; only macOS was exercised. Windows is unsupported.

## Consumer migration

- Replace `TerminalApplicationView`'s `title`, `regions`, `tip`, `help`, and `focusedRegionId` with `header`, one `body`, `message`, `footer`, and `windowTitle`. A `choices` region becomes a `ApplicationList`: group headings become `ApplicationListGroup`s, `indicator` becomes the item `marker`, `status` becomes a cell in a declared column, and an unavailable choice keeps its row while its action explains itself. A reading region becomes a `ApplicationReadingBody`, or detail `block`s that follow a list.
- `onDismiss` receives `{ message }` or `{ layer }`; check which before reading the id.
- Replace `onKey` with `keymap` entries whose actions reach `onAction(action, context, source)`. `{ kind: "handled" }` no longer exists; return nothing. Escape no longer exits: bind a key that returns `{ kind: "exit" }`, or bind `escape` for back navigation when nothing else closes.
- Read `context.state.lists[listId].selectedId` instead of `positions[regionId].selectedId`; `focusedRegionId` becomes `focusedControlId`. `runTerminalApplication` resolves with that state.
- Use `onSelectionChange` to load detail for the selected item and `onSelectionMoved` to announce moves; never track selection yourself.
- Tests that drove `updateTerminalApplication(view)` and `transitionTerminalApplication(state, key, regionRows)` use `createTerminalApplicationModel(view)`, `updateTerminalApplication(model, view, now)`, and `transitionTerminalApplication(model, { kind: "key", key }, now)`, and render with `renderTerminalApplication(model, …)`, whose frame returns the fitted `model`.
- Custom `TerminalIO` adapters with native pending reads implement `cancelRead`, and forwarding wrappers preserve it. Readiness conditions build on `ptySettledFrame`; transcript assertions find paints by the synchronized-update begin, not a leading `CSI 2 J`.
- The Markdown browser runs on this runtime: `requestMarkdownBrowser` keeps its results, and `markdownBrowserCommand` opens it inside a running application. A caller that released the screen to act on a choice and started a new browser from the returned state passes `respond` instead and answers the choice in place. The browser's pure state, transition, and renderer exports and its pane options are gone; see the [CLI page](README.md#markdown-browser).
