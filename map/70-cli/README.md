# CLI rendering

The React-free CLI surface has four entrypoints. `./cli` renders the discern design language as deterministic terminal strings; the optional `./cli/interactive` Adapter owns terminal effects and turns raw input into those semantic frame states; `./cli/interactive/testing` publishes the deterministic terminal that drives the real interaction machinery in package and consumer tests; and `./cli/projection` decodes package-emitted output into typed spans and reviewable HTML. Together they combine explicit terminal capabilities, a bound presenter, Token-derived colour and spacing, grapheme-aware text layout and editing, package-owned triangle motifs and narration lines, a vertical rhythm contract, typed interaction state, and generated per-Component CLI enrollment.

[ADR-0011](../_adr/0011-terminal-input-uses-request-vocabulary.md) reserves “prompt” for coding-agent instructions. The terminal Adapter names individual value-producing operations `request*` and names their shared lifecycle and machinery `Interaction*`.

## Boundary and data flow

[`src/cli/mod.ts`](../../src/cli/mod.ts) is the public entrypoint named by both package manifests. The graph imports [`tokens.ts`](../../src/tokens/tokens.ts), CLI foundation modules, the generated CLI registry and renderer barrel, and rendered Component CLI modules. It imports no `.tsx` module and never resolves React; the release suite checks that graph directly and also runs a publish-shaped neutral consumer.

[`src/cli/interactive/mod.ts`](../../src/cli/interactive/mod.ts) is a separate optional entrypoint in both manifests. Its graph imports the pure CLI foundation, Deno terminal APIs, and rendered Component CLI modules, but no `.tsx` module or React. Importing it performs no terminal mutation; constructing `DenoTerminalIO` and running an interaction cross the effects boundary.

[`src/cli/interactive/testing.ts`](../../src/cli/interactive/testing.ts) and [`src/cli/projection.ts`](../../src/cli/projection.ts) are the published instrument entrypoints recorded in [ADR-0013](../_adr/0013-publish-testing-and-projection-instruments.md). Release tests keep all four CLI graphs React-free, import each with zero permissions so none may perform I/O at import, and run a publish-shaped neutral consumer that drives a real scripted interaction and projects real emitted output.

Renderers receive a [`TerminalCapabilities`](../../src/cli/capabilities.ts) value containing colour depth (`none`, `ansi16`, `ansi256`, or `truecolor`), terminal columns, Unicode support, and optional ANSI cursor-control and OSC 8 hyperlink support. These are independent facts: `C.UTF-8` and `C.utf8` retain Unicode glyphs under `TERM=dumb`, while colour and cursor controls remain disabled; exact `C` and `POSIX` locales retain the ASCII fallback. [`detectTerminalCapabilities()`](../../src/cli/capabilities.ts) interprets caller-supplied `NO_COLOR`, `TERM`, `COLORTERM`, tty, locale, and width facts. It performs no process read itself. Component and motif renderers accept capabilities as an argument and perform no I/O or environment access. The compatibility-optional `ansiControl` field defaults to the earlier control assumption when callers construct capabilities manually, while detector-produced values always state it. The optional `hyperlinks` field gates OSC 8 hyperlink emission; an omitted field derives the fact from colour depth, and the detector states it from the same derivation because no portable environment fact announces hyperlink support — callers holding terminal-specific knowledge state it directly.

## Token bridge and primitives

[`theme.ts`](../../src/cli/theme.ts) derives light and dark terminal themes directly from the authored `DesignToken` and `ThemeToken` arrays. It resolves Token references, converts authored OKLCH and hexadecimal colours to sRGB, composites the authored translucent overlay over the variant canvas, and computes nearest ANSI 256- and 16-colour fallbacks. Spacing Tokens map to character cells relative to `--discern-space-2`; weight Tokens determine bold roles, while muted, emphasis, and annotation roles use dim and italic terminal attributes. No terminal palette repeats an authored design colour. The authored `--discern-measure` Token bounds default frame widths through [`frame-measure.ts`](../../src/cli/frame-measure.ts): form frames, Toast, Meter, and the interactive activity and sequential-form paints clamp to its character-cell value on wide terminals, and explicit `width` props override it.

[`ansi.ts`](../../src/cli/ansi.ts) composes styled spans, emits the selected ANSI form, and owns terminal hyperlinks: `styleHyperlink()` is the single authority that writes OSC 8 envelope bytes, so no consumer or renderer composes the sequence itself. Emission follows the `hyperlinks` capability fact — derived from colour depth when the caller omits it — and emits ST-ended envelopes with an optionally styled label. The fallback never loses the label: it renders `label (url)`, or the label alone when the label already is the URL. Labels must be non-empty and control-free, URLs non-empty printable ASCII (callers percent-encode anything wider), and `stripAnsi()` removes CSI styling and complete OSC envelopes, so hyperlinked strings measure, wrap, and pad by their visible labels alone. [`text.ts`](../../src/cli/text.ts) segments graphemes for width, wrap, truncation, and padding, including wide CJK and emoji clusters. Its styled family — `wrapStyledText()` and `truncateStyledText()` — wraps and truncates package-emitted styled text through the same plain-projection authorities, then re-attributes the active SGR styling and open hyperlinks to every produced line, closing and reopening them at line boundaries so each emitted line renders correctly alone. Foreign, malformed, or unterminated sequences throw; styling left open at end of input still closes on every line; truncation closes styling and hyperlinks before its always-unstyled marker, so no dangling envelope survives; output re-emits canonically at the input's original colour depth; and `padText()` pads styled content by visible cells with the added spaces outside every run. `wrapTextPreservingIndent()` is the shared indentation authority: it keeps a fitting line byte-intact and hangs wrapped continuations under the line's leading spaces, so stack traces and nested output keep their shape. [`layout.ts`](../../src/cli/layout.ts) provides vertical joins, inline cluster wrapping, and column layout. [`box.ts`](../../src/cli/box.ts) draws width-bounded frames, wraps over-wide bodies through the shared indentation authority, and substitutes `+`, `-`, and `|` when Unicode is unavailable.

[`triangles.ts`](../../src/cli/triangles.ts) owns the discern triangle glyphs and the preserved weave and spinner orders. Its pure renderers cover horizontal, vertical, thick, phased, and reversed patterns; spinner and determinate progress frames; labeled rules; semantic workflow steps; and an out-and-back activity beacon. Labeled section rules default to one uppercase strong embedded title — two heavy cells, one triangle, and a heavy rule filling the remaining width — instead of surrounding the label with repeated triangle fields. Their public `treatment` option also provides a strong underline and a quiet sandwich; long labels truncate within the requested width, `=` preserves strong ASCII weight, and `-` preserves the quiet variant. Every workflow state reserves the same three-cell marker slot, so labels do not move when a step becomes active. Completed status triangles point up and incomplete status triangles point down regardless of item index; active states retain their spinner phase, while pending, error, and cancelled states keep distinct dot, bang, and cross markers. Colours and gaps come from the terminal theme, measurement uses the shared text primitive, and ASCII orientations preserve the same status meaning. [ADR-0010](../_adr/0010-use-calm-full-width-cli-heading-rules.md) records why the full-width boundary remains while the repeated motif does not.

## Presenter, narration, and rhythm

[`presenter.ts`](../../src/cli/presenter.ts) is the default way to render this surface. `createCliPresenter(capabilities, { theme, width })` binds terminal capabilities, a theme variant, and a default frame width once and returns a pure presenter value; `present(renderer, props)` then supplies everything except the call's own props, so a consumer holding one presenter never re-spreads capabilities or threads a theme again. Props win over bound defaults one call at a time, the bound width narrows the effective columns and never widens the real terminal, and `with()` derives a re-themed or re-bounded presenter from the same base terminal while leaving its source untouched. A bound call is byte-equal to the same renderer called by hand, held by a registry-wide test across every rendered Component example — the raw `(props, capabilities)` form remains the escape hatch for callers that thread capabilities themselves.

[`narration.ts`](../../src/cli/narration.ts) supplies the verbs for output too small to deserve a Component: `renderSuccessLine`, `renderNoteLine`, `renderWarningLine`, `renderFailureLine`, and `renderLeadLine`, each a pure `CliRenderer` over one trimmed control-free line with optional `theme` and `maxWidth`. Markers stay in the package dialect — check, triangle, bang, cross, with `+ > ! x` ASCII fallbacks — only the marker takes the tone colour, wrapped lines hang under the marker column, and the lead-in takes the embedded section rule's uppercase strong title treatment without its rule or any owned blank lines, so it stays lighter than Display Heading. `narrationLineRenderers` maps kinds to verbs for severity-driven callers, and `styleSemanticText` styles inline text by type role and semantic tone. The presenter carries all of it bound: `success`, `note`, `warning`, `failure`, `lead`, and `style`.

[`rhythm.ts`](../../src/cli/rhythm.ts) makes "exactly one blank line between semantic groups" a property of composition rather than author bookkeeping. A conforming block neither begins nor ends with a blank line and carries no trailing newline. `composeCliBlocks` normalises block edges — a Heading's owned leading boundary composes without doubling — preserves interiors byte-for-byte, drops empty blocks, and joins with exactly one blank line, so composed results nest without change. A sink that writes incrementally counts the consecutive newlines already at its stream tail, capped at two, opens every block after the first with `cliBlockBoundary(count)`, and terminates each written block with one newline. The package defines the contract and the composer but ships no sink: writing is the consumer's effect.

The registry maps every slug to exempt or rendered and records each rendered module path.

The rendered module convention is visible in [`badge.cli.ts`](../../src/components/display/badge/badge.cli.ts): a default pure renderer, a `<Pascal>CliProps` type, and `cliExamples`. Badge's web and terminal renderers both import [`BadgeTone`](../../src/components/display/badge/badge.types.ts), so React does not own their shared vocabulary. Rendered Components follow the same framework-neutral vocabulary rule for named variants, sizes, surfaces, spacing, alignments, statuses, tones, and directions; CLI-only item shapes use strings rather than `ReactNode`.

[`catalogue-cli.ts`](../../scripts/catalogue-cli.ts) is the generated-registry browser for the terminal surface, composing the shared [`cli-inventory.ts`](../../scripts/cli-inventory.ts) authority that also feeds the CLI Playground. `deno task catalogue:cli` prints every rendered Component's named examples, every exempt Component with its recorded reason, and the Triangle motifs and Narration lines sheets in canonical Group order. A Component slug or case-insensitive Group name narrows the output; `triangles` prints only the motifs and `narration` only the narration lines. The motif sheet calls package APIs for horizontal and vertical dividers, thick ribbon, field and weave, every spinner phase, representative progress including 25 percent, the labeled section rule, every workflow-step state, and representative activity-beacon phases. The narration sheet renders every verb plus one composed-rhythm specimen through the bound presenter. Capability detection honours `NO_COLOR`; no frame or exemption is copied into the script.

The browser Catalogue exposes the same Component inventory beside the web examples through the independent Web/CLI switch in every Component card. [`build.ts`](../../scripts/build.ts) generates static imports of every default CLI renderer and its `cliExamples`; [`cli-preview.tsx`](../../catalogue/cli-preview.tsx) executes them at 80 columns with truecolour and Unicode, then projects the output through the published `./cli/projection` module — spans, the shared browser style mapping, and the safe hyperlink-target policy — onto one bare, cell-stable monospace surface. The browser wrapper adds neither Terminal window chrome nor proportional-font shaping to the renderer's geometry. A recorded exemption disables the CLI choice and makes its Metadata reason available as a tooltip. [`catalogue_cli_preview_test.ts`](../../tests/catalogue_cli_preview_test.ts) renders and projects every enrolled example and guards that single browser projection authority, so the view cannot silently drift from the terminal catalogue authority.

Core's identity renderers use capability-aware glyph and triangle wordmarks; its action renderers preserve Button, Icon button, and Theme toggle vocabulary. Theme switcher is exempt because terminal palette choice is already a caller-owned renderer input, while presenting its three-way form would imply a driver and persistence policy. Display maps compact text treatments to ANSI roles, frames Card, Window, and Terminal with the box primitive, sizes Table columns inside the available width, and keeps Diffstat direction legible through literal `+` and `−` bars. Divider is the Component authority for selecting the triangle foundation's horizontal and vertical rules, ribbons, fields, weaves, phases, and labeled section rules. Layout's Container, Stack, Cluster, Grid, and Section renderers are thin wrappers over the foundation layout combinators; Section selects the authoritative triangle primitives when a rule or ribbon clarifies its boundary.

Editorial renderers cover measured article shells and prose, framed callouts, source listings and data figures, structured reading lists and trees, pull quotes, and a triangle-railed Timeline. Docs renderers cover triangle-labeled headings, navigation trees, glossary terms, key caps, and previous/next paging. People renderers derive Avatar, Avatar group, Persona, Byline, Mention, and Profile card initials from [`initials.ts`](../../src/components/initials.ts). When web and terminal renderers share tones, variants, or sizes, the vocabulary is hoisted into a React-free sibling `*.types.ts` module rather than imported from `.tsx`.

[`interactive-states.ts`](../../src/cli/interactive-states.ts) defines the visual inputs for text, masked, confirmation, selection, search, query-filtered multiselection, autocomplete, acknowledgement, textarea, spinner, progress, activity-log, and sequential-form frames. Active, validation-error, submitted, and cancelled lifecycles are data. Search, search-multiselect, and autocomplete frames carry an optional `pending` fact — a provider call is scheduled or in flight, so the shown results answer an earlier query. Spinner phase, completed units, workflow status, and beacon phase remain semantic values. The activity-log frame carries pinned stable lines in the narration severities, the recent committed tail lines, an optional in-progress partial line, and an exact `tailRows` count the fitter decides.

## Interactive terminal Adapter

[`io.ts`](../../src/cli/interactive/io.ts) defines the injectable `TerminalIO` boundary and its Deno stdin/stdout implementation. Interactions refuse to start unless both handles are TTYs. [`lifecycle.ts`](../../src/cli/interactive/lifecycle.ts) brackets raw mode and supported cursor hiding as one exception- and signal-safe operation: success, validation failure, Ctrl+C, EOF, callback exceptions, and form back-navigation all attempt the applicable restoration, and each bracket additionally installs a scoped SIGINT listener for its duration — never process-global — through the injectable `TerminalSignalSource` boundary ([`signals.ts`](../../src/cli/interactive/signals.ts)). The default signal path runs the bracket owner's restoration share, restores raw mode and the cursor exactly once, removes its own listener, and re-raises so the process still dies as an interrupt; a caller-supplied `onInterrupt` receives the signal instead and leaves restoration to the ordinary path — the required posture for hosts managing SIGINT themselves. Deno's additive listener model means the package never disturbs a host's existing listener, and `withRawTerminal`'s `hideCursor: false` holds raw mode without touching the cursor for query round-trips. [ADR-0014](../_adr/0014-bracket-sigint-through-an-injectable-source.md) records the scope, nesting guarantees, and injectability.

[`painter.ts`](../../src/cli/interactive/painter.ts) replaces a multiline frame only while the complete current and replacement frames fit within the current viewport and ANSI cursor control is available. `replace()` returns `InlineFramePaintResult`: `painted` or `unchanged` carries both frame line counts and viewport rows; `refused` adds `ansi-control-unavailable`, `frame-exceeds-viewport`, or `current-frame-exceeds-viewport`. An empty frame occupies zero rows; every newline starts another row, including a trailing newline. A refusal writes nothing and preserves the current frame. Activity drivers can select a static view from that result. Interaction drivers first use [`viewport-budget.ts`](../../src/cli/interactive/viewport-budget.ts) to fit the state through its real Component renderer; after a downward resize strands the previous live frame, they end that scrollback region and start a newly bounded live region. [ADR-0007](../_adr/0007-separate-terminal-rendering-and-control-capabilities.md) records why repertoire, styling, and control remain separate; [ADR-0009](../_adr/0009-fit-prompt-frames-through-component-renderers.md) records why interaction geometry is renderer-measured.

[`keys.ts`](../../src/cli/interactive/keys.ts) incrementally decodes UTF-8, retains incomplete escape sequences between reads, normalises common CSI and SS3 variants, and keeps unknown control sequences non-printable. Escape followed by an unrecognised character is an Alt/meta chord and stays a non-printable unknown sequence rather than leaking an `escape` key plus literal text. A lone Escape is disambiguated in the key reader by a short continuation window (100ms by default, tunable through `TerminalKeyReaderOptions.escapeDelayMs`): bytes arriving inside the window complete their sequence, and an elapsed window delivers the `escape` key through the decoder's `flushLoneEscape`, which never touches longer fragments — a split CSI or SS3 sequence still decodes incrementally no matter how late its remaining bytes arrive. The deliberate trade-off, recorded in [ADR-0012](../_adr/0012-deliver-lone-escape-through-a-reader-timing-window.md): continuation bytes arriving later than the window after a bare Escape byte read as Escape plus the remainder. A raw read left pending by an elapsed window is parked per terminal and adopted by the next reader on the same terminal, so an interaction ended by Escape cannot strand a read that would steal the next interaction's first bytes. [`editor.ts`](../../src/cli/interactive/editor.ts) edits by grapheme rather than UTF-16 code unit and supports Arrow, Home/End, Delete, Backspace, Option+Backspace, and the common Ctrl+A/B/E/F/H/N/P bindings. Textarea movement remains line-oriented; its visible window follows the logical cursor when wrapped content is taller than the current editor, and Ctrl+D submits it.

The interaction modules are event loops over typed state machines. Text, masked, confirm, select, multiselect, search, query-filtered multiselect, autocomplete, acknowledgement, and textarea machines return the corresponding frame shape. Before every paint, the driver reads the current `TerminalIO.size().rows`, subtracts the caller's `reservedRows` — a shared request option declaring how many rows the caller's own composition occupies above the frame — and measures the real rendered frame against the remainder, so a full-budget list never scrolls a caller's header band away. A zero or absent reservation is byte-identical to an unreserved request, and a reservation taller than the viewport degrades exactly like a too-short terminal. Choice `visibleCount` and textarea `rows` are caller-requested upper bounds: a short viewport reduces only that frame's visible window, while a later resize or interaction starts again from the unchanged request. Textarea defaults to five requested rows and may expose any positive requested count that fits; a terminal too short for even one coherent control row refuses before painting.

The shared driver owns request correctness. It paints the initial frame before any machine work, so a slow provider never delays the first honest frame, and it offers machines a context whose `repaint` and `fail` land asynchronous state safely — both ignored once the interaction has finished, with machine timers and in-flight provider work disposed on every exit. An optional synchronous `transform` on `InteractionOptions` canonicalises the submitted value first, then the required check runs, then the validator; the transformed value is what validation judges and what the request returns, while frames keep presenting the value as edited and masked values stay masked throughout. Once a submission has failed, the driver latches the validator to reality: every subsequent value change re-validates — including a value changed by a provider resolution — the message persists through no-op keys, clears the moment the value passes, and returns live if a later edit makes it invalid again. An asynchronous verdict never blocks key handling, a verdict superseded by a newer edit is discarded, and a rejecting validation faults the interaction with full restoration; submitting while invalid re-runs the validator and re-presents the current message. Escape cancels a request exactly like Ctrl+C — cancelled frame, then `InteractionCancelled` — under its own `"Dismissed."` reason, distinct from Ctrl+C's `"Cancelled."` and EOF's `"Input ended."`. The Ctrl+U no-previous-step notice clears on the next key, restoring whatever lifecycle it covered.

Discovery providers never block the key loop. Search, query-filtered multiselect, and provider-backed autocomplete issue every provider call with a monotonic tag and an `AbortSignal` that fires when a newer query supersedes the call or the request ends; a superseded resolution is discarded unseen, so a stale result set never paints as current. The optional `debounceMs` on the shared `DiscoveryRequestPacing` options coalesces rapid edits through an injectable `InteractionDelayScheduler` — mirroring the spinner's injectable repetition — while the initial call always issues immediately, and synchronous provider results still apply within the same frame, so array-backed providers keep their immediate behaviour byte for byte. Throughout scheduling and flight the frame carries the pending truth: the form status token reads `searching` and an empty result region says `Searching…` rather than claiming no results exist, in plain text that survives `NO_COLOR` and ASCII without moving a row. A rejecting provider faults the interaction with full restoration, and a resolution that arrives after supersession or disposal is dropped rather than raised.

Choice IDs stay stable across values and disabled choices remain visible but unselectable. Select, multiselect, search, and query-filtered multiselect accept one public entry union: ordinary `InteractionChoice<T>` values and semantic `InteractionGroupHeading` structure. A group heading owns a stable ID and non-empty label but no `T` value. Validation rejects duplicate or control-bearing IDs, control-bearing labels, empty headings, and required lists without a selectable choice. Initial highlight, movement, Home/End, paging, toggle-all, submission, and returned values operate only on choices. PageUp and PageDown jump the highlight one visible window in select and multiselect — sized by the most recently fitted frame rather than the requested count — landing on the nearest enabled choice past the target and clamping at the list's edges instead of wrapping. The shared choice window keeps the governing heading visible when a grouped list scrolls, without making the heading a navigation stop. Search providers may be synchronous or asynchronous and return the same entry vocabulary; `SearchRequestOptions.initialId` remembers an enabled choice by stable ID across provider reordering, filtering, and clearing without inventing a query or keypress. A missing, grouped, or disabled ID preserves the existing unhighlighted initial search state. Autocomplete uses inline ghost text.

`requestSearchSelections` combines the multiselection contract with a live query over the same provider vocabulary. Tab toggles the highlighted entry, Ctrl+A toggles every enabled current match, and movement stays on Up/Down, Ctrl+P/Ctrl+N, and Shift+Tab while other keys edit the query — so Space types and the query editor cedes Tab and Ctrl+A to selection. Selected entries the query no longer returns stay visible and deselectable in a machine-composed band under a renderer-labeled `Selected` heading whose frame-local ID never collides with caller IDs; deselecting a retained entry removes it and the highlight lands on the nearest enabled neighbour, `initialIds` select from the first provider resolution where present and enabled, and submission returns values in selection order. `requestAcknowledgement` is the smallest kind: a validated, control-free message acknowledged with Enter or Space, the reserved footer carrying a `Press Enter to continue.` hint unless the caller overrides it, and the standard cancellation contract throughout. [`sequential-form.ts`](../../src/cli/interactive/sequential-form.ts) reevaluates conditional steps, retains prior values, removes values for newly inapplicable steps, and treats Ctrl+U as navigation to the preceding applicable step; acknowledgement steps participate like any other request.

[`activity.ts`](../../src/cli/interactive/activity.ts) is the only time-advancing layer. Its scheduler advances the canonical `DISCERN_TRIANGLE_SPINNER_ORDER`; its determinate controller carries completed and total units and emits submitted lifecycle only at truthful completion. The controller also carries a live label naming the unit of work underway: `set` and `advance` accept an optional per-unit label, `relabel` renames without moving units, and the current label reads back from the handle. Activity labels — spinner, progress, and activity log, at construction and on every update — are validated free of control and format characters, so a label change can never move the frame's geometry. Spinner frames stay on the triangle spinner primitive, while determinate frames render through Feedback's Meter renderer, which delegates its fill to the same triangle progress authority. Both wrappers ride the signal-safe cursor bracket: an interrupt stops the animation, clears the incomplete live frame, and restores the cursor before the signal re-raises or reaches the caller's `onInterrupt`, and the request driver ends the same way under an externally delivered SIGINT — painting the truthful Ctrl+C cancelled frame before restoration.

`withActivityLog` ([ADR-0016](../_adr/0016-stream-activity-through-a-component-backed-log-frame.md)) is the third activity kind: long-running work with streaming detail. Its producer controller appends committed lines, replaces the in-progress partial line, pins narration-toned stable lines, relabels the headline, and finishes with a declared completion — keep the stable summary, or collapse to one toned result line — with an unfinished operation getting the summary applied for it and post-finish calls throwing. Frames render through Workflow's Activity log renderer, fitted through the shared viewport authority with the tail region as the variable budget, repainted only on scheduler ticks so fast producers coalesce, and following the stranded-frame resize contract. A SIGINT paints the stable summary under the cancelled headline before restoration. Unlike the spinner and progress wrappers, it never refuses a non-interactive terminal: non-TTY, missing ANSI control, unfittable viewports, and painter refusals all degrade to one truthful append-only feed — the headline as a lead line, committed lines once each behind the muted rail, stable lines as narration lines when pinned, no partial churn, and an uncommitted partial flushed once at finish. Streamed text is sanitised rather than trusted — foreign ANSI stripped, carriage-return overwrites reduced to their final visible segment, tabs expanded, remaining control and format characters removed — while caller-authored labels, hints, and pinned lines stay under the throwing validation. One live activity or request per terminal at a time remains the Adapter's contract; the log adds no multiplexing.

[`background.ts`](../../src/cli/interactive/background.ts) senses the terminal ground at the effects boundary. `senseTerminalBackground` takes a caller-supplied `TerminalIO` and environment snapshot — nothing ambient, mirroring capability detection — queries the terminal's reported background colour (OSC 11) inside a cursor-untouched raw round-trip bounded by a strict timeout (250ms default), falls back to the `COLORFGBG` hint when the query cannot answer, and returns a typed `TerminalBackgroundReading`: a ground of `light`, `dark`, or `unknown` plus the evidence used. Light and dark split at the WCAG text-contrast flip point; non-TTY handles are inert; and the shared package-internal read broker ([`read-broker.ts`](../../src/cli/interactive/read-broker.ts)) keeps buffered bytes separate from its one pending raw read. If the deadline wins, a brokered byte-stream filter retains ownership of the eventual OSC 11 reply while streaming ordinary input onward in order, so neither a late reply nor preserving already-read input can corrupt or steal a later interaction's keys. Consumers map `light` and `dark` to the derived `terminalThemes` variants and choose their own default for `unknown`; selection stays the caller's move. [ADR-0015](../_adr/0015-sense-terminal-background-as-a-caller-driven-effect.md) records why sensing is effectful and caller-driven, the timeout posture, and why unknown is a first-class answer.

Interaction modules pass their typed states directly to Component renderers. Text, masked, and autocomplete use Forms' Input; confirm uses Switch; select uses Select; multiselect and query-filtered multiselect use Checkbox; search uses Radio; acknowledgement uses Field; and textarea uses Textarea. Sequential forms render their sections through Marketing's Process steps. The removed temporary frame dispatcher leaves terminal I/O, decoding, editing, state transitions, and Component rendering as separate authorities without an intermediate presentation language.

## Feedback, Forms, Navigation, and Marketing renderers

Forms are static views over that interaction contract. Input accepts text, masked-input, and autocomplete frames; Switch accepts confirmation; Select accepts single selection; Checkbox accepts multiselection and the query-filtered search-multiselect frame with its query row; Radio accepts search results; Field accepts a direct labeled control or the acknowledgement frame; and Textarea accepts its multiline frame directly. A pending discovery frame swaps the status token to `searching` and renders an empty result region as `Searching…` — plain text under every capability, never an added row, so heights hold while a provider runs. Every form frame reserves its footer row unconditionally — hint text when provided, the lifecycle message when present, a blank row otherwise — so active, validation-error, and hint variants of one request render at identical heights and nothing below the frame shifts when a message appears or clears. Select, Checkbox, and Radio distinguish semantic headings from disabled selectable choices and render headings through the shared Token-derived triangle section rule, including no-colour and ASCII geometry. Their choice rows reserve pointer indentation inside the Box, so moving a highlight changes the marker rather than the label column. The active target and selected single-choice or multiselect marks use the form border's Token-derived accent in colour terminals; pointer, filled-circle, and checkmark shapes retain the same information without colour, while disabled labels remain explicit and muted. Switch always renders both yes and no labels in fixed columns and moves one Unicode or ASCII indicator between them, so toggling does not move either label or surrounding text. Their optional presentation snapshot distinguishes idle, active, filled, and disabled without changing the driver's lifecycle data; validation-error, submitted, and cancelled remain the shared lifecycle authority. Textarea's control width derives from the same `--discern-measure` frame default rather than a local cap. Field supplies the same visual shell for custom controls. Meter accepts the determinate-progress frame directly, while Process steps accepts the sequential-form frame and delegates markers, phase order, and beacon motion to [`triangles.ts`](../../src/cli/triangles.ts).

Feedback renders toned boxes, modal and empty blocks, notifications, and determinate progress. Breadcrumbs and Tabs render wrapping path and tab-strip treatments. Marketing renders adaptive audience cards, proof stories, comparison rows/tables, calls to action, disclosures, a triangle hero banner, name rolls, stat rows, the canonical stepper, and attributed quotations. Hover-only supplementary surfaces, browser page chrome, and media-defined asymmetric layouts carry explicit exemptions in Component Metadata.

## Workflow and Agents renderers
