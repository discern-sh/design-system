# CLI rendering

The React-free CLI surface has two entrypoints. `./cli` renders the discern design language as deterministic terminal strings; the optional `./cli/interactive` Adapter owns terminal effects and turns raw input into those semantic frame states. Together they combine explicit terminal capabilities, Token-derived colour and spacing, grapheme-aware text layout and editing, package-owned triangle motifs, typed interaction state, and generated per-Component CLI enrollment.

[ADR-0011](../_adr/0011-terminal-input-uses-request-vocabulary.md) reserves “prompt” for coding-agent instructions. The terminal Adapter names individual value-producing operations `request*` and names their shared lifecycle and machinery `Interaction*`.

## Boundary and data flow

[`src/cli/mod.ts`](../../src/cli/mod.ts) is the public entrypoint named by both package manifests. The graph imports [`tokens.ts`](../../src/tokens/tokens.ts), CLI foundation modules, the generated CLI registry and renderer barrel, and rendered Component CLI modules. It imports no `.tsx` module and never resolves React; the release suite checks that graph directly and also runs a publish-shaped neutral consumer.

[`src/cli/interactive/mod.ts`](../../src/cli/interactive/mod.ts) is a separate optional entrypoint in both manifests. Its graph imports the pure CLI foundation, Deno terminal APIs, and rendered Component CLI modules, but no `.tsx` module or React. Importing it performs no terminal mutation; constructing `DenoTerminalIO` and running an interaction cross the effects boundary. Release tests inspect both CLI graphs and import the Adapter from a publish-shaped neutral consumer.

Renderers receive a [`TerminalCapabilities`](../../src/cli/capabilities.ts) value containing colour depth (`none`, `ansi16`, `ansi256`, or `truecolor`), terminal columns, Unicode support, and optional ANSI cursor-control and OSC 8 hyperlink support. These are independent facts: `C.UTF-8` and `C.utf8` retain Unicode glyphs under `TERM=dumb`, while colour and cursor controls remain disabled; exact `C` and `POSIX` locales retain the ASCII fallback. [`detectTerminalCapabilities()`](../../src/cli/capabilities.ts) interprets caller-supplied `NO_COLOR`, `TERM`, `COLORTERM`, tty, locale, and width facts. It performs no process read itself. Component and motif renderers accept capabilities as an argument and perform no I/O or environment access. The compatibility-optional `ansiControl` field defaults to the earlier control assumption when callers construct capabilities manually, while detector-produced values always state it. The optional `hyperlinks` field gates OSC 8 hyperlink emission; an omitted field derives the fact from colour depth, and the detector states it from the same derivation because no portable environment fact announces hyperlink support — callers holding terminal-specific knowledge state it directly.

## Token bridge and primitives

[`theme.ts`](../../src/cli/theme.ts) derives light and dark terminal themes directly from the authored `DesignToken` and `ThemeToken` arrays. It resolves Token references, converts authored OKLCH and hexadecimal colours to sRGB, composites the authored translucent overlay over the variant canvas, and computes nearest ANSI 256- and 16-colour fallbacks. Spacing Tokens map to character cells relative to `--discern-space-2`; weight Tokens determine bold roles, while muted, emphasis, and annotation roles use dim and italic terminal attributes. No terminal palette repeats an authored design colour. The authored `--discern-measure` Token bounds default frame widths through [`frame-measure.ts`](../../src/cli/frame-measure.ts): form frames, Toast, Meter, and the interactive activity and sequential-form paints clamp to its character-cell value on wide terminals, and explicit `width` props override it.

[`ansi.ts`](../../src/cli/ansi.ts) composes styled spans, emits the selected ANSI form, and owns terminal hyperlinks: `styleHyperlink()` is the single authority that writes OSC 8 envelope bytes, so no consumer or renderer composes the sequence itself. Emission follows the `hyperlinks` capability fact — derived from colour depth when the caller omits it — and emits ST-ended envelopes with an optionally styled label. The fallback never loses the label: it renders `label (url)`, or the label alone when the label already is the URL. Labels must be non-empty and control-free, URLs non-empty printable ASCII (callers percent-encode anything wider), and `stripAnsi()` removes CSI styling and complete OSC envelopes, so hyperlinked strings measure, wrap, and pad by their visible labels alone. [`text.ts`](../../src/cli/text.ts) segments graphemes for width, wrap, truncation, and padding, including wide CJK and emoji clusters. Its styled family — `wrapStyledText()` and `truncateStyledText()` — wraps and truncates package-emitted styled text through the same plain-projection authorities, then re-attributes the active SGR styling and open hyperlinks to every produced line, closing and reopening them at line boundaries so each emitted line renders correctly alone. Foreign, malformed, or unterminated sequences throw; styling left open at end of input still closes on every line; truncation closes styling and hyperlinks before its always-unstyled marker, so no dangling envelope survives; output re-emits canonically at the input's original colour depth; and `padText()` pads styled content by visible cells with the added spaces outside every run. [`layout.ts`](../../src/cli/layout.ts) provides vertical joins, inline cluster wrapping, and column layout. [`box.ts`](../../src/cli/box.ts) draws width-bounded frames, preserves meaningful leading indentation across fitting and wrapped lines, and substitutes `+`, `-`, and `|` when Unicode is unavailable.

[`triangles.ts`](../../src/cli/triangles.ts) owns the discern triangle glyphs and the preserved weave and spinner orders. Its pure renderers cover horizontal, vertical, thick, phased, and reversed patterns; spinner and determinate progress frames; labeled rules; semantic workflow steps; and an out-and-back activity beacon. Labeled section rules default to one uppercase strong embedded title — two heavy cells, one triangle, and a heavy rule filling the remaining width — instead of surrounding the label with repeated triangle fields. Their public `treatment` option also provides a strong underline and a quiet sandwich; long labels truncate within the requested width, `=` preserves strong ASCII weight, and `-` preserves the quiet variant. Every workflow state reserves the same three-cell marker slot, so labels do not move when a step becomes active. Completed status triangles point up and incomplete status triangles point down regardless of item index; active states retain their spinner phase, while pending, error, and cancelled states keep distinct dot, bang, and cross markers. Colours and gaps come from the terminal theme, measurement uses the shared text primitive, and ASCII orientations preserve the same status meaning. [ADR-0010](../_adr/0010-use-calm-full-width-cli-heading-rules.md) records why the full-width boundary remains while the repeated motif does not.

## Interactive terminal Adapter

[`io.ts`](../../src/cli/interactive/io.ts) defines the injectable `TerminalIO` boundary and its Deno stdin/stdout implementation. Interactions refuse to start unless both handles are TTYs. [`lifecycle.ts`](../../src/cli/interactive/lifecycle.ts) brackets raw mode and supported cursor hiding as one exception-safe operation: success, validation failure, Ctrl+C, EOF, callback exceptions, and form back-navigation all attempt the applicable restoration.

[`painter.ts`](../../src/cli/interactive/painter.ts) replaces a multiline frame only while the complete current and replacement frames fit within the current viewport and ANSI cursor control is available. `replace()` returns `InlineFramePaintResult`: `painted` or `unchanged` carries both frame line counts and viewport rows; `refused` adds `ansi-control-unavailable`, `frame-exceeds-viewport`, or `current-frame-exceeds-viewport`. An empty frame occupies zero rows; every newline starts another row, including a trailing newline. A refusal writes nothing and preserves the current frame. Activity drivers can select a static view from that result. Interaction drivers first use [`viewport-budget.ts`](../../src/cli/interactive/viewport-budget.ts) to fit the state through its real Component renderer; after a downward resize strands the previous live frame, they end that scrollback region and start a newly bounded live region. [ADR-0007](../_adr/0007-separate-terminal-rendering-and-control-capabilities.md) records why repertoire, styling, and control remain separate; [ADR-0009](../_adr/0009-fit-prompt-frames-through-component-renderers.md) records why interaction geometry is renderer-measured.

[`keys.ts`](../../src/cli/interactive/keys.ts) incrementally decodes UTF-8, retains incomplete escape sequences between reads, normalises common CSI and SS3 variants, and keeps unknown control sequences non-printable. Escape followed by an unrecognised character is an Alt/meta chord and stays a non-printable unknown sequence rather than leaking an `escape` key plus literal text. A lone Escape is disambiguated in the key reader by a short continuation window (100ms by default, tunable through `TerminalKeyReaderOptions.escapeDelayMs`): bytes arriving inside the window complete their sequence, and an elapsed window delivers the `escape` key through the decoder's `flushLoneEscape`, which never touches longer fragments — a split CSI or SS3 sequence still decodes incrementally no matter how late its remaining bytes arrive. The deliberate trade-off, recorded in [ADR-0012](../_adr/0012-deliver-lone-escape-through-a-reader-timing-window.md): continuation bytes arriving later than the window after a bare Escape byte read as Escape plus the remainder. A raw read left pending by an elapsed window is parked per terminal and adopted by the next reader on the same terminal, so an interaction ended by Escape cannot strand a read that would steal the next interaction's first bytes. [`editor.ts`](../../src/cli/interactive/editor.ts) edits by grapheme rather than UTF-16 code unit and supports Arrow, Home/End, Delete, Backspace, Option+Backspace, and the common Ctrl+A/B/E/F/H/N/P bindings. Textarea movement remains line-oriented; its visible window follows the logical cursor when wrapped content is taller than the current editor, and Ctrl+D submits it.

The interaction modules are event loops over typed state machines. Text, masked, confirm, select, multiselect, search, autocomplete, and textarea machines return the corresponding Wave 1 frame shape. Before every paint, the driver reads the current `TerminalIO.size().rows` and measures the real rendered frame. Choice `visibleCount` and textarea `rows` are caller-requested upper bounds: a short viewport reduces only that frame's visible window, while a later resize or interaction starts again from the unchanged request. Textarea defaults to five requested rows and may expose any positive requested count that fits; a terminal too short for even one coherent control row refuses before painting.

The shared driver owns request correctness. An optional synchronous `transform` on `InteractionOptions` canonicalises the submitted value first, then the required check runs, then the validator; the transformed value is what validation judges and what the request returns, while frames keep presenting the value as edited and masked values stay masked throughout. Once a submission has failed, the driver latches the validator to reality: every subsequent value change re-validates, the message persists through no-op keys, clears the moment the value passes, and returns live if a later edit makes it invalid again. An asynchronous verdict never blocks key handling, a verdict superseded by a newer edit is discarded, and a rejecting validation faults the interaction with full restoration; submitting while invalid re-runs the validator and re-presents the current message. Escape cancels a request exactly like Ctrl+C — cancelled frame, then `InteractionCancelled` — under its own `"Dismissed."` reason, distinct from Ctrl+C's `"Cancelled."` and EOF's `"Input ended."`. The Ctrl+U no-previous-step notice clears on the next key, restoring whatever lifecycle it covered.

Choice IDs stay stable across values and disabled choices remain visible but unselectable. Select, multiselect, and search accept one public entry union: ordinary `InteractionChoice<T>` values and semantic `InteractionGroupHeading` structure. A group heading owns a stable ID and non-empty label but no `T` value. Validation rejects duplicate or control-bearing IDs, control-bearing labels, empty headings, and required lists without a selectable choice. Initial highlight, movement, Home/End, paging, toggle-all, submission, and returned values operate only on choices. PageUp and PageDown jump the highlight one visible window in select and multiselect — sized by the most recently fitted frame rather than the requested count — landing on the nearest enabled choice past the target and clamping at the list's edges instead of wrapping. The shared choice window keeps the governing heading visible when a grouped list scrolls, without making the heading a navigation stop. Search providers may be synchronous or asynchronous and return the same entry vocabulary; `SearchRequestOptions.initialId` remembers an enabled choice by stable ID across provider reordering, filtering, and clearing without inventing a query or keypress. A missing, grouped, or disabled ID preserves the existing unhighlighted initial search state. Autocomplete uses inline ghost text. [`sequential-form.ts`](../../src/cli/interactive/sequential-form.ts) reevaluates conditional steps, retains prior values, removes values for newly inapplicable steps, and treats Ctrl+U as navigation to the preceding applicable step.

[`activity.ts`](../../src/cli/interactive/activity.ts) is the only time-advancing layer. Its scheduler advances the canonical `DISCERN_TRIANGLE_SPINNER_ORDER`; its determinate controller carries completed and total units and emits submitted lifecycle only at truthful completion. Spinner frames stay on the triangle spinner primitive, while determinate frames render through Feedback's Meter renderer, which delegates its fill to the same triangle progress authority.

Interaction modules pass their typed states directly to Component renderers. Text, masked, and autocomplete use Forms' Input; confirm uses Switch; select uses Select; multiselect uses Checkbox; search uses Radio; and textarea uses Textarea. Sequential forms render their sections through Marketing's Process steps. The removed temporary frame dispatcher leaves terminal I/O, decoding, editing, state transitions, and Component rendering as separate authorities without an intermediate presentation language.

## CLI Playground

The static CLI Catalogue prints deterministic frames; the CLI Playground drives the real Adapter in a live terminal. `deno task playground:cli` opens an interactive hub of named journeys; `deno task playground:cli --list` prints every journey ID and description without a TTY; `deno task playground:cli tour` visits every journey in recommended order; `deno task playground:cli <journey-id>` runs one journey directly, so a defective menu component never blocks review. Interactive modes refuse non-TTY stdin or stdout through the Adapter's own guard before any terminal mutation. The playground is a development and review instrument for this repository — never a published command or consumer API.

[`cli-inventory.ts`](../../scripts/cli-inventory.ts) is the shared authority both review surfaces consume: selector resolution, rendered-module loading, per-component sections, the exemption sheet, and the triangle motif sheet all derive from the generated registries and `cliExamples`, so the Catalogue, the Playground, and Codegen cannot disagree about what exists. Journeys drive only the public exports of `./cli` and `./cli/interactive` — no private interaction machines, key decoding, painters, or raw-terminal handling. Every high-level interactive API has a focused journey (text, the validation latch with a trimming transform over an asynchronous validator, masked, confirm, flat and grouped select and multiselect, search with grouped results and a remembered non-first ID, autocomplete, a ten-row textarea, sequential form with conditional steps and Ctrl+U back-navigation, spinner, determinate progress), each demonstrating meaningful variants — validation failure, initial values, disabled entries, group headings, duplicate labels under distinct IDs — and printing its typed result; masked journeys report length only. Stress journeys cover the long grouped list, visible counts 3, the package default, and 16, label and grapheme stress within the accepted repertoire (the package deliberately rejects format characters such as ZWJ in choice labels), resizing while an interaction is active, width and height review, and a repeated 16-row search-and-select loop that reproduces the reported progressive-height observation without any playground-local geometry. The direct `triangle-statuses` journey presents Timeline and stepper status direction together. The direct `heading-variants` journey renders only the settled public embedded, underline, and sandwich treatments at a readable width; the discarded candidate scaffolding is gone. Degradation journeys run live interactions through `DenoTerminalIO` constructed with synthetic `NO_COLOR`, `TERM=dumb` plus UTF-8, and exact `C`/`POSIX` environments, then name the relaunch commands (`NO_COLOR=1 deno task playground:cli`, `TERM=dumb LANG=C.UTF-8 …`, `LC_ALL=C …`) for fully degraded sessions. Every journey begins by printing the current terminal facts — columns, rows, Unicode, colour depth, ANSI control — so observations stay reproducible; journeys catch only the public `InteractionCancelled` outcome and return to the hub, unexpected faults propagate after the package restores raw mode and the cursor, and the playground never clears the terminal or erases scrollback.
