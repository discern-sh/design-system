# CLI rendering

The React-free CLI surface has four entrypoints. `./cli` renders deterministic terminal strings; the optional `./cli/interactive` Adapter owns terminal effects and turns raw input into semantic frame states; `./cli/interactive/testing` publishes the deterministic terminal that drives the real interaction machinery in package and consumer tests; and `./cli/projection` decodes package-emitted output into typed spans, reviewable HTML, and explicit terminal-layout geometry. Together they combine explicit terminal capabilities, a bound presenter, Token-derived colour and spacing, grapheme-aware text layout and editing, consumer-bindable semantic motifs with a discern preset, narration lines, a vertical rhythm contract, typed interaction state, and generated per-Component CLI enrollment.

[ADR-0011](../_adr/0011-terminal-input-uses-request-vocabulary.md) reserves “prompt” for coding-agent instructions. The terminal Adapter names individual value-producing operations `request*` and names their shared lifecycle and machinery `Interaction*`.

[ADR-0022](../_adr/0022-browse-markdown-in-an-owned-terminal-viewport.md) records why the Markdown browser owns an alternate-screen viewport, pure pane state, adaptive split/single layouts, and resumable action returns instead of extending the inline form painter.

## Boundary and data flow

[`src/cli/mod.ts`](../../src/cli/mod.ts) is the public entrypoint named by both package manifests. The graph imports [`tokens.ts`](../../src/tokens/tokens.ts), CLI foundation modules, the generated CLI registry and renderer barrel, and rendered Component CLI modules. It imports no `.tsx` module and never resolves React; the release suite checks that graph directly and also runs a publish-shaped neutral consumer.

[`src/cli/interactive/mod.ts`](../../src/cli/interactive/mod.ts) is a separate optional entrypoint in both manifests. Its graph imports the pure CLI foundation, Deno terminal APIs, and rendered Component CLI modules, but no `.tsx` module or React. Importing it performs no terminal mutation; constructing `DenoTerminalIO` and running an interaction cross the effects boundary.

[`src/cli/interactive/testing.ts`](../../src/cli/interactive/testing.ts) and [`src/cli/projection.ts`](../../src/cli/projection.ts) are the published instrument entrypoints recorded in [ADR-0013](../_adr/0013-publish-testing-and-projection-instruments.md). Release tests keep all four CLI graphs React-free, import each with zero permissions so none may perform I/O at import, and run a publish-shaped neutral consumer that drives a real scripted interaction and projects real emitted output.

Renderers receive a [`TerminalCapabilities`](../../src/cli/capabilities.ts) value containing colour depth (`none`, `ansi16`, `ansi256`, or `truecolor`), terminal columns, Unicode support, and optional ANSI cursor-control and OSC 8 hyperlink support. These are independent facts: `C.UTF-8` and `C.utf8` retain Unicode glyphs under `TERM=dumb`, while colour and cursor controls remain disabled; exact `C` and `POSIX` locales retain the ASCII fallback. [`detectTerminalCapabilities()`](../../src/cli/capabilities.ts) interprets caller-supplied `NO_COLOR`, `TERM`, `COLORTERM`, tty, locale, and width facts. It performs no process read itself. Component and motif renderers accept capabilities as an argument and perform no I/O or environment access. The compatibility-optional `ansiControl` field defaults to the earlier control assumption when callers construct capabilities manually, while detector-produced values always state it. The optional `hyperlinks` field gates OSC 8 hyperlink emission; an omitted field derives the fact from colour depth, and the detector states it from the same derivation because no portable environment fact announces hyperlink support — callers holding terminal-specific knowledge state it directly.

## Token bridge and primitives

[`theme.ts`](../../src/cli/theme.ts) derives light and dark terminal themes directly from the authored `DesignToken` and `ThemeToken` arrays. It resolves Token references, converts authored OKLCH and hexadecimal colours to sRGB, composites the authored translucent overlay over the variant canvas, and computes nearest ANSI 256- and 16-colour fallbacks. Spacing Tokens map to character cells relative to `--discern-space-2`; weight Tokens determine bold roles, while muted, emphasis, and annotation roles use dim and italic terminal attributes. No terminal palette repeats an authored design colour. The authored `--discern-measure` Token bounds prose-oriented default frame widths through [`frame-measure.ts`](../../src/cli/frame-measure.ts): ordinary form frames, Toast, Meter, and the interactive activity and sequential-form paints clamp to its character-cell value on wide terminals. Scrolling choice frames instead use the currently available terminal columns so avoidable wrapping does not hide options; an explicit `width` remains a narrowing override for either policy.

[`ansi.ts`](../../src/cli/ansi.ts) composes styled spans, emits the selected ANSI form, and owns terminal hyperlinks: `styleHyperlink()` is the single authority that writes OSC 8 envelope bytes, so no consumer or renderer composes the sequence itself. Emission follows the `hyperlinks` capability fact — derived from colour depth when the caller omits it — and emits ST-ended envelopes with an optionally styled label. The fallback never loses the label: it renders `label (url)`, or the label alone when the label already is the URL. Labels must be non-empty and control-free, URLs non-empty printable ASCII (callers percent-encode anything wider), and `stripAnsi()` removes CSI styling and complete OSC envelopes, so hyperlinked strings measure, wrap, and pad by their visible labels alone. [`text.ts`](../../src/cli/text.ts) segments graphemes for width, wrap, truncation, and padding: standardized RGI emoji sequences occupy two cells, while text-presentation pictographs follow the same pinned East Asian Width policy as other symbols. [`east-asian-width.ts`](../../src/cli/east-asian-width.ts) pins Unicode 17.0 Ambiguous and Wide/Fullwidth classifications for that measurement and for motif construction; the pinned version makes a data update an ordinary reviewed layout change. The styled family — `wrapStyledText()`, `wrapStyledTextPreservingIndent()`, and `truncateStyledText()` — wraps and truncates package-emitted styled text through the same plain-projection authorities, then re-attributes the active SGR styling and open hyperlinks to every produced line, closing and reopening them at line boundaries so each emitted line renders correctly alone. Foreign, malformed, or unterminated sequences throw; styling left open at end of input still closes on every line; truncation closes styling and hyperlinks before its always-unstyled marker, so no dangling envelope survives; output re-emits canonically at the input's original colour depth; and `padText()` pads styled content by visible cells with the added spaces outside every run. The plain and styled indentation-preserving wrappers hang continuations under a line's leading spaces, so stack traces, nested output, and styled choice rows keep their shape. [`layout.ts`](../../src/cli/layout.ts) provides vertical joins, inline cluster wrapping, and column layout. [`box.ts`](../../src/cli/box.ts) draws width-bounded frames, preserves package styling while wrapping over-wide bodies, accepts an optional styled lower-border label, and substitutes `+`, `-`, and `|` when Unicode is unavailable.

[`semantic-inline.ts`](../../src/cli/semantic-inline.ts) owns the public `SemanticInlineContent` vocabulary and its safety boundary, recorded in [ADR-0019](../_adr/0019-own-semantic-inline-content.md). A recursively readonly string-or-node tree represents text, escaped or decoded literal text, nested emphasis/strong/strikethrough, literal inline code, links, image alternatives, soft and hard breaks, and footnote references without exposing parser ASTs, React nodes, raw HTML, or caller-authored ANSI. Every projection or render validates exact data-node keys, non-empty required labels, control- and format-free visible text, stable ASCII footnote identifiers, printable URL references limited to safe absolute protocols or relative forms, link-label nesting, a 64-node depth ceiling, and cycles. `semanticInlineText()` is the one lossless no-colour projection: Markdown-like delimiters retain style distinctions, links retain unavailable targets, images name themselves and retain alternative text plus source, and footnote markers remain visible. `renderSemanticInlineContent()` derives styling from terminal Themes and the existing span and hyperlink authorities; colour-capable Unicode output gives inline code a restrained package treatment without source backticks, while no-colour and ASCII output keep the fences that carry the distinction. Components may select the package-owned body, display, strong, emphasis, muted, or annotation base typography without exposing raw styles. `wrapSemanticInlineContent()` capability-bounds the requested measure and delegates to `wrapStyledText()`, so every produced line closes and reopens nested SGR and OSC 8 state independently.

[`block-composition.ts`](../../src/cli/block-composition.ts) owns nested terminal Component structure. `createCliBlock(renderer, props)` binds semantic props to a pure Component renderer instead of accepting a rendered string; `renderCliBlock` and `renderCliBlocks` re-render children at the parent-owned measure, parse their result through the styled-sequence authority, reject foreign controls and forged blocks, normalise clean edges through `composeCliBlocks`, and stop structural recursion at 64 levels. Bounded blocks are measured line by line. A Code block created with the explicit `preserve` width policy may overflow, and that one exception propagates only through its active ancestor chain; an unrelated sibling remains bounded.

[`motif.ts`](../../src/cli/motif.ts) is the single glyph authority. A `TerminalMotif` names spinner, repeated-pattern, accent-marker, and complete/incomplete status roles for both Unicode and ASCII; `defineTerminalMotif()` validates and freezes a complete definition, while `deriveTerminalMotif()` replaces selected roles on an existing value. Unicode glyphs are single visible non-combining scalars that measure one cell and are neither Ambiguous nor Wide/Fullwidth under the pinned Unicode data. ASCII glyphs are single printable non-space characters. The opaque factory brand prevents unchecked object literals reaching renderers. The package publishes one `DISCERN_TERMINAL_MOTIF`: small solid triangles for the clockwise spinner, the established half-filled weave and marker, and up/down completion status.

[`motifs.ts`](../../src/cli/motifs.ts) asks only for those semantic roles. Its pure renderers cover horizontal, vertical, thick, phased, and reversed patterns; spinner and determinate progress frames; labelled rules; semantic workflow steps; and an out-and-back activity beacon. Labeled section rules default to one uppercase strong embedded title — two heavy cells, one motif marker, and a heavy rule filling the remaining width — instead of surrounding the label with a repeated field. Their public `treatment` option also provides a strong underline and a quiet sandwich; long labels truncate within the requested width, `=` preserves strong ASCII weight, and `-` preserves the quiet variant. Every workflow state reserves the same three-cell marker slot, so labels do not move when a step becomes active. Complete and incomplete states use their status roles; active states use the spinner role; pending, error, and cancelled states keep distinct dot, bang, and cross markers. Colours and gaps come from the terminal theme, measurement uses the shared text primitive, and the supplied ASCII repertoire preserves meaning. [ADR-0010](../_adr/0010-use-calm-full-width-cli-heading-rules.md) records the section-rule geometry; [ADR-0018](../_adr/0018-bind-semantic-terminal-motifs.md) records the motif ownership and override model.

## Presenter, narration, and rhythm

[`presenter.ts`](../../src/cli/presenter.ts) is the default way to render this surface. `createCliPresenter(capabilities, { theme, motif, width })` binds terminal capabilities, a theme variant, a semantic motif, and a default frame width once and returns a pure presenter value; `present(renderer, props)` then supplies everything except the call's own props. Props win over bound defaults one call at a time, presenter values win over the discern preset, the bound width narrows the effective columns and never widens the real terminal, and `with()` derives a re-themed, re-motifed, or re-bounded presenter from the same base terminal while leaving its source untouched. Box and the three motif APIs whose call shapes cannot satisfy the generic renderer contract have named bindings — `box`, `motifSpinnerFrame`, `motifSectionRule`, and `motifWorkflowStepper`. The raw fully specified forms remain the escape hatch for callers that thread those facts themselves. There is no mutable package-global motif and motif is not part of theme: product identity and colour selection remain independent pure inputs.

Every motif-bearing Component prop contract accepts `TerminalMotifOptions`, and the interaction runtime plus spinner, progress, activity-log, and sequential-form options carry the same motif fact through `CliPresentationOptions`. A registry-driven test renders every Component example through a custom presenter and rejects leaked discern glyphs; direct interaction tests carry that custom value through grouped headings and every time-advancing or sequential path. A source guard keeps the distinctive discern repertoire in `motif.ts` alone. New Components therefore inherit the presenter path or fail the future-enrolling test instead of silently baking in a glyph.

[`narration.ts`](../../src/cli/narration.ts) supplies the verbs for output too small to deserve a Component: `renderSuccessLine`, `renderNoteLine`, `renderWarningLine`, `renderFailureLine`, and `renderLeadLine`, each a pure `CliRenderer` over one trimmed control-free line with optional `theme`, `motif`, and `maxWidth`. Success, warning, and failure retain their semantic check, bang, and cross; note and lead use the effective motif's accent marker. Only the marker takes the tone colour, wrapped lines hang under the marker column, and the lead-in takes the embedded section rule's uppercase strong title treatment without its rule or any owned blank lines, so it stays lighter than Display Heading. `narrationLineRenderers` maps kinds to verbs for severity-driven callers, and `styleSemanticText` styles inline text by type role and semantic tone. The presenter carries all of it bound: `success`, `note`, `warning`, `failure`, `lead`, and `style`.

[`rhythm.ts`](../../src/cli/rhythm.ts) makes "exactly one blank line between semantic groups" a property of composition rather than author bookkeeping. A conforming block neither begins nor ends with a blank line and carries no trailing newline. `composeCliBlocks` normalises block edges — a Heading's owned leading boundary composes without doubling — preserves interiors byte-for-byte, drops empty blocks, and joins with exactly one blank line, so composed results nest without change. A sink that writes incrementally counts the consecutive newlines already at its stream tail, capped at two, opens every block after the first with `cliBlockBoundary(count)`, and terminates each written block with one newline. The package defines the contract and the composer but ships no sink: writing is the consumer's effect.

## Interactive terminal Adapter

[`io.ts`](../../src/cli/interactive/io.ts) defines the injectable `TerminalIO` boundary and its Deno stdin/stdout implementation. Interactions refuse to start unless both handles are TTYs. [`lifecycle.ts`](../../src/cli/interactive/lifecycle.ts) brackets raw mode and supported cursor hiding as one exception- and signal-safe operation: success, validation failure, Ctrl+C, EOF, callback exceptions, and form back-navigation all attempt the applicable restoration, and each bracket additionally installs a scoped SIGINT listener for its duration — never process-global — through the injectable `TerminalSignalSource` boundary ([`signals.ts`](../../src/cli/interactive/signals.ts)). The default signal path runs the bracket owner's restoration share, restores raw mode and the cursor exactly once, removes its own listener, and re-raises so the process still dies as an interrupt; a caller-supplied `onInterrupt` receives the signal instead and leaves restoration to the ordinary path — the required posture for hosts managing SIGINT themselves. Deno's additive listener model means the package never disturbs a host's existing listener, and `withRawTerminal`'s `hideCursor: false` holds raw mode without touching the cursor for query round-trips. [ADR-0014](../_adr/0014-bracket-sigint-through-an-injectable-source.md) records the scope, nesting guarantees, and injectability.

[`painter.ts`](../../src/cli/interactive/painter.ts) replaces a multiline frame only while the complete current and replacement frames fit within the current viewport and ANSI cursor control is available. `replace()` returns `InlineFramePaintResult`: `painted` or `unchanged` carries both frame line counts and viewport rows; `refused` adds `ansi-control-unavailable`, `frame-exceeds-viewport`, or `current-frame-exceeds-viewport`. An empty frame occupies zero rows; every newline starts another row, including a trailing newline. A refusal writes nothing and preserves the current frame. Activity drivers can select a static view from that result. Interaction drivers first use [`viewport-budget.ts`](../../src/cli/interactive/viewport-budget.ts) to fit the state through its real Component renderer, testing control windows from largest to smallest so non-linear structural rows cannot make it skip a larger fit; after a downward resize strands the previous live frame, they end that scrollback region and start a newly bounded live region. [ADR-0007](../_adr/0007-separate-terminal-rendering-and-control-capabilities.md) records why repertoire, styling, and control remain separate; [ADR-0009](../_adr/0009-fit-prompt-frames-through-component-renderers.md) records why interaction geometry is renderer-measured.

[`keys.ts`](../../src/cli/interactive/keys.ts) incrementally decodes UTF-8, retains incomplete escape sequences between reads, normalises common CSI and SS3 variants, and keeps unknown control sequences non-printable. Escape followed by an unrecognised character is an Alt/meta chord and stays a non-printable unknown sequence rather than leaking an `escape` key plus literal text. A lone Escape is disambiguated in the key reader by a short continuation window (100ms by default, tunable through `TerminalKeyReaderOptions.escapeDelayMs`): bytes arriving inside the window complete their sequence, and an elapsed window delivers the `escape` key through the decoder's `flushLoneEscape`, which never touches longer fragments — a split CSI or SS3 sequence still decodes incrementally no matter how late its remaining bytes arrive. The deliberate trade-off, recorded in [ADR-0012](../_adr/0012-deliver-lone-escape-through-a-reader-timing-window.md): continuation bytes arriving later than the window after a bare Escape byte read as Escape plus the remainder. A raw read left pending by an elapsed window is parked per terminal and adopted by the next reader on the same terminal, so an interaction ended by Escape cannot strand a read that would steal the next interaction's first bytes. [`editor.ts`](../../src/cli/interactive/editor.ts) edits by grapheme rather than UTF-16 code unit and supports Arrow, Home/End, Delete, Backspace, Option+Backspace, and the common Ctrl+A/B/E/F/H/N/P bindings. Textarea movement remains line-oriented; its visible window follows the logical cursor when wrapped content is taller than the current editor, and Ctrl+D submits it.

The interaction modules are event loops over typed state machines. Text, masked, confirm, select, multiselect, search, query-filtered multiselect, autocomplete, acknowledgement, and textarea machines return the corresponding frame shape. `InteractionRuntime` carries the same optional theme and motif as pure renderers, and the driver supplies both to every Component callback. Before every paint, the driver reads the current `TerminalIO.size().rows`, subtracts the caller's `reservedRows` — a shared request option declaring how many rows the caller's own composition occupies above the frame — and measures the real rendered frame against the remainder, so a full-budget list never scrolls a caller's header band away. A zero or absent reservation is byte-identical to an unreserved request, and a reservation taller than the viewport degrades exactly like a too-short terminal. Choice `visibleCount` and textarea `rows` are caller-requested upper bounds: a short viewport reduces only that frame's visible window, while a later resize or interaction starts again from the unchanged request. Textarea defaults to five requested rows and may expose any positive requested count that fits; a terminal too short for even one coherent control row refuses before painting.

The shared driver owns request correctness. It paints the initial frame before any machine work, so a slow provider never delays the first honest frame, and it offers machines a context whose `repaint` and `fail` land asynchronous state safely — both ignored once the interaction has finished, with machine timers and in-flight provider work disposed on every exit. An optional synchronous `transform` on `InteractionOptions` canonicalises the submitted value first, then the required check runs, then the validator; the transformed value is what validation judges and what the request returns, while frames keep presenting the value as edited and masked values stay masked throughout. Once a submission has failed, the driver latches the validator to reality: every subsequent value change re-validates — including a value changed by a provider resolution — the message persists through no-op keys, clears the moment the value passes, and returns live if a later edit makes it invalid again. An asynchronous verdict never blocks key handling, a verdict superseded by a newer edit is discarded, and a rejecting validation faults the interaction with full restoration; submitting while invalid re-runs the validator and re-presents the current message. Escape cancels a request exactly like Ctrl+C — cancelled frame, then `InteractionCancelled` — under its own `"Dismissed."` reason, distinct from Ctrl+C's `"Cancelled."` and EOF's `"Input ended."`. The Ctrl+U no-previous-step notice clears on the next key, restoring whatever lifecycle it covered. `InteractionOptions.completion` selects `retain-frame` (the established default) or `clear-frame`. Only successful validation invokes the policy: the driver either paints and finishes the submitted state or asks the active painter to clear its current geometry before returning. Validation and cancellation remain visible. Clear-frame requests raise `InteractionFrameCleanupError` before terminal mutation when cursor control is unavailable, and a resize-invalidated cleanup raises the same error without guessing erase rows; the raw-mode, cursor, and signal bracket still restores once on every exit.

Discovery providers never block the key loop. Search, query-filtered multiselect, and provider-backed autocomplete issue every provider call with a monotonic tag and an `AbortSignal` that fires when a newer query supersedes the call or the request ends; a superseded resolution is discarded unseen, so a stale result set never paints as current. The optional `debounceMs` on the shared `DiscoveryRequestPacing` options coalesces rapid edits through an injectable `InteractionDelayScheduler` — mirroring the spinner's injectable repetition — while the initial call always issues immediately, and synchronous provider results still apply within the same frame, so array-backed providers keep their immediate behaviour byte for byte. Throughout scheduling and flight the frame carries the pending truth: the form status token reads `searching` and an empty result region says `Searching…` rather than claiming no results exist, in plain text that survives `NO_COLOR` and ASCII without moving a row. A rejecting provider faults the interaction with full restoration, and a resolution that arrives after supersession or disposal is dropped rather than raised.

Choice IDs stay stable across values and disabled choices remain visible but unselectable. Select, multiselect, search, and query-filtered multiselect accept one public entry union: ordinary `InteractionChoice<T>` values and semantic `InteractionGroupHeading` structure. Either entry may add a control-free, non-empty `description`; the value remains distinct from disabled notation, follows the entry through pure frame states and windows, and renders through the one shared choice-entry authority.
