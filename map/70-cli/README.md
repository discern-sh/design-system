## Token bridge and primitives

[`theme.ts`](../../src/cli/theme.ts) keeps terminal ground and appearance independent. `theme: "light" | "dark"` selects the pole; `appearance` carries an optional `accent` hue across the complete finite `0…360` circle plus optional paper and ink tints, the same vocabulary the browser scope uses. `resolveTerminalTheme()` evaluates every appearance-owned colour through the shared opaque appearance authority, converts the resulting OKLCH values to sRGB, and computes ANSI 256 and ANSI 16 fallbacks. Untinted monochrome is the cached default exposed by compatibility values `terminalThemes.light` and `.dark`, so callers that omit `appearance`, or pass one whose accent is absent and whose tints are inert, retain the exact monochrome projection. Accent never restores the removed CSS parser or a terminal RGB table. Its pale dark-ground roles keep chromatic meaning in ANSI 16 by selecting the nearest of that palette's six hue families at the ground-appropriate intensity; success, warning, and danger therefore retain distinct green, yellow, and red families, while an Accent near one of those hues may share the finite family because the visible word or glyph remains the semantic witness. The six categorical series colours stay on ADR 0032's independent fixed projection in every appearance. A population guard requires every metadata-enrolled colour role to appear in every palette and permits only those six series roles to bypass the appearance evaluator.

Spacing Tokens map to character cells relative to `--discern-space-2`; weight Tokens determine bold roles, while muted, emphasis, and annotation roles use dim and italic terminal attributes. The authored `--discern-measure` Token bounds prose-oriented default frame widths through [`frame-measure.ts`](../../src/cli/frame-measure.ts): ordinary form frames, focus-driven menus, Toast, Meter, and the interactive activity and sequential-form paints clamp to its character-cell value on wide terminals. Form and browsing choice frames instead use the currently available terminal columns so avoidable wrapping does not hide options; an explicit `width` remains authoritative for every policy.

[`ansi.ts`](../../src/cli/ansi.ts) composes styled spans, emits Token-derived foregrounds and backgrounds at the selected ANSI depth, and owns terminal hyperlinks: `styleHyperlink()` is the single authority that writes OSC 8 envelope bytes, so no consumer or renderer composes the sequence itself. Emission follows the `hyperlinks` capability fact — derived from colour depth when the caller omits it — and emits ST-ended envelopes with an optionally styled label. The fallback never loses the label: it renders `label (url)`, or the label alone when the label already is the URL. Labels must be non-empty and control-free, URLs non-empty printable ASCII (callers percent-encode anything wider), and `stripAnsi()` removes CSI styling and complete OSC envelopes, so hyperlinked strings measure, wrap, and pad by their visible labels alone. [`text.ts`](../../src/cli/text.ts) segments graphemes for width, wrap, truncation, and padding: standardized RGI emoji sequences and Wide/Fullwidth scalars occupy two cells, while East Asian Width–Ambiguous scalars and text-presentation pictographs occupy one under the package's pinned narrow-A geometry. Wrapping breaks at spaces first; a word wider than its whole line breaks after the last `-` or `/` that fits, and is cut mid-segment only where none does, so identifiers, paths, and addresses split where their parts join. When everything after an earlier `/` fits the next line whole and the paragraph takes no more lines for it, the word breaks after that `/` instead, so a path keeps its last name together. Each helper segments its input a bounded number of times and lays it out from those measured graphemes, never segmenting again what remains after a line or piece it cuts, so wrapping, truncation, and measurement take time in proportion to their input however long an unbroken word or streamed line runs; truncation stops measuring once a line is known not to fit, the path-or-joint choice shares its count of the lines that follow across a paragraph, and the styled wrappers read a paragraph's runs forward once while re-attributing its lines. Two guards hold this. [`text_work_test.ts`](../../tests/cli/text_work_test.ts) counts the work every function the module exports causes as its input grows fourfold, enrolling new exports from the module itself: the platform segmentation, plus the pieces tried on a line and the styled runs read, which the internal [`layout-steps.ts`](../../src/cli/layout-steps.ts) tallies where segmentation cannot see them. Each input shape names any quadratic work the direct algorithm does on it — re-measuring a long word's remainder for every piece, re-wrapping the rest of a paragraph to choose a path word's break, re-reading styled runs from the first for every word — and the test requires the reference to do that work and the package to count it, so a shape that stops reaching its cause fails instead of passing vacuously. [`text_layout_parity_test.ts`](../../tests/cli/text_layout_parity_test.ts) holds the output byte-identical to the direct reference algorithm in [`text_layout_oracle.ts`](../../tests/cli/text_layout_oracle.ts) over randomized wide, combining, joined, and styled text at widths 1–120. [`east-asian-width.ts`](../../src/unicode/east-asian-width.ts) pins the Unicode 17.0 Ambiguous and Wide/Fullwidth classifications consumed by that measurement; the pinned version makes a data update an ordinary reviewed layout change. The styled family — `wrapStyledText()`, `wrapStyledTextPreservingIndent()`, and `truncateStyledText()` — wraps and truncates package-emitted styled text through the same plain-projection authorities, then re-attributes the active SGR styling and open hyperlinks to every produced line, closing and reopening them at line boundaries so each emitted line renders correctly alone. Foreign, malformed, or unterminated sequences throw; styling left open at end of input still closes on every line; truncation closes styling and hyperlinks before its always-unstyled marker, so no dangling envelope survives, and cuts where the room runs out unless `TerminalTruncateOptions.at` is `word`, which cuts prose after its last whole word and drops a clause separator before the marker, unless that would keep less than half of what fits, where it cuts mid-word so the line keeps its information; output re-emits canonically at the input's original colour depth; and `padText()` pads styled content by visible cells with the added spaces outside every run. `fillStyledLine()` instead fits one line to an exact width with a style painted inside it: the style's background underlays every run that sets none of its own, its attributes join every run, and the padding carries it, so a full-width selection bar or a tinted panel row keeps its fill; where the capabilities cannot paint the style it pads plainly. The plain and styled indentation-preserving wrappers hang continuations under a line's leading spaces, so stack traces, nested output, and styled choice rows keep their shape. [`layout.ts`](../../src/cli/layout.ts) provides vertical joins, inline cluster wrapping, and column layout. [`box.ts`](../../src/cli/box.ts) draws width-bounded frames, preserves package styling while wrapping over-wide bodies, aligns an optional title to the start, centre, or end of the upper border, centres an optional styled lower-border label, and substitutes `+`, `-`, and `|` when Unicode is unavailable. Its `style` is `light` (square corners, the default), `rounded`, or `none`, which keeps the frame's border rows and columns as blank cells so a filled panel and its bordered fallback occupy the same area; an optional `fill` paints a surface under every cell through `fillStyledLine()`. `terminalFrameGlyphs()` is the one frame-glyph authority, including the joins ruled grids use, and Table, Code block, and Code listing draw through it. [`terminal-glyphs.ts`](../../src/cli/terminal-glyphs.ts) holds `TERMINAL_GLYPHS`, the column-aware table of state, fold, consequence, flag, menu, button, chrome, and key glyphs described in [the glyph map](../15-glyphs/README.md#terminal-glyph-table). [`key-hints.ts`](../../src/cli/key-hints.ts) lays out a footer of `KeyHints`: a left cluster, primary first, and a right cluster pinned to the edge, each hint a strong key and a muted label, the primary key in accent — unless `primary: false` says the cluster has none, as when Enter does nothing, and every key draws in ink. `layoutKeyHintsCli()` returns the line — exactly the requested width — and each surviving hint's cell range, so a pointer can hit-test it; `renderKeyHintsCli()` returns the line alone. The collapse ladder is fixed: extras join the right cluster in order only while the whole left cluster leaves six cells between the clusters, left hints drop lowest `rank` first and from the end within a rank but never the primary — once only ranked hints remain, the primary label shortens to eight cells before one of them drops — below `compactBelowColumns` (56 by default) the gap tightens from three cells to two and right labels drop from the end, then the primary label shortens, then remaining right labels and hints drop. Keys are `KeyChord`s spelled as the decoder names them; `normalizeKeyChord()` also accepts `ctrl+k`, `pageDown`, and `esc`, and `formatKeyChord()` shows glyphs for Enter and the arrows (words without Unicode), carets for Ctrl chords, and `Shift+` or `⇧` for shifted keys. Several keys shown as one hint stand a space apart (`↑↓ k j`, `→ .`, `PgUp PgDn`, `Tab ⇧Tab`, `Up Down` without Unicode) except arrow glyphs that touch, which read as a pair (`↑↓`, `←→`), and three or more consecutive digits, which read as a range (`1–5`, ASCII `1-5`), so no two keys run together into what reads as one and a keys list uses one separator. A test requires every decoded key name to have a display form.

[`semantic-inline.ts`](../../src/cli/semantic-inline.ts) owns the public `SemanticInlineContent` vocabulary and its safety boundary, recorded in [ADR-0019](../_adr/0019-own-semantic-inline-content.md). A recursively readonly string-or-node tree represents text, escaped or decoded literal text, nested emphasis/strong/strikethrough, literal inline code, links, image alternatives, soft and hard breaks, and footnote references without exposing parser ASTs, React nodes, raw HTML, or caller-authored ANSI. Every projection or render validates exact data-node keys, non-empty required labels, control- and format-free visible text, stable ASCII footnote identifiers, printable URL references limited to safe absolute protocols or relative forms, link-label nesting, a 64-node depth ceiling, and cycles. `semanticInlineText()` is the one lossless no-colour projection: Markdown-like delimiters retain style distinctions, links retain unavailable targets, images name themselves and retain alternative text plus source, and footnote markers remain visible. `renderSemanticInlineContent()` derives styling from terminal Themes and the existing span and hyperlink authorities; colour-capable output gives inline code a restrained sunken-surface background, and styled Unicode output can omit source backticks, while no-colour and ASCII output keep the fences that carry the distinction. Components may select the package-owned body, display, strong, emphasis, muted, or annotation base typography without exposing raw styles. `wrapSemanticInlineContent()` capability-bounds the requested measure and delegates to `wrapStyledText()`, so every produced line closes and reopens nested SGR and OSC 8 state independently.

[`block-composition.ts`](../../src/cli/block-composition.ts) owns nested terminal Component structure. `createCliBlock(renderer, props)` binds semantic props to a pure Component renderer instead of accepting a rendered string; `renderCliBlock` and `renderCliBlocks` re-render children at the parent-owned measure, parse their result through the styled-sequence authority, reject foreign controls and forged blocks, normalise clean edges through `composeCliBlocks`, and stop structural recursion at 64 levels. Bounded blocks are measured line by line. A Code block created with the explicit `preserve` width policy may overflow, and that one exception propagates only through its active ancestor chain; an unrelated sibling remains bounded.

[`motif.ts`](../../src/cli/motif.ts) is the single glyph authority. A `TerminalMotif` names spinner, repeated-pattern, accent-marker, and complete/incomplete status roles for both Unicode and ASCII; `defineTerminalMotif()` validates and freezes a complete definition, while `deriveTerminalMotif()` replaces selected roles on an existing value. Unicode glyphs are single assigned visible non-combining scalars that measure one cell through the shared narrow-A authority, so Ambiguous glyphs are accepted while Wide/Fullwidth scalars and RGI emoji are rejected. ASCII glyphs are single printable non-space characters. The opaque factory brand prevents unchecked object literals reaching renderers. A motif speaks two registers: the everyday `marker`, optional `markerQuiet`, and `pattern` roles carry ambient accents, while the optional ceremonial `brand` register (a marker plus pattern, replaced atomically by `deriveTerminalMotif()` and resolved with everyday fallbacks through `terminalMotifRegisterRoles()` and `terminalMotifQuietMarker()`) is selected per call via `TerminalMotifOptions.register`. The package publishes one `DISCERN_TERMINAL_MOTIF`: half-filled circles for the clockwise spinner; plain triangles for the everyday register — `▲` marker, `△` quiet marker, the alternating-fill `▲ ▷ ▼ ◁` pattern, and filled/outline `▲`/`△` completion status; and the half-filled `◮` mark with its `◮ ⧩ ◭ ⧨` rotation reserved in the brand register, worn by default only by Logo and Brand. [`triangles.ts`](../../src/cli/triangles.ts) is the sibling plain-triangle authority: sixteen filled/unfilled, regular/small compass triangles paired with ASCII fallbacks through `triangleGlyph()`. Fixed component geometry draws from it instead of the motif — Meter's `▶` in-progress and `▲` complete heads, the small `▴` activity beacons, Window's `▲` and Terminal's `▶` title marks, focus markers, and disclosure carets — so a consumer motif restyles the semantic roles while component geometry stays put.

[`motifs.ts`](../../src/cli/motifs.ts) asks only for those semantic roles. Its pure renderers cover a quiet horizontal divider with either one centred accent marker or one leading marker before the rail, plus an unmarked end-capped rule for neutral document boundaries; horizontal, vertical, phased, and reversed patterns; spinner frames; labelled rules; semantic workflow steps; determinate progress with a moving marker between strong completed and quiet remaining rails; and a one-marker out-and-back activity rail. Labeled section rules default to one uppercase strong embedded title — two heavy cells, one motif marker, and a heavy rule filling the remaining width — instead of surrounding the label with a repeated pattern. Their public `treatment` option also provides a strong underline, a quiet single-row left-marker boundary that preserves the label's casing, and a quiet sandwich; long labels truncate within the requested width, `=` preserves strong ASCII weight, and `-` preserves the quiet variants. Every workflow state reserves the same three-cell marker slot, so labels do not move when a step becomes active. Complete and pending states use the complete/incomplete status roles; active states use the spinner role; error and cancelled states keep distinct bang and cross markers. Colours and gaps come from the terminal theme, measurement uses the shared text primitive, and the supplied ASCII repertoire preserves meaning. [ADR-0026](../_adr/0026-use-quiet-labelled-rules-for-subordinate-sections.md) records the current section-rule hierarchy and supersedes [ADR-0010](../_adr/0010-use-calm-full-width-cli-heading-rules.md)'s treatment inventory; [ADR-0023](../_adr/0023-bind-terminal-motifs-to-narrow-a-geometry.md) records the motif ownership, override model, and width policy.

## Presenter, narration, and rhythm

[`presenter.ts`](../../src/cli/presenter.ts) is the default way to render this surface. `createCliPresenter(capabilities, { theme, appearance, motif, register, width })` binds terminal capabilities, a ground, an appearance, a semantic motif/register, and a default frame width once and returns a pure presenter value; `present(renderer, props)` then supplies everything except the call's own props. Props win over bound defaults one call at a time, presenter values win over package defaults, the bound width narrows the effective columns and never widens the real terminal, and `with()` derives a new presenter from the same base terminal while leaving its source untouched. A monochrome presenter can opt one call or composed subtree into any accent hue; an accent presenter can opt one call back to monochrome or replace its inherited hue, and the next call returns to the bound appearance. [`CliPresentationOptions`](../../src/cli/contracts.ts) is the shared input authority, and `cliPresentationPassthrough()` forwards only explicit values so a child spread afterwards can override in either direction. There is no ambient read, mutable palette registry, singleton, async context, or React context. Box and the three motif APIs whose call shapes cannot satisfy the generic renderer contract have named bindings — `box`, `motifSpinnerFrame`, `motifSectionRule`, and `motifWorkflowStepper`. The raw fully specified forms remain the escape hatch for callers that thread those facts themselves.

These are ordinary package calls; no raw ANSI value or terminal-global configuration is involved:

```ts
import {
  createCliPresenter,
  renderBadgeCli,
} from "@discern-sh/design-system/cli";

// Omission is the byte-compatible dark-ground monochrome default.
const mono = createCliPresenter(capabilities);
mono.present(renderBadgeCli, { label: "Quiet by default" });

// An accent is one optional hue. 255 is the hue the Catalogue names Blue.
const accent = mono.with({ appearance: { accent: 335 } });
const blue = mono.with({ appearance: { accent: 255 } });

// A faintly navy ground for a monochrome presenter.
const navy = mono.with({ appearance: { inkTint: 0.4, inkTintHue: 265 } });

// One accent call inside monochrome, then inheritance returns to monochrome.
mono.present(renderBadgeCli, {
  label: "High-value status",
  appearance: { accent: 120 },
});
mono.present(renderBadgeCli, { label: "Quiet again" });

// Monochrome and a different hue inside an accent, then hue 335 resumes.
accent.present(renderBadgeCli, { label: "Neutral region", appearance: {} });
accent.present(renderBadgeCli, {
  label: "Local blue region",
  appearance: { accent: 245 },
});
accent.present(renderBadgeCli, { label: "Inherited hue 335" });
```

Ground sensing remains an effects-boundary decision owned by the caller. Appearance does not change that policy:

```ts
import { createCliPresenter } from "@discern-sh/design-system/cli";
import { senseTerminalBackground } from "@discern-sh/design-system/cli/interactive";

const reading = await senseTerminalBackground({ io, environment });
const theme = reading.ground === "light" ? "light" : "dark"; // caller chooses unknown
const presenter = createCliPresenter(capabilities, {
  theme,
  appearance: { accent: 335 },
});
```

Every rendered Component prop contract accepts `CliPresentationOptions`, and the interaction runtime plus spinner, progress, activity-log, sequential-form, and application state carry the same explicit ground, appearance, motif, and register facts. A generated-registry type proof requires every current and future rendered props type to expose every shared key. Its runtime companion renders every canonical example in monochrome and representative accent hues at both poles, all four colour depths, Unicode/ASCII, and narrow/standard/wide widths; emitted codes must belong to the selected palette, while an explicit empty appearance must equal the no-option bytes. A synthetic renderer that accepts but ignores `appearance` fails the same guard. The Catalogue's one presentation adapter feeds this contract from its global Appearance state, and cross-surface conformance compares Web and CLI under the same canonical example and exact numeric hue. New Components therefore inherit the complete presenter path or fail population conformance instead of silently resetting one presentation fact.

[`narration.ts`](../../src/cli/narration.ts) supplies the verbs for output too small to deserve a Component: `renderSuccessLine`, `renderNoteLine`, `renderWarningLine`, `renderFailureLine`, and `renderLeadLine`, each a pure `CliRenderer` over one trimmed control-free line with optional `theme`, `motif`, and `maxWidth`. Success, warning, and failure retain their semantic check, bang, and cross; note uses the fixed disclosure arrow `▸`/`>`, while lead uses the effective motif's accent marker. Only the marker takes the tone colour, wrapped lines hang under the marker column, and the lead-in takes the embedded section rule's uppercase strong title treatment without its rule or any owned blank lines, so it stays lighter than Display Heading. `narrationLineRenderers` maps kinds to verbs for severity-driven callers, and `styleSemanticText` styles inline text by type role and semantic tone. The presenter carries all of it bound: `success`, `note`, `warning`, `failure`, `lead`, and `style`.

[`rhythm.ts`](../../src/cli/rhythm.ts) makes "exactly one blank line between semantic groups" a property of composition rather than author bookkeeping. A conforming block neither begins nor ends with a blank line and carries no trailing newline. `composeCliBlocks` normalises block edges — a Heading's owned leading boundary composes without doubling — preserves interiors byte-for-byte, drops empty blocks, and joins with exactly one blank line, so composed results nest without change. A sink that writes incrementally counts the consecutive newlines already at its stream tail, capped at two, opens every block after the first with `cliBlockBoundary(count)`, and terminates each written block with one newline. The package defines the contract and the composer but ships no sink: writing is the consumer's effect.

## Component CLI contract

[`ComponentMeta`](../../src/types/component-meta.ts) requires a `cli` stance. `{ stance: "rendered" }` requires `<slug>.cli.ts`; `{ stance: "exempt", reason }` requires a non-empty explanation. ### Markdown browser

The Markdown browser is an application on the [terminal application runtime](applications.md): [`markdown-browser-view.ts`](../../src/cli/interactive/markdown-browser-view.ts) holds the `MarkdownBrowserController` that builds each view from the caller's corpus and the reader's history and answers each action, link, and dismissal, [`markdown-browser-model.ts`](../../src/cli/interactive/markdown-browser-model.ts) the corpus, options, resumable state, results, and copy, and [`markdown-browser-request.ts`](../../src/cli/interactive/markdown-browser-request.ts) the two ways to run it. [ADR-0054](../_adr/0054-the-markdown-browser-runs-on-the-application-runtime.md) records the decision.

`MarkdownBrowserOptions<Action>` takes a `label`, grouped entries — group headings, documents with stable ids, corpus-relative paths, Markdown source, and optional diagram and chart resources, caller actions, and exits — an optional search `placeholder`, `initialState`, `documentMeasure`, `mouse`, `showPaths`, a synchronous `resolveLink`, and `copy`. Construction validates the corpus — ids, labels, paths, resources against their sources, the measure — and the initial state against it, before anything reaches the terminal.

Three screens make up the browser. The **contents** is a master-detail body: a list of every entry grouped under its heading, entries before the first heading under the copy's `contents` title, where actions and exits carry a mark saying what choosing them does and documents carry none, so no row borrows a mark an application gives a state; the detail previews the selected document — its title with its description beneath, then the document as its reading will show it, a Markdown detail block starting at the title's column, without its opening title when that says the same words as the entry's label, so the title shows once — and below 80 columns a strip carries the description. A document's path shows beside its preview and title, and search matches it, only with `showPaths`, since readers seldom navigate a corpus by file. A **document** is a Markdown reading body (`document:<id>`), whose links Tab reaches and Enter follows. **Search** is a palette over every entry, ranked as the reader types, listing a document once however many groups list it — its first listing stands for the rest. `/` and Ctrl+K open search from either screen, `c` shows the contents above the document, Escape and Backspace go back through the history, and `q` closes; Escape at the place the browser started closes too. Back to the contents selects the document the reader left, and a document comes back at its own scroll with the link that was followed still focused, because the runtime remembers both by reading id.

A followed link that names a heading of the same document is the reading body's own business. Any other reaches `resolveLink` through the browser: absolute `http:`, `https:`, `mailto:`, `file:`, and scheme-relative destinations leave the documents as an external-link result; an admitted document opens, at its fragment when the heading exists; a missing heading, a document the browser was not given, and an unresolved outcome show a message and leave the reader in place. A resolver that answers with a promise fails the session, since resolution is effect-free.

`requestMarkdownBrowser()` runs the browser on its own screen. It refuses missing ANSI control or a terminal below the application minimum with `MarkdownBrowserRefusalError` before anything changes, then resolves with the chosen action, exit, or external link and a `MarkdownBrowserResumableState` — the history, the contents selection, each document's scroll position, and its focused link — after the terminal is restored; closing otherwise, Ctrl+C, EOF, and abort raise `InteractionCancelled`. `markdownBrowserCommand()` returns the nested command that opens it inside a running application, with `onClose` receiving the resumable state as one of the application's callbacks. Both take the same `respond` (`MarkdownBrowserRequestHandlers`), which answers a chosen action or external link with a command while the browser stays on screen; a failed background command shows its error's message, and `{ kind: "exit" }` closes the browser — the standalone request then resolves with the answered choice. One package-internal `markdownBrowserApplication` builds the browser for both shapes, so they cannot answer a choice differently, and the runtime tests run the same journeys through each. [The browser tests](../../tests/cli/markdown_browser_test.ts), [frames](../../tests/cli/markdown_browser_frames_test.ts), and [runtime tests](../../tests/cli/markdown_browser_request_test.ts) hold the contract, and [`application-preview.ts`](../../catalogue/application-preview.ts) drives any application's options through the pure model for the Catalogue's postures.

Mouse input is opt-in and follows the application mouse policy. Mouse reporting redirects clicks and wheel events that a terminal would otherwise use for selection or a native hyperlink gesture; many terminals use Shift as a temporary bypass, but that override is terminal-configurable, so consumers that require ordinary selection leave `mouse` off. The keyboard contract is complete either way.
