# Operational status and evidence

Operational views lead with an outcome and the action it supports. [Result summary](../../src/components/workflow/result-summary/) places its next action before counts; [Diagnostic](../../src/components/workflow/diagnostic/) places the required correction before location, reproduction and evidence. [Verification report](../../src/components/agents/verification-report/) keeps the report outcome, summary and next action outside its evidence disclosure. The caller owns the verdict: a report stamp is not inferred from a partial set of checks. The stamp follows Badge's tone recipe (a soft fill with a tone edge) and leads with the matching Feedback mark, and the report is a standalone card in the interface face.

## Inspecting evidence

Raw output and report evidence use native `details`/`summary`. They work in static HTML without an interaction controller. A closed raw summary identifies its subject, the line count of plain string content (or an authored extent for rich content), and an optional caller-reported outcome. A closed report enumerates the check population by outcome; expanding exposes every original metadata value and check, including skipped work. Metadata rows stack the value under a muted label in a narrow report and share one value column from a 28rem evidence width. Each check stacks its muted value under the label, and its outcome (the Feedback mark beside the word) sits in one end-aligned column, so failures scan down a single edge; a glyph never separates from its word. The summary's “Evidence” label never breaks inside the word, each count clause stays whole, and a wrapped clause starts its line without a dangling separator. The summary's hover fill and focus ring share one rounded shape that stays clear of the divider above it. Custom labels should identify the subject rather than repeat the word “details”.

Preformatted browser evidence is selectable, locally scrollable and keyboard reachable after expansion. Result data uses the same Raw output disclosure and composes the existing [static copy contract](../40-runtime-emitter/static-copy.md); the authored clipboard string is independent of display wrapping, including empty values, whitespace and line endings. Consumers retain responsibility for making their own rich content accessible. This local native markup does not introduce a general Disclosure Component.

Terminal reports include their evidence by default; `expanded: false` requests a closed summary frame. Raw output has an explicit expanded frame as well. Terminal presentation reflows into the allocated character width, so browser preformatted evidence and copy values remain the source for exact source formatting.

## Complete identities

Workflow and Agents browser text wraps rather than replacing a distinguishing segment with an ellipsis. This includes path prefixes, final segments, branch names, artifact names, report values, command directories and agent identities. Path reference retains its complete accessible text and exact copy payload. The [operational CSS guard](../../tests/operational_identity_test.ts) scans every authored stylesheet in these groups, including future folders; the [browser journey](../../tests/workflow_operations_browser_test.tsx) checks complete long values, containment and exact copy transport in narrow and wide allocations, and the [geometry guard](../../tests/identity_operations_geometry_test.tsx) checks Fleet column alignment and tabular figures, whole timestamps, evidence labels and count clauses, the outcome column, seamless Worklog rail segments, the disclosure ring, and the Worklog continuation dot under forced colours.

Terminal paths wrap through the Workflow text authority. File change moves a path and magnitude onto labelled lines when the combined row cannot fit. Fleet retains its established `compact`/`lossless` identity contract: operational examples request `lossless`, whose explicit identity continuations can exceed the frame width to preserve a contiguous value. Even compact Fleet rows expose full branch continuations when two distinct branches would share the same truncated cell. Consumers needing exact contiguous Fleet identities should select `lossless` rather than reconstructing wrapped cells.

## Workflow visual grammar

Workflow Components share one restrained surface grammar, repeated in each stylesheet because class ownership forbids a shared class. An in-flow panel (Command, Diagnostic, Result summary, Activity log, Prerequisite list, Standard meter and their peers) is a flat `--discern-color-surface` box with a hairline `--discern-color-border` edge at `--discern-radius-md`. A well nested inside a raised surface (the Path reference chip, Expected result inside Command, the Activity log tail, the Agent handoff prompt, the Raw output body) is `--discern-color-inset` with the same hairline at `--discern-radius-sm`, so it sits below its surface in both themes; `--discern-color-surface-sunken` stays for top-level tinted panels on the canvas, such as a standalone Expected result. Diagnostic and Result summary draw a nested Command or Raw output at `--discern-radius-sm` (Raw output reads `--discern-raw-output-radius`). Labels use `font: var(--discern-font-label)` in muted ink and sentence case, and label/value rows align on their first baseline. Only Destructive action notice keeps a `--discern-color-border-strong` frame, and only Rule carries an accent bar: a rounded inset bar inside a uniformly rounded card. Secondary guidance such as a Command failure note, a Procedure step criterion or a Retry notice label is an unframed label row rather than another band. Procedure draws the hairline between its steps, so a standalone Procedure step and the last step carry no trailing rule.

States stay legible in monochrome through a drawn mark beside the word, in an `aria-hidden` wrapper so the accessible text remains the word alone. A state that is a feedback tone wears that tone's [Feedback mark](../../src/components/feedback/feedback-marks.tsx), the same shape a Banner, Toast or Field error draws: the circle-check for finished well or safe, the octagon for failed or danger, the triangle for attention, blocked or unresolved, the information circle for an Activity log note. Lifecycle states that are not tones are drawn by [`workflow-marks.tsx`](../../src/components/workflow/workflow-marks.tsx) on the same grid: a ring with a dot for active work, a clock for waiting, an empty ring for idle, cancelled or a required prerequisite. A mark never wears a different tone from its word: Activity log sets one tone per status for both, and accent marks only active work. Terminal renderers keep their own glyph tables ([`terminal-glyphs.ts`](../../src/cli/terminal-glyphs.ts), [`result-summary.marks.ts`](../../src/components/workflow/result-summary/result-summary.marks.ts)); File change resolves its disposition marks from [`file-change.marks.ts`](../../src/components/workflow/file-change/file-change.marks.ts), shared with its terminal renderer. Result summary state, Diagnostic severity and the Destructive action notice chip compose Badge in the matching tone and lead with Badge's own mark (the tone's Feedback mark, or a dot for a changed result), so the cluster has one pill recipe; a declared result keeps a dashed strong edge and no mark. Ownership badges lead with a Badge dot for tool relationships: hollow for generated output, filled for a tool-owned file, none for an authored file, and the accent tint for a project-owned one. Standard meter leads its trend word with the arrow the value moves in. Procedure numbers its steps with counter-drawn circles, keeps `role="list"` so list semantics survive `list-style: none`, and fills the circle with the action colour for the step that carries `aria-current="step"`.

Scroll wells (the Command text, an Expected result output and the Raw output body) fade their inline end while more content remains. The fade is the start state of a scroll-driven animation, so it lifts at the scroll end, never shows when nothing overflows, and is absent in engines without scroll timelines; keyboard focus removes it. Raw output paints its well on a wrapper so the fade reaches the text and not the well. Focusable wells carry a little padding and `--discern-radius-sm`, so the focus ring has room and follows a curve, and a focused Raw output summary rings the whole disclosure. Every Workflow copy control leads with the copy glyph, and below 30rem a Command stacks its copy control under the command. Visible paths in a Command context and an Agent handoff prompt break after separators through the same helper Path reference uses. A Branch choice card is one stretched-link target, so its hover and press fills and focus ring wrap the whole card.

## Status and routine records

Fleet's optional typed status prints a semantic word independently of a custom state slot. Its `nextAction` carries caller-authored blocked-work guidance behind the same muted “Next action” label Verification report and Result summary use. Rows are subgrids of one five-track list grid, so persona, branch, state, drift and meta align from row to row; below a 40rem container each row restacks on its own template. Blocked reads in the warning tone, because it needs a person rather than reporting a failure, and is the only status word at the strong weight. Drift and meta use tabular figures. Avoid also printing the same status in a composed persona. Activity log distinguishes working, waiting, blocked, complete and cancelled with visible words; its terminal waiting/blocked snapshots apply only to an active lifecycle. The existing activity driver still owns streaming, scheduling and termination.

Transcript and Worklog accept an explicit `routineGroup` label. Only adjacent compatible records form a visual run; omission or a changed label is a boundary. Transcript additionally requires the same known speaker: exact string speakers can match directly, while rich speaker slots require a stable `speakerId`. Worklog groups only compatible completed, queued or skipped entries, leaving active and failed steps separate. Every record remains an ordered-list item, every transcript turn retains its announced speaker, and every timestamp, detail and decision stays in its original order. A Transcript body aligns under a persona speaker's name, or flush with a plain-string speaker's name; a continuation turn keeps its timestamp on the body line without wrapping it. Worklog continuation entries condense to a small status dot on an unbroken rail beneath the run's first marker; each rail segment runs from one marker's centre to the next, and both rail and dot are drawn with borders so they survive forced colours. A failed step wears the danger Feedback mark. The renderer does not inspect prose to decide whether something was a decision, deduplicate records, or infer a missing conversation.

Dense canonical examples share [neutral authored fixtures](../../src/components/agents/operational-examples.ts) between Web and CLI. Their source-owned review postures expose both reading widths and open evidence states in the existing [review instrument](../60-catalogue/visual-review.md); the browser journey guards native keyboard inspection.
