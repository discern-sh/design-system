# Operational status and evidence

Operational views lead with an outcome and the action it supports. [Result summary](../../src/components/workflow/result-summary/) places its next action before counts; [Diagnostic](../../src/components/workflow/diagnostic/) places the required correction before location, reproduction and evidence. [Verification report](../../src/components/agents/verification-report/) keeps the report outcome, summary and next action outside its evidence disclosure. The caller owns the verdict: a report stamp is not inferred from a partial set of checks.

## Inspecting evidence

Raw output and report evidence use native `details`/`summary`. They work in static HTML without an interaction controller. A closed raw summary identifies its subject, the line count of plain string content (or an authored extent for rich content), and an optional caller-reported outcome. A closed report enumerates the check population by outcome; expanding exposes every original metadata value and check, including skipped work. Each evidence row keeps its label and value on one line when they fit and otherwise stacks the value under the label on the start edge; a check's glyph and outcome word never separate, and the summary's “Evidence” label never breaks inside the word. Custom labels should identify the subject rather than repeat the word “details”.

Preformatted browser evidence is selectable, locally scrollable and keyboard reachable after expansion. Result data uses the same Raw output disclosure and composes the existing [static copy contract](../40-runtime-emitter/static-copy.md); the authored clipboard string is independent of display wrapping, including empty values, whitespace and line endings. Consumers retain responsibility for making their own rich content accessible. This local native markup does not introduce a general Disclosure Component.

Terminal reports include their evidence by default; `expanded: false` requests a closed summary frame. Raw output has an explicit expanded frame as well. Terminal presentation reflows into the allocated character width, so browser preformatted evidence and copy values remain the source for exact source formatting.

## Complete identities

Workflow and Agents browser text wraps rather than replacing a distinguishing segment with an ellipsis. This includes path prefixes, final segments, branch names, artifact names, report values, command directories and agent identities. Path reference retains its complete accessible text and exact copy payload. The [operational CSS guard](../../tests/operational_identity_test.ts) scans every authored stylesheet in these groups, including future folders; the [browser journey](../../tests/workflow_operations_browser_test.tsx) checks complete long values, containment and exact copy transport in narrow and wide allocations, and the [geometry guard](../../tests/identity_operations_geometry_test.tsx) checks Fleet column alignment, whole timestamps and evidence labels, unsplit check outcomes and the continuous Worklog rail.

Terminal paths wrap through the Workflow text authority. File change moves a path and magnitude onto labelled lines when the combined row cannot fit. Fleet retains its established `compact`/`lossless` identity contract: operational examples request `lossless`, whose explicit identity continuations can exceed the frame width to preserve a contiguous value. Even compact Fleet rows expose full branch continuations when two distinct branches would share the same truncated cell. Consumers needing exact contiguous Fleet identities should select `lossless` rather than reconstructing wrapped cells.

## Workflow visual grammar

Workflow Components share one restrained surface grammar, repeated in each stylesheet because class ownership forbids a shared class. An in-flow panel (Command, Diagnostic, Result summary, Activity log, Prerequisite list, Standard meter, a standalone Expected result and their peers) is a flat `--discern-color-surface` box with a hairline `--discern-color-border` edge at `--discern-radius-md`. An inset nested inside a panel (Expected result inside Command, the Activity log tail, the Agent handoff prompt) is `--discern-color-surface-sunken` with the same hairline at `--discern-radius-sm`. Labels use `font: var(--discern-font-label)` in muted ink and sentence case, and label/value rows align on their first baseline. Only Destructive action notice keeps a `--discern-color-border-strong` frame, and only Rule keeps a start-edge accent bar, squared at its start corners so it never tapers; secondary guidance such as a Command failure note, a Procedure step criterion or a Retry notice label is an unframed label row rather than another band. Procedure draws the hairline between its steps, so a standalone Procedure step and the last step carry no trailing rule.

States stay legible in monochrome through a glyph beside the word, rendered as an `aria-hidden` span so the accessible text remains the word alone. Where the terminal glyph table ([`terminal-glyphs.ts`](../../src/cli/terminal-glyphs.ts)) names a meaning, the web mark is that glyph, chosen by meaning rather than tone: ✓ finished well or safe, ✕ has failed, ! needs attention or is a hazard still ahead (so Destructive action notice wears ! for both Warning and Danger). Result summary and File change resolve their marks from modules shared with their terminal renderers ([`result-summary.marks.ts`](../../src/components/workflow/result-summary/result-summary.marks.ts), [`file-change.marks.ts`](../../src/components/workflow/file-change/file-change.marks.ts)). Result summary state, Diagnostic severity and the Destructive action notice chip share one state-pill recipe: a pill with a 1px tone edge, soft tone fill, label type and a strong-weight mark. Ownership badges are plain labels without a mark. Procedure numbers its steps with counter-drawn circles the same diameter as Prerequisite list markers, keeps `role="list"` so list semantics survive `list-style: none`, and fills the circle with the action colour for the step that carries `aria-current="step"`.

Single-line scroll wells (the Command text and an Expected result output) fade their inline end while more content remains; a scroll-driven animation lifts the fade at the scroll end, and keyboard focus removes it. Visible paths in a Command context break after separators through the same helper Path reference uses. A Branch choice card is one stretched-link target, so its hover fill and focus ring wrap the whole card.

## Status and routine records

Fleet's optional typed status prints a semantic word independently of a custom state slot. Its `nextAction` carries caller-authored blocked-work guidance. Rows are subgrids of one five-track list grid, so persona, branch, state, drift and meta align from row to row; below a 40rem container each row restacks on its own template. Blocked is the only status word at the strong weight. Avoid also printing the same status in a composed persona. Activity log distinguishes working, waiting, blocked, complete and cancelled with visible words; its terminal waiting/blocked snapshots apply only to an active lifecycle. The existing activity driver still owns streaming, scheduling and termination.

Transcript and Worklog accept an explicit `routineGroup` label. Only adjacent compatible records form a visual run; omission or a changed label is a boundary. Transcript additionally requires the same known speaker: exact string speakers can match directly, while rich speaker slots require a stable `speakerId`. Worklog groups only compatible completed, queued or skipped entries, leaving active and failed steps separate. Every record remains an ordered-list item, every transcript turn retains its announced speaker, and every timestamp, detail and decision stays in its original order. A Transcript body aligns under a persona speaker's name, or flush with a plain-string speaker's name; a continuation turn keeps its timestamp on the body line without wrapping it. Worklog continuation entries condense to a small status dot on an unbroken rail beneath the run's first marker. The renderer does not inspect prose to decide whether something was a decision, deduplicate records, or infer a missing conversation.

Dense canonical examples share [neutral authored fixtures](../../src/components/agents/operational-examples.ts) between Web and CLI. Their source-owned review postures expose both reading widths and open evidence states in the existing [review instrument](../60-catalogue/visual-review.md); the browser journey guards native keyboard inspection.
