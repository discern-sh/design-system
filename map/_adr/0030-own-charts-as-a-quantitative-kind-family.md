# ADR 0030: Own charts as a quantitative kind family with its own scene grammar

**Status**: accepted

## Context

The dataviz programme adds package-owned charts: typed quantitative specs rendered as deterministic SVG, a React Component, and truthful terminal frames. The diagram programme already landed the architecture this needs — typed spec → validate/layout → closed scene → independent projections, generated kind enrolment, budgeted refusals, description-first accessibility — and the two-family refactor generalized its codegen into a kind-family framework over shared internal authorities in `src/internal/`.

The obvious-looking move is to enrol chart kinds as more diagram kinds. It fails structurally. Diagrams are identity and topology: `DiagramScene` requires every connector to end in an arrowhead, admits exactly three middle-anchored text placements, closes its paint set over thirteen relationship-oriented semantic roles, and its conformance pass actively forbids the geometry charts are made of — adjacent rectangles, lines passing beneath other elements, dense unconnected marks. Charts are quantities on scales: marks whose length, position, or intensity encodes a number, axes with ticks, gridlines that render beneath data by design. Nothing in the repository computes with numbers yet — no scale, no tick mathematics, no deterministic number formatter, no series palette — and those authorities must not grow inside one kind where a second kind would fork them.

Charts also carry honesty obligations diagrams never faced: a truncated baseline, a resampled series, or a dual axis produces a drawing that lies about magnitude while looking authoritative. And the terminal contract inherits "never drop a fact" from the diagram family, but continuous quantities cannot always print exactly at cell resolution, so the family needs a stated refinement of what losslessness means rather than a silent trade.

## Decision

Charts are a second kind family beside diagrams, not new diagram kinds. The split is semantic: the diagram family owns identity-and-topology subjects; the chart family owns quantities-on-scales subjects. The chart family enrols through the same kind-family codegen as a configuration — its own kind root (`src/chart/kinds/`), vocabulary, generated files, and error-code space — and composes the shared internal authorities wave 1A promoted (geometry predicates, conservative text measurement, data safety, error mechanics, the release-corpus framework). It never imports from `src/diagram/` and never re-implements a promoted authority; a gap found in one is fixed at the authority.

**`ChartScene` is a second declared scene grammar, not a fork.** It is closed, immutable, and projection-neutral like `DiagramScene`, built from the same shared geometry arithmetic, but its vocabulary is chart-shaped: marks, data paths, point populations, area fills, axis lines, gridlines, reference lines, and single-line tick labels with start, middle, and end anchoring — the anchoring axis labels need and `DiagramText` cannot express. It is only as rich as the bar slice plus the known kind library requires; it is not a general graphics API. `conformChartScene` proves its own invariants — finite positive bounds, mark containment in the plot area, tick-label clearance, honest declared bounds, and no overlaps beyond exact declared stacking — and proves z-order by declaration: elements are ordered by a fixed layer sequence (gridlines, marks, reference lines, axis, labels), so gridlines render beneath marks — and a reference threshold stays readable above them — because the scene says so, not because crossings are forbidden. The diagram grammar and its proofs are untouched.

**Scene element granularity is decided once, per kind shape.** Countable kinds (`bar`, `distribution`) emit one element per mark, giving each mark a stable id (`mark-<series>-<category>`), cheap rectangle conformance, and a description that already enumerates the same facts row by row. Path-shaped kinds (`line`, `scatter`) emit one aggregate element per series — a data path or point population — because per-point elements would multiply conformance cost quadratically, manufacture thousands of ids no projection addresses, and imply per-point description entries where the honest description is the data table. Granularity is grammar, not kind preference.

**Series colour is a fixed six-slot family with paired non-colour cues.** Six ordered categorical slots carry authored light and dark oklch values whose hues avoid the reserved state hues (success 152, warning 74–82, danger 28), the ink hue (285), and the default accent hue (255) — under the default preset a series near 255 impersonates brand action exactly as one near 152 would impersonate success. Every slot pairs its colour with a marker glyph and a terminal fill glyph, so meaning never rides on colour alone. Palette safety is machine-checked, not asserted: a deterministic colour-vision-deficiency separation guard (Machado–Oliveira–Fernandes protan and deutan simulation at severity 1.0, adjacent slot pairs, both modes, OKLab distance, threshold pinned at the measured value) plus ANSI 256 pairwise-distinctness and a pinned ANSI 16 collapse record. Sequential encoding is not a second palette: it rides the accent ramp with lightness carrying magnitude. The theming boundary is deliberately asymmetric and permanent: browser series tokens are consumer-overridable custom properties; terminal series colours are package-authored only, because a consumer override cannot re-run the CVD and ANSI guards that make the palette safe.

**The terminal honesty ladder refines losslessness for continuous quantities.** The universal fallback for every kind is the lossless description — title, summary, axis facts, series inventory, the data table in authored order, and mechanical extremes. An enhanced frame declares one of two tiers at birth, in kind Metadata beside its CLI stance. **Exact** frames print every authored value within a declared width envelope (`bar`, and later `distribution` and `slope`). **Faithful** frames are declared-resolution approximations for kinds whose continuous data cannot print exactly: they state their resolution, print their extremes, and never distort — never resample, never rescale relative to a hidden minimum, never round a nonzero mark to nothing. This ladder is the chart family's restatement of the inherited never-drop-facts contract, made explicit here rather than silently traded on: a faithful frame is honest because it declares what it approximates, and a frame that cannot stay inside its tier declines with a typed reason and yields to the description.

**Braille canvases are refused permanently.** Braille-dot plotting is rejected for three reasons together: screen readers voice braille patterns as braille, turning a chart into noise for exactly the readers the description serves; no ASCII analogue exists at comparable resolution, so the mandatory ASCII posture would be a different chart rather than a degraded one; and colour applies per cell, so crossing series corrupt each other's colour inside a shared braille cell. The chart terminal idiom is the annotated glyph: label, eighth-block-scaled bar, printed value.

**The honesty rules are grammar and validation facts, not conventions.** Zero baselines are enforced for length-encoding kinds. Bins are declared in the spec, never renderer-adaptive. No resampling, no dual axes, no min-relative scaling. Explicit nulls are declared gaps distinct from zero. A nonzero value never renders empty. These are enforced by validation refusals and by the scene grammar itself; a projection cannot opt out.

**Numerics are integer-space and locale-free.** Tick generation uses Heckbert 1-2-5 nice steps computed in scaled-decimal integer space; labels derive by decimal integer arithmetic on (coefficient, exponent), never from a floating-point intermediate; display precision derives from the step exponent; rounding is half-away-from-zero wherever the numeric authorities quantize. The number/unit format vocabulary is closed and locale-free, designed as the future public API. A release-test-shaped graph guard bans `Intl.NumberFormat`, `Intl.DateTimeFormat`, `toLocaleString`, `toFixed`, and `Date` construction from the chart module graph — scoped exactly there, so `Intl.Segmenter` in the CLI text authority stays legitimate.

**V1 is strictly static.** The behaviour-script standard holds runtime script bytes at a ceiling that chart interactivity cannot fit under, so tooltips, zooming, and hover states are out of scope by decision, not omission. Charts ship as static SVG, static React output, and static terminal frames.

**The bar orientation hint is a deliberate, scoped divergence from ADR-0028's no-presentation-hints stance.** A bar spec may state `orientation: "vertical" | "horizontal"`. Orientation changes no semantic fact — the description ignores it — but for label-heavy categorical data the horizontal form is the difference between a readable chart and a density refusal, and no mechanical rule can choose for the author without making equal specs produce surprising scenes. The divergence is scoped to restrained layout-posture hints of this shape; free placement, per-mark styling, and pixel coordinates remain refused.

**V1 `bar` rejects negative values with a typed refusal.** The zero-baseline rule makes downward bars a distinct grammar (a diverging variant with a stated axis treatment), not a degenerate case of the upward one. Until that variant is designed, a negative value fails validation with a refusal that names the deferred diverging variant, and the deferral is recorded in `discern/TODO.md`.

**A declared-enhanced chart kind without a landed projector is handled by the family CLI surface being optional, then mandatory.** The kind-family framework treats a family's terminal projector surface (module stance, generated CLI registry, CLI contracts module) as one optional configuration group. The chart family omits it in this wave: chart kind Metadata already declares its CLI stance and honesty tier at birth, but no chart CLI registry is generated and a chart `*.cli.ts` file is a loud generation failure — nothing can silently decline. Wave 3A enables the surface, and the framework's existing two-way stance pairing immediately makes a still-missing `bar.cli.ts` a generation failure. The guarantee is machine-checked today by enabling the surface against the real chart config in a test and watching generation refuse. The diagram family's pairing is unchanged.

## Consequences

Wave 3A can build the entire public surface — SVG emitter, React `Chart`, CLI frames, documented series tokens — against foundations that are already proven: a spec that validates honestly, a scene whose geometry is conformance-proven, numerals that are byte-identical on every engine, glyphs that degrade to ASCII without losing a fact, and a palette whose safety is machine-checked. Adding a chart kind is a folder plus Metadata; the family codegen fails when a surface is missing.

The costs are accepted deliberately. Two scene grammars must be maintained, and an element useful to both families must be promoted to `src/internal/` rather than imported across the boundary. The six-slot palette caps simultaneous series at six, and complexity budgets refuse rather than squeeze. The honesty rules refuse charts other libraries draw — truncated baselines, dual axes, adaptive bins — and that refusal is the product. The consumer-theming asymmetry means a re-branded browser palette and the terminal palette can drift apart visually; the paired glyph cues are what keep meaning stable across that drift. Strictly static v1 forecloses interaction until a later decision revisits the behaviour-script ceiling. The orientation hint sets a precedent that must be policed: every future hint proposal is measured against this ADR's scope, restrained layout posture only.

## Alternatives considered

**Enrolling charts as diagram kinds** would reuse the landed scene and conformance wholesale, but every structural premise fails: mandatory arrowheads, middle-only text, a closed relationship paint set, and overlap prohibitions that forbid adjacent bars and underlying gridlines. Bending `DiagramScene` to admit both vocabularies would cost the diagram proofs their strictness — the connector rules are strict _because_ the grammar is closed.

**One merged super-scene grammar** for both families was rejected for the same reason from the other side: a grammar wide enough for marks, axes, arrowheads, and lifelines can prove almost nothing universally, and every projection pays for the union. Two small closed grammars over shared arithmetic keep each family's proofs strong.

**Braille-resolution terminal charts** were surveyed and refused permanently rather than deferred; the three reasons above are structural, not maturity gaps.

**Auto-selecting bar orientation from measured label widths** would avoid the presentation hint but makes scene shape an emergent property of font metrics — a spec edit far from the labels could flip every consumer's chart form. An explicit restrained hint keeps equal specs producing predictable scenes.

**A per-kind "projector pending" flag** was rejected for the deferred-projector problem: it would generate a CLI registry entry that declares enhanced while silently declining, exactly the gap the stance contract exists to prevent. Making the family surface itself optional generates nothing that can lie.
