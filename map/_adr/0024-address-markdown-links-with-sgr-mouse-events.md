# ADR 0024: Address Markdown links through semantic events and opt-in SGR mouse tracking

**Status**: accepted

## Context

The package-owned Markdown browser can search, open, and scroll caller-supplied documents, while the Markdown renderer can preserve safe destinations in OSC 8 envelopes. Those contracts do not make a link part of the browser's navigation state: relative destinations still have no caller-owned resolution boundary, fragments have no heading-scroll operation, repeated or wrapped links have no stable focus identity, and an OSC-capable terminal does not thereby support mouse reporting. Reading emitted bytes again inside the state machine would also duplicate the styled-sequence grammar and lose the neutral Markdown occurrence that distinguishes repeated destinations.

Mouse reporting changes terminal process state. While it is active, clicks and wheel input that would ordinarily select text or invoke a terminal hyperlink can be delivered to the application instead. Enabling a protocol therefore needs the same partial-entry and exact-restoration discipline as raw mode, cursor visibility, signals, and the alternate screen. Keyboard navigation must remain complete because there is no portable positive detector for mouse reporting and because a caller may deliberately leave it disabled.

Following a link can cross the package's effects boundary. The design system may navigate among documents already admitted by the caller and may return an external destination, but it must not infer a filesystem root, load a document, or open an operating-system browser while terminal state is active.

## Decision

Terminal input gains an additive `TerminalInputEvent` vocabulary beside the source-compatible `TerminalKey` and `TerminalKeyReader` APIs. One incremental reader retains the existing UTF-8, split-sequence, and lone-Escape timing model, then classifies complete SGR mouse reports as typed press, release, wheel-up, or wheel-down events with one-based terminal-cell coordinates and Shift, Alt, and Control modifier facts. Coordinates are positive safe integers under a documented package bound. Malformed mouse-shaped CSI, motion reports, unsupported buttons, horizontal wheels, and unknown controls become non-text unknown events; control bytes never enter an editor.

Mouse tracking uses DECSET 1000 normal tracking plus DECSET 1006 SGR extended coordinates. The browser does not enable 1002/1003 motion tracking, drag selection, hover, or legacy byte-coordinate reporting. `requestMarkdownBrowser` enables tracking only when the caller explicitly opts in, stdin and stdout are interactive, ANSI control is available, and the independent `mouseTracking` capability has not refused it. An omitted capability means portable detection is unknown and the request-level opt-in is the caller's terminal-specific assertion. OSC 8 hyperlink support, colour depth, Unicode repertoire, cursor control, and mouse tracking remain separate facts; none implies another.

The lifecycle bracket subscribes to signals before mutation, then enters raw mode, the alternate screen, DECSET 1000, DECSET 1006, and cursor hiding in that order. Each completed entry records its own cleanup eligibility. Normal completion first removes browser resize and cancellation observers, then the bracket removes its signal listener and restores DECSET 1006, DECSET 1000, cursor visibility, the normal screen, and raw mode in reverse ownership order. The signal path runs the browser's observer cleanup before the same terminal restoration. A failed entry emits cleanup only for earlier modes known to have completed; all applicable cleanup continues after a cleanup failure. An operation or entry error remains primary when cleanup also fails, while cleanup failures surface when the operation otherwise succeeded. Importing the Adapter remains inert.

Markdown link identity begins in the package-owned neutral document, not in an ANSI parser. During browser projection, each admitted semantic link receives a stable document-local occurrence identity before Component rendering. The normal Markdown renderers still own layout and wrapping. The existing styled-sequence/projection authority decodes that package-emitted result once into cell-measured rows, groups every wrapped row under the original occurrence, and remaps or removes the internal hyperlink envelope according to actual OSC 8 support. The browser state machine consumes typed link occurrences and hit regions, never OSC or SGR bytes. Repeated destinations remain distinct occurrences, and heading fragments use the neutral Markdown heading-id authority.

In the document pane, `]` focuses or advances to the first visible or next logical link, `[` traverses in reverse, Enter activates the focused occurrence, and Escape first clears link focus before retaining its existing close-document meaning. Tab and Shift+Tab remain pane switching, and ordinary scroll keys remain available. Traversal reveals the complete focus target as far as the viewport allows. Focus decoration is independently closed on every rendered row and includes a non-colour, ASCII-safe marker. The footer reports only commands active in the current posture.

A resolver receives the source document ID and corpus-relative path, the admitted destination, and readonly facts for every available document. Its closed result is one of: an admitted document with an optional fragment, a same-document fragment, a safe external destination, or an unresolved outcome with bounded feedback. Same-document fragments scroll through the package heading map. Document results open only an ID already present in the request and start at the resolved heading or first row. External results return a typed external-link action plus resumable browser state; the request resolves only after terminal restoration, so the consumer performs any browser or operating-system effect afterwards. Unresolved or missing fragments leave the document, query, picker, and ordinary scroll state intact. Unsafe Markdown destinations remain inert visible text under the semantic-inline policy and never become resolver input or hit regions.

When tracking is active, a primary-button press on a selectable picker row focuses that pane and selects the row; group headings remain structural. A press in document content focuses the document and a press on a link follows the same resolution path as Enter. Wheel input scrolls the pane beneath its coordinates without first changing keyboard focus. Coordinates outside the frame and rows or cells owned by borders, titles, and hints are inert. A resize transition precedes the next pointer transition, so hit regions always derive from the current paint geometry.

Mouse reporting temporarily displaces ordinary terminal selection and native hyperlink gestures. Public guidance tells users that many terminals use Shift as a temporary application-mouse bypass for selection or their native link gesture, while explicitly noting that the modifier is terminal-configurable rather than part of this package's protocol. Callers that require native selection leave mouse tracking off. No-colour, ASCII, OSC-less, mouse-refused, and no-mouse postures retain the complete keyboard contract; a control-less or non-interactive terminal retains the browser's existing pre-mutation refusal.

## Consequences

Consumers gain deterministic keyboard and optional pointer navigation without granting the package filesystem, network, browser, or process-opening authority. Tests can script semantic mouse events, resolver outcomes, and cell hit regions through the published fake terminal instead of hand-authoring CSI bytes. The one lifecycle bracket makes partial mouse entry and every exit path auditable alongside existing screen, cursor, raw-mode, resize, and SIGINT restoration.

The public state, event, resolver, result, capability, testing, and projection surfaces grow under SemVer. Rendering links with stable identities requires one browser-specific projection pass over the neutral document and package-emitted styled spans, and focus can change wrapping because its visible degraded marker is real terminal content. Mouse-enabled users trade ordinary unmodified selection for pointer operation for the duration of the alternate-screen request; that cost is why opt-in remains explicit.

## Alternatives considered

Treating OSC 8 support as mouse support was rejected because hyperlink envelopes are output styling while mouse reporting is a separate input mode. Legacy X10 coordinates were rejected because they cannot represent modern terminal dimensions safely. Any-event or button-motion tracking was rejected because click and wheel behaviour needs no motion stream and the extra reports interfere further with terminal selection. Parsing OSC 8 inside the browser state machine was rejected because it would create a second byte grammar and still fail to distinguish repeated destinations reliably. Passing a filesystem loader or browser callback into the package was rejected because it would perform consumer effects before terminal restoration and make corpus policy part of the design system.
