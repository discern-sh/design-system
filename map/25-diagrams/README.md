# Diagrams

The diagram subsystem owns semantic, documentation-scale reference diagrams between author data and presentation. [`src/diagram/mod.ts`](../../src/diagram/mod.ts) is the published React-free `./diagram` boundary: the closed `DiagramSpec` union, kind types, `diagramAltText`, `describeDiagram`, supported-kind Metadata, the generated `diagramKindAuthorGuide`, `renderDiagramMarkdownImage`, and `renderDiagramSvg`. It deliberately does not export caller-authored scenes, layout dispatch, generated fixtures, or terminal machinery. The package root remains unchanged.

[ADR-0028](../_adr/0028-own-diagrams-as-typed-semantics-and-neutral-scenes.md) records why typed specs, a closed scene, generated built-in kinds, description-first terminals, and independent SVG postures form one boundary. [ADR-0029](../_adr/0029-upgrade-markdown-images-through-explicit-diagram-resources.md) records why ordinary image syntax upgrades only through caller-supplied source-to-spec resources.

## Choose by the reader's verb

Kinds are reference archetypes, not skins over a graph language. Start with what the reader must do when revisiting the document:

| Reader task                                        | Kind           | Semantic boundary                                                                                                               | CLI posture                                                |
| -------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Trace steps, decisions, or an explicit return      | `flow`         | Ordered process nodes and directed progressions; restrained branches and return edges also cover small state machines           | Enhanced while its viability envelope preserves every fact |
| Locate parts, ownership, and directed dependencies | `architecture` | Stable role-bearing nodes, labelled relationships, and optional one-level ownership boundaries; at most one focal node          | Description                                                |
| Revisit an ordered practice that repeats           | `cycle`        | Three or more authored stages around one loop, with one optional shared hub and at most one named hub relationship per stage    | Enhanced while its viability envelope preserves every fact |
| Follow who communicates what, and when             | `sequence`     | Stable participants and authored call, signal, return, or self-message order, with notes attached to one participant or message | Enhanced while its viability envelope preserves every fact |
| Compare scheduled spans and dated gates            | `timeline`     | One explicit half-open ISO date range, one-level groups and rows, half-open task bars, and one-date milestones                  | Description                                                |

Use `flow` when a state-like subject is adequately explained as decisions plus explicit returns; there is no separate state kind. A need for arbitrary nesting, network-scale topology, timing protocols, unconstrained dates, coordinates, ports, custom shapes, or raw SVG means the requested model is outside this library. A meaningful physical schematic, spatial metaphor, animation, control, or bespoke illustration remains consumer-owned; Artwork continues to own only semantically disposable decoration.

The exact purpose guidance, CLI stance, numerical limits, and remedy identifier for every kind come from its `*.meta.ts`. The kind-family framework in [`scripts/kind-family.ts`](../../scripts/kind-family.ts) — with [`scripts/generate.ts`](../../scripts/generate.ts) supplying the diagram family's configuration and writing the results — turns that one inventory into the public Metadata, `diagramKindAuthorGuide`, authoring and validated unions, runtime dispatch, registry, CLI registry, and export barrel. A future kind cannot join only one projection.

## Authoring and refusal boundary

All inputs are JSON-safe semantic data with stable identifiers, required title and summary, plain labels, and no environment-derived values. Labels are concise sentence case while code, acronyms, and proper nouns retain their required spelling; edge and message labels name only the relationship they distinguish. Validation rejects extra fields, duplicate identities, dangling or ambiguous references, normalization-hostile text, and kind-specific contradictions before layout. Budgets are measurable rather than aesthetic: population, relationship density, wrap count, total wording, and scene extent are named dimensions. Refusals carry the received fact, limit, and a practical action such as shortening a label, reducing a tier or participant set, shortening a date range, splitting a group, or publishing an overview beside a focused diagram. A render never squeezes, clips, or drops facts to evade a budget.

Timeline dates are parsed as proleptic Gregorian `YYYY-MM-DD` strings without `Date`, locale, timezone, or clock access; the calendar arithmetic is the shared [`src/internal/iso-date.ts`](../../src/internal/iso-date.ts) authority, with the timeline kind binding the diagram refusal messages. Its range and task ends are exclusive, while a milestone names one included date. This duration grammar is separate from the Editorial Timeline Component, which owns narrative entries rather than bars on a calendar scale.

## One scene authority

The generated dispatch under [`src/generated/`](../../src/generated/) validates once for each projection, then feeds the selected kind's deterministic layout and description. Universal scene validity belongs to [`conformance.ts`](../../src/diagram/conformance.ts). Shared layout authority in [`layout-authority.ts`](../../src/diagram/layout-authority.ts) owns conservative text measurement, positioned text, connector arrowheads, guide construction, translation, bounds, and final scene creation. Regions are shared by architecture boundaries and timeline groups; guides are shared by sequence lifelines and timeline scales; explicit polylines are shared by cycles and sequences. Kind-specific ranking, ring arithmetic, participant columns, and calendar scaling stay inside their kind folders rather than becoming a general solver.

The family-neutral substrate beneath those authorities lives in [`src/internal/`](../../src/internal/): scene geometry arithmetic and the conformance predicates, the font metric tables with grapheme clustering, measurement, and wrapping, measured-text composition, the standalone SVG document scaffold and number format, JSON/text/identifier data safety, the kind-error mechanics, Token literal resolution, XML/Markdown escaping, and the kind Metadata/release-corpus framework. Each diagram module above is the facade that binds diagram policy — precision and tolerance values, budgets, error classes and codes, the paint map, message vocabulary — onto those shared facts, so a sibling kind family reuses them without importing anything from `src/diagram/`. `src/internal/` is never a public entrypoint.

[`roles.ts`](../../src/diagram/roles.ts) is the paired style authority. Node bundles keep surface, border, ink, and a non-colour cue together; connector bundles keep stroke, marker, and line treatment together. Architecture prints every node role and uses a focus treatment only for the focal node. Cycle numbers every stage and separates the outer direction from hub spokes. Sequence gives message kinds distinct line geometry and labels. Timeline names critical gates and uses a diamond rather than colour alone. Every semantic fact also appears in the kind's deterministic Unicode-independent description.

## Projection boundary

[`renderDiagramSvg`](../../src/diagram/svg.ts) returns one complete byte-stable SVG document and performs no I/O. Canonical root attributes, `<title>`, `<desc>`, embedded style, canvas, regions, guides, connectors, shapes, and text have fixed order. Semantic text remains escaped, conservatively bounded, and middle-anchored as real `<text>`; explicit arrowhead polygons avoid global IDs, external definitions, and `context-stroke`. Light and dark modes resolve public diagram Tokens to literal values. Adaptive embeds light as its deterministic fallback and a self-contained dark `prefers-color-scheme` rule.

[`Diagram`](../../src/components/editorial/diagram/diagram.tsx) is the Editorial React projection. It maps the conformant scene directly to semantic SVG elements, never parses the serializer string, and admits no caller SVG, coordinates, markup, child labels, accessibility overrides, or arbitrary style. An inline-size-contained, focusable horizontal viewport preserves intrinsic geometry in narrow containers and prevents the SVG's preferred width from widening a grid or flex ancestor; the SVG carries its name and description directly without generated relationship IDs, so repeated diagrams remain collision-free. Required title and summary name the image and the full structural description retains every fact, but neither becomes visible canvas prose. DataFigure owns visible title, caption, source, and legend.

[`renderDiagramCli`](../../src/components/editorial/diagram/diagram.cli.ts) is the generated CLI Component renderer. Description mode always formats the universal description through the existing Theme, text, layout, and rhythm authorities. Auto mode asks [`diagram-cli-registry.ts`](../../src/generated/diagram-cli-registry.ts). Flow, cycle, and sequence may return complete enhanced frames within conservative width and density envelopes; a typed decline selects the description. Architecture deliberately remains description-first because grouped ownership plus exterior relationship routing cannot preserve every boundary fact at normal terminal widths. Timeline remains description-first because a useful calendar scale, row ownership, exact dates, durations, and gates cannot all survive a normal-width frame. Neither stance crops or abbreviates.

[`MarkdownDiagramResource`](../../src/diagram/markdown.ts) is the explicit bridge back from an ordinary generated asset reference to typed semantics. A consumer authors a spec, writes `renderDiagramSvg(spec)` to its chosen asset path during its own build, and uses `renderDiagramMarkdownImage(resource)` to serialize safe standard image syntax with the canonical alt and summary title. React Markdown, CLI Markdown, and each interactive Markdown-browser document may register that same resource to upgrade an isolated matching image. Matching uses the existing safe normalized URL reference, duplicate normalized sources reject, alt and optional title must agree with the spec, and valid unused resources are allowed for a shared corpus collection. No package projection reads the asset or resolves the path against a host location.
