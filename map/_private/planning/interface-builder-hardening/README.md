# Interface builder hardening programme

One delegation brief for taking the Catalogue-only interface builder from a viable prototype to a production-ready authoring surface. The builder currently lives only on `agent/visual-interface-builder-4df23e`; it is not yet on `main`, so the brief composes below that branch after its gate proof is green.

The work stays in one session and one worktree because its real seams meet in the same authorities: `catalogue/builder/app.tsx`, `builder.css`, `render.tsx`, `export.ts`, and the browser conformance gate. Splitting security, accessibility, responsive layout, and browser proof across separate worktrees would make each stream edit the same files and relocate the collision to integration time. The coordinating agent may use sub-agents for bounded, disjoint audits or source slices inside its own worktree, but owns every integration decision, commit, generated surface, preview, gate run, and landing attempt.

## Confirmed starting evidence

The brief is based on a fresh review after the builder branch was updated through `main` at `ffe0c8c`. Agents must verify these anchors against their live worktree because line numbers and component inventory can move.

| Area                              | Current evidence                                                                                                                                                                                                                                                                                   | Required outcome                                                                                                                                                                                      |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preview trust boundary            | `catalogue/builder/render.tsx` parses `node.extra` and merges it into live React props. A saved document containing `dangerouslySetInnerHTML` currently renders authored HTML inside a spreading Component such as Card.                                                                           | Imported, restored, edited, previewed, and exported documents share one explicit safe-data policy; source files can never execute HTML or smuggle React escape hatches.                               |
| Document resource bounds          | `parseDocument` recursively accepts an unbounded JSON tree and unbounded strings, while history retains up to 100 complete document snapshots.                                                                                                                                                     | Hostile or accidental files fail early with useful errors before recursion, rendering, export, storage, or history can exhaust the page.                                                              |
| Export validity                   | Naming a composition `Button` currently generates both `import { Button }` and `export function Button()`. Required callbacks such as `ThemeSwitcher.onModeChange` are hidden from controls and omitted from exported TSX.                                                                         | Every export is deterministic, syntactically valid, and type-checkable; consumer wiring holes are explicit rather than silently missing or silently inert.                                            |
| Preview/export parity             | Additional props accept any JSON source; preview ignores non-object values while export spreads them, and additional props can overwrite modeled props.                                                                                                                                            | The canvas and emitted source use the same canonical value and precedence rules.                                                                                                                      |
| Persistence and files             | Initial corrupt storage has a recovery path, but ordinary autosave, theme reads/writes, and asynchronous `file.text()` failures can still throw or reject without a durable in-app status.                                                                                                         | Storage denial/quota, malformed files, oversized files, and read failures leave the current document usable and tell the user what happened.                                                          |
| Keyboard and assistive technology | The live preview contains the Component tree's real focusable controls even though canvas click capture suppresses their behavior. Global Delete/Backspace handling excludes form fields but not other interactive controls. Search and icon-only move controls lack robust names/focus treatment. | The outline/inspector form a complete keyboard path; preview content cannot become a misleading tab stop; shortcuts, focus, names, status, forced colours, and screen-reader feedback are deliberate. |
| Adaptive layout                   | `builder.css` fixes a 280px palette, flexible canvas, and 340px inspector in a `100vh` three-column grid and defines no media/container response.                                                                                                                                                  | Wide, narrow, touch, and 400%-zoom users can reach Palette, Canvas, and Inspector without page-level horizontal overflow or drag-only actions.                                                        |
| Placement precision               | A drop on empty root canvas space always appends, even when the pointer is between root siblings; only the outline can insert before a sibling.                                                                                                                                                    | Pointer insertion has visible, position-aware root targets while click, keyboard, and outline alternatives remain complete.                                                                           |
| Browser proof                     | `tests/builder_test.ts` provides strong pure/regression coverage, but the production browser gate does not exercise the builder route, axe, focus traversal, adaptive panes, file lifecycle, or hostile import behavior.                                                                           | The normal conformance job proves the real route in Chromium across themes and representative viewports and fails on console/page/accessibility regressions.                                          |

This is the final stage of a below-trunk stack, not an independently landed parallel wave. The receiving agent uses the `discern-await-the-fleet` skill to observe the exact immutable base and follows its met hint; nobody guesses a commit or creates a worktree early.

## Landing authority

Dispatch is entirely owner-controlled; this planning work starts no session or sub-agent. After the hardening agent has committed a clean tree and `discern_done` passes, it runs `discern_accept`. A standing or per-worktree recorded grant may land the complete builder stack; without one, the verb refuses without mutation and the agent reports the proof line and worktree for review. Prose in this brief grants no landing authority.

## Review loop

When 1A reports green, review the branch diff against `main`, not its summary. Re-run the gate in its worktree and exercise the exact builder preview URL. Try malformed, oversized, deeply nested, and HTML-bearing saved documents; composition names colliding with every imported export; Components with required callbacks; keyboard-only placement/edit/reorder/delete/undo; narrow and 400%-zoom pane navigation; forced colours; storage denial; and file read failure. Look especially for a blocklist applied only in the UI while imported state bypasses it, an axe-only accessibility pass with unusable focus order, mobile CSS that merely hides an essential pane, generated TSX that looks plausible but was never type-checked, or browser tests that duplicate rather than compose the existing conformance authorities.
