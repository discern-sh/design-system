## Background

The builder is a capable Catalogue-only composition tool: its document model, derived controls, shared canvas renderer, JSON save format, TSX/runtime-selection export, dependency-cost view, history, drag/click placement, outline, and inspector all work and have substantial pure tests. It now follows the Catalogue rename and the current CLI-era Component/type registry.

The remaining gap is that it treats locally-authored and file-imported data as if both were trusted. `node.extra` is parsed and merged into live React props; an imported payload with `dangerouslySetInnerHTML` currently injects raw HTML through a Component that spreads DOM props. Parsing and history have no resource bounds. Preview and export disagree on malformed additional-prop shapes. Composition names can collide with imported Component exports, and Components with required callbacks produce incomplete TSX. Storage and file failures are not consistently contained. The desktop-only three-pane layout, intercepted live preview, global shortcuts, and missing browser coverage leave accessibility and adaptive behavior unproved.

Production-ready here means a robust local authoring instrument, not a hosted page builder: no accounts, cloud persistence, collaboration, arbitrary code execution, or published builder API.

## Deliverables

Work in atomic commits, one logical change per commit.

1. **Create one safe document/value authority.** Define a framework-neutral policy used by saved-file import, local-storage restoration, inspector edits, canvas rendering, and TSX generation—not parallel UI and exporter blocklists. Additional props must be a plain JSON object and must not override modeled children/props or carry React/DOM escape hatches such as raw HTML, refs, keys, executable handler names, or prototype-sensitive keys. Preserve legitimate `aria-*`, `data-*`, class, style, and ordinary safe DOM/Component props through an explicit, tested policy. Apply equivalent recursive safety to JSON-valued props where object-literal semantics could differ from parsed JSON. The same accepted document must mean the same thing in preview and export; rejected input names its exact path and reason.
2. **Bound untrusted documents before expensive work.** Put defendable limits on input bytes, tree depth, total nodes, per-slot children, identifiers/names/text, and raw JSON sources, taking the builder's 100-snapshot history into account. Enforce limits during one validating walk before recursive render/export/history work. Boundary values pass, the next value fails deterministically, and malformed/deep input produces `BuilderDocumentError` rather than `RangeError`, a frozen tab, partial state, or a generic crash. Keep version validation explicit and leave a clear seam for a future migration without inventing one now.
3. **Make persistence and file workflows failure-safe.** Centralise guarded storage access for document autosave, recovery, and theme preference. Storage denial, quota exhaustion, and corrupt saved state must leave the current document editable and surface a durable, accessible in-app status; preserve recoverable source when possible without repeatedly throwing. Bound file size before reading, handle `file.text()` rejection as well as parse failure, keep the current composition unchanged on every failed load, and allow retrying the same file. Replace blocking `alert`/opaque failure paths with package-consistent inline status or feedback. Keep save-file naming deterministic and object-URL cleanup reliable.
4. **Guarantee consumer-ready export.** Derive a deterministic component function identifier that cannot collide with any imported Component export and remains stable for hostile, blank, numeric, Unicode, or punctuation-only names. Define and implement an explicit output contract for required non-serialisable callbacks such as `ThemeSwitcher.onModeChange`: generated source must type-check and make consumer wiring unmistakable; a silent no-op is not an acceptable production contract. Preserve slot/newline meaning, safe comments/strings, canonical prop precedence, selection closure, and deterministic ordering. Add a test that generates representative and adversarial documents—including every placeable Component class—and actually parses/formats and type-checks their TSX against `@discern-sh/design-system/react`, rather than asserting only substrings.
5. **Make the workspace genuinely keyboard and assistive-technology usable.** Treat the rendered canvas as an inspection surface, not a second accidental application: its internal links, buttons, and fields must not become misleading tab stops or activatable controls while click capture suppresses them. Keep the outline and inspector as the complete semantic selection/editing route. Scope Delete/Backspace and undo/redo so focused buttons, links, disclosures, file controls, and other interactive descendants never trigger destructive global actions. Give search, move/reorder, palette, file, status, and icon controls robust names; announce placement, movement, deletion, load, recovery, and errors where feedback is otherwise visual; restore focus sensibly after structural changes. Add token-based `:focus-visible` treatment and forced-colour support without removing native focus unless a visible replacement exists.
6. **Provide an adaptive, non-drag-dependent workspace.** Define and implement explicit wide, intermediate, narrow/touch, and 400%-zoom behavior for Toolbar, Palette, Canvas, and Inspector. At constrained widths, use a truthful pane/tab/drawer workflow or another tested layout in which all three surfaces remain reachable, state and focus survive pane changes, and the document viewport does not overflow horizontally. Use dynamic viewport sizing rather than pinning mobile browsers to `100vh`. Click-to-place, outline selection/reorder, inspector move buttons, save/load, and all editing remain complete without HTML drag-and-drop; native drag stays a progressive enhancement.
7. **Finish placement precision.** Cure the recorded root-drop limitation in `discern/TODO.md`: calculate before/after insertion from pointer position at the root and show stable insertion indicators between siblings, rather than treating every empty-space drop as append. Preserve subtree protection, slot drops, outline-before drops, explicit end-of-page drops, selection, history, and keyboard/non-drag alternatives. Test geometry separately from DOM events where possible, and cover first, middle, last, empty, nested, self, and descendant moves.
8. **Put the builder in the real browser gate.** Compose a focused builder conformance module with the existing server, browser launcher, viewport transaction helper, axe setup, console/page-error collection, and screenshot conventions; do not create a second browser harness. Exercise the canonical `/catalogue/builder/` route in light and dark themes at wide desktop, an intermediate width, 390px, and the project's 320-CSS-pixel/400%-zoom posture. Prove no page-level horizontal overflow; every adaptive pane is reachable; keyboard traversal is finite and visibly focused; canvas internals are not tab stops; click placement, selection, edit, move, undo/redo, safe load failure, and recovery status work; and axe reports no WCAG A/AA/2.1/2.2 violations. Add at least one wide and one narrow review screenshot. Keep pure security/export/limit cases in fast tests and browser-only behavior in conformance.
9. **Re-run the class-level inventory.** The existing test that every Catalogue Component yields controls, a default instance, renderable markup, and exportable TSX must continue to auto-enrol future Components. Add structural guards so future sibling/shared vocabulary locations cannot silently degrade select/object controls, and so new required function props cannot bypass the export contract. Do not replace closed-set or exact assertions with weaker substring checks just to accommodate the current inventory.
10. **Document the finished contract and leave a preview.** Update `map/60-catalogue/interface-builder.md` from the real implementation, including trust posture, limits, persistence/recovery, export wiring, keyboard model, adaptive panes, and browser proof. Remove the root-drop TODO when its class is cured; only remove the shared-module extraction TODO if this work actually cures it. ## Constraints

- The builder remains under `catalogue/` and outside the JSR publish set. React stays out of the neutral root and CLI graphs; do not turn the document model or policy into a published API without an explicit ADR and owner decision.
- Source documents are inert data. Never use `dangerouslySetInnerHTML`, `eval`, `Function`, executable string handlers, caller-authored JSX, or unsanitised HTML as a shortcut. Preserve useful safe props through a principled policy rather than banning all additional props.
- Keep one authority for document acceptance and one renderer shared by canvas/tests. Preview/export divergence is a defect.
- Reuse the project's browser, viewport, axe, focus-token, generated-registry, and design-system feedback authorities. Do not hand-edit `src/generated/` or `catalogue/generated/`.
- Cure each confirmed class with a practical regression guard. Commit atomically. Record any surprising or hard-to-reverse security, callback-export, or adaptive-pane decision in an ADR.
- After the last implementation edit, run `discern_prepare`, inspect and commit every resulting source/generated change, then run `discern_done` on clean HEAD. Never loosen a standard to pass.

## Out of scope

- Accounts, cloud or server persistence, collaboration, publishing/deploying composed pages, multi-user conflict resolution, analytics, or telemetry.
- Arbitrary JSX/HTML/CSS/JavaScript editing, third-party Component plug-ins, or running consumer code in the builder.
- A new public design-system Component solely for builder chrome; reuse current Components or Catalogue-local markup.
- Reworking unrelated Catalogue or CLI surfaces, package release/version work, or fixing the shared-module-outside-`src/components` TODO unless a real current prop requires it.
- Requiring touch drag gestures. A complete click/keyboard pane workflow is the production baseline; pointer drag is an enhancement.
- Splitting this task into independently landed sibling branches.

## Definition of done

- **Measurable safety:** hostile raw-HTML/React-escape payloads, unsafe additional-prop shapes/keys, oversized/deep documents, malformed JSON, storage failures, and file-read failures are rejected or contained by one tested policy without changing the active document or executing source content.
- **Measurable export:** adversarial names and documents containing every Component class produce deterministic source that is actually formatted/parsed and type-checks; required callback wiring is explicit; preview, saved JSON, TSX, and runtime selection agree.
- **Measurable experience:** axe is clean in both themes; keyboard traversal, focus visibility, announcements, non-drag placement/edit/reorder, root insertion geometry, and adaptive Palette/Canvas/Inspector access pass in the real browser at all named viewports with no page-level horizontal overflow.
- **Project bar:** fast tests and browser conformance cover the whole defect classes; map/TODO/generated surfaces are current; the exact preview and review screenshots are reported; the clean committed tree passes `discern_done` with standards held.
- **Semantic:** a person can safely open an untrusted composition, author and reorganise it without a mouse or wide monitor, recover from local browser/file failures, and paste the exported source into a strict consumer knowing it is complete, inert, and faithful to the preview.
