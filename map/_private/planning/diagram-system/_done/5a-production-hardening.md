## Background

Feature waves tend to prove the happy path of the thing they just built. This wave assumes the surface still fails in combinations: a dark adaptive SVG embedded as `<img>`; a system font wider than Inter; a diagram repeated twice in one page; a description fallback inside a resized terminal viewport; a hostile label at an XML/control boundary; a generated kind missing from a publication graph; or an attractive frame that silently loses a relationship.

The objective is not to add another feature. It is to make the existing contract release-worthy and to leave permanent guards for every class of defect found. Visual quality matters, but correctness comes first: a diagram that cannot remain legible or complete within its supported budget must refuse or fall back, not squeeze, clip, or conceal facts.

## Deliverables

Work in small behavior-preserving audit/fix commits. When an audit finds a defect, cure the class at its owning authority and add the practical regression guard before moving on.

1. **Build one canonical release corpus.** Create a package-owned, product-neutral fixture set that covers every kind's minimal, representative, branch/return or grouping behavior, long labels across representative scripts and annotations, maximum supported density, every semantic tone/line style, all CLI stances, Markdown registered/unregistered forms, and deliberate invalid/hostile cases. Include one over-budget case per kind whose stable error identifies the exceeded dimension and teaches the documented decomposition. Derive SVG, React, CLI, descriptions, and Markdown projections from these specs; do not maintain separate hand-copied facts. Add an inventory guard so every generated kind contributes the required corpus postures automatically.
2. **Audit geometry mathematically across the full library.** Assert finite canonical number formatting, positive/tight view boxes, minimum padding, shape containment, text baselines/bounds and clear space, connector endpoint attachment at the actual boundary without fill occlusion, connector bodies crossing no unrelated node or label, arrowhead clearance/containment, group containment, lane/rank order, tick/date alignment, and every non-overlap/crossing promise each kind documents. Exercise the shared scene-conformance authority directly and run the invariants for both directions and the supported density boundary. Where a crossing or overlap is sometimes unavoidable, encode, document, and test the exact accepted condition rather than weakening the assertion globally.
3. **Audit typography in a real browser without making the browser authoritative.** Reuse existing Playwright/Chromium infrastructure—no new browser dependency—to render every kind with the bundled Inter/JetBrains assets available, with those optional assets unavailable so the system fallback wins, at light/dark themes, narrow/wide containers, normal and increased browser zoom/text settings. Inspect and assert no clipped labels, overflow outside the SVG/view box, unreadable collision, layout shift that hides content, or page-level horizontal scrolling. Audit the committed horizontal metric approximation against representative Latin, wide-script, combining, punctuation, and mono-annotation strings, and bind bundled-font claims to the inspected asset digests. Any calibration generator remains an explicit on-demand tool whose output is reviewed; routine codegen and runtime layout never launch a browser or capture host-dependent measurements. Prefer fixing conservative measurement/padding or honest validation limits over adding a font parser or converting text to paths.
4. **Audit the visual system, not only snapshots.** Review the real Catalogue output for consistent spacing rhythm, node radii, line weights, connector treatment, accent restraint, type hierarchy, density, and semantic role across all kinds. Assert that node/container roles resolve through complete surface/border/primary-ink/annotation-ink bundles and connector roles through complete stroke/marker/line-treatment bundles in light, dark, adaptive, and React modes, with their non-colour cues intact; no projection may assemble an accidental pairing or colour a sequence decoratively. Ensure generic outputs look like one system rather than five local renderers. Move repeated geometry/style constants to their existing authority; do not create a second global abstraction if only one kind uses a value. Avoid brittle pixel-golden images where structural geometry and rendered browser assertions guard the class more reliably, but retain reviewable deterministic artifacts.
5. **Prove accessible equivalence.** For every corpus spec, compare a canonical semantic-fact inventory against `describeDiagram`, standalone SVG title/description and text nodes, React accessible name/description, CLI description, any enhanced CLI output, raw Markdown alt/title, and registered Markdown projection. Run Axe through existing browser tooling on inline Diagram and Markdown compositions. Test forced-colours/high-contrast posture and confirm tone/line meaning also appears as text, shape, dash, label, or ordering. Repeated diagrams must not create duplicate-ID relationships. Do not add a decorative mode: informative title and summary remain mandatory.
6. **Stress terminal degradation and reader geometry.** Exercise truecolour, ANSI 256, ANSI 16, no-colour, Unicode, and ASCII at widths around every enhanced projector's viability threshold. Assert exact frames, stripped width, closed SGR/OSC sequences, stable fact inventory, and deterministic fallback. In the interactive Markdown browser, resize across those thresholds while scrolled above, within, and below a diagram; confirm anchors, link regions, pane focus, resume state, complete-frame height, alternate-screen lifecycle, and content reachability remain correct. An enhanced renderer must return a typed decline before producing an invalid frame.
7. **Fuzz validation and serialization deterministically.** Add seeded/generated hostile specs within and around public limits: duplicate/confusable IDs, dangling relationships, invalid dates, cycles in forbidden positions, extreme counts/depths, empty/long/control/bidi/markup-bearing labels, XML delimiters, surrogate/Unicode edge cases, NaN/infinity smuggled through untyped runtime values, mutated objects, and prototype-shaped data. The complete boundary must either return safe deterministic output or one documented deterministic error, never partial SVG/terminal bytes, a hang, unbounded recursion, executable markup, or an ambient exception. Budget failures must retain stable machine-readable identity and a concise actionable remedy; internal conformance failures must not masquerade as author mistakes. Keep the corpus bounded and reproducible in the normal test suite.
8. **Prove standalone asset portability honestly.** Load explicit light, explicit dark, and adaptive output directly and through an `<img>` in the test browser; verify meaningful fallback when adaptive media behavior is unavailable. Assert assets contain no external URLs, data-font payloads, scripts, event handlers, `foreignObject`, unnamespaced globals, random IDs, or page-token assumptions. Exercise any SVG convenience used by connectors or markers—such as `context-stroke`—through every supported asset path; keep it only with direct evidence, otherwise emit explicit deterministic per-role values. Confirm common Markdown renderers can size the assets from intrinsic dimensions/viewBox and that ordinary alt text remains meaningful even when SVG internals are not exposed to accessibility APIs.
9. **Lock the dependency and module boundaries.** Extend release/import-graph tests so `./diagram` resolves only package/platform modules, no React, and no external runtime/build diagram package; `./cli` remains React-free; React remains behind `./react`; and Markdown's already-recorded parser graph is not accidentally pulled into a consumer that imports only `./diagram`. Record that waves 1–5 introduce no dependency requiring a new compatibility decision for the FSL-licensed consumer; do not offer legal certainty beyond inspected license evidence.
10. **Exercise the publish-shaped consumer end to end.** Extend the existing temporary published-artifact test with a neutral consumer that imports a typed spec and `renderDiagramSvg`, writes the result using consumer-owned I/O, and verifies deterministic bytes; a React consumer that renders Diagram/DataFigure/Markdown; and a CLI/interactive consumer that supplies the same spec as a Markdown resource. The fixture must use only declared public exports, not source paths, examples, generated internals, or undeclared permissions. It should prove that standard Markdown still works without resources and upgrades on both package surfaces when resources are supplied.

## Constraints

- This is a hardening wave, not an API expansion wave. Add a public option or scene primitive only when a demonstrated release blocker cannot be cured within the existing contract; record any consequential change in an ADR and the changelog.
- Preserve the dependency-free Diagram baseline and current authoring model. No library, binary, WASM, font parser/subsetter, vendored algorithm, remote service, or custom Markdown syntax.
- Fix root authorities. Do not patch individual examples, loosen geometry/exact-frame assertions, hand-edit generated output, suppress accessibility findings, or hide overflow with CSS clipping.
- Visual review complements invariant tests; it does not replace them. Terminal beauty never outranks complete semantic fallback.
- Existing Markdown parser dependencies are not “new Diagram dependencies.” Keep their containment and recorded license policy intact and make the graph distinction observable.
- No version bump, release, tag, publication, or sibling-repository edit. Public changes remain under **Unreleased**.
- After the final edit, run `discern_prepare`, commit the resulting clean tree, then run `discern_done` once. Keep the Catalogue server alive after the gate.

## Out of scope

- New diagram kinds, a DSL/editor, custom-kind API, arbitrary scene authoring, animation/interaction, terminal image protocols, or consumer-specific content.
- Adding or replacing a layout/font/SVG dependency; 6A evaluates whether measured limitations justify a separate later build.
- Shipping a package release or adopting it in `/Users/jack/Sites/discern`.
- Claiming legal advice about FSL compatibility; the task records authoritative license facts and stops on uncertainty.

- **Measurable:** one generated release corpus covers every kind/posture and actionable over-budget refusal; shared scene conformance plus mathematical and real-browser geometry/typography checks pass; digest-bound committed metric data remains independent of routine codegen; paired role styles, portable markers, accessible fact equivalence, Axe/forced-colour, terminal threshold/fallback, interactive resize/scroll, deterministic fuzz/safety, standalone `<img>`, import/dependency/license, publish-shaped consumer, API documentation, and complete gate tests pass; zero new Diagram dependencies is demonstrated; maps/docs/Unreleased changelog are current; `discern_done` is green on clean committed HEAD.
- **Semantic:** the complete surface behaves like a mature design-system layer rather than a collection of demos: authors get consistently legible assets, readers receive equivalent meaning on web/raw-Markdown/terminal surfaces, hostile or over-complex input fails honestly, and consumers can adopt the published package without internal imports or hidden runtime machinery.
