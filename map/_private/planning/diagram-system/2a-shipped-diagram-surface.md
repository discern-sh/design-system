## Background

Wave 1 owns semantic input, validation, layout, a projection-neutral scene, and a complete textual description. This wave proves the risky proposition: one spec can become a high-quality SVG, live React UI, and meaningful terminal output without separate models or a third-party engine.

The static SVG is the primary artifact for ordinary Markdown. It must remain useful when opened directly or rendered as `<img>`, where page CSS variables and fonts cannot be assumed to cascade. The React Component is a separate scene projection that uses the live design-system token context; it must not inject the serializer's XML string. Terminal is a first-class semantic surface but not a pixel imitation. An enhanced kind renderer is allowed only when it carries the same facts within the current width/capabilities; otherwise description is the correct output.

## Public contract to deliver

- A dedicated framework-neutral `@discern-sh/design-system/diagram` entrypoint exports the authored spec types/kinds, canonical `diagramAltText` and structural `describeDiagram` surfaces, supported-kind Metadata as appropriate, and `renderDiagramSvg` plus documented option/result types. It imports neither React nor terminal modules.
- `@discern-sh/design-system/react` exports one `Diagram` Component accepting a `DiagramSpec`. It composes naturally as `visual={<Diagram spec={spec} />}` inside `DataFigure`; it does not duplicate figure title/caption/source/legend semantics.
- `@discern-sh/design-system/cli` exports the generated `renderDiagramCli` Component renderer and its props. Its default `auto` behavior tries a kind's enhanced projector and otherwise renders the universal description. Callers may request the stable description-only mode.
- The first enhanced projector belongs to the `flow` kind and is enrolled through a generated CLI-kind registry that is imported only from the CLI graph. The neutral `./diagram` graph sees the stance Metadata but never resolves the enhanced module.

## Constraints

- One spec, validation boundary, layout, scene, accessibility authority, and kind registry feed every edition. Serializer, React, and terminal code may differ only at projection/presentation.
- Do not expose raw SVG, HTML, JSX label slots, arbitrary CSS, absolute coordinates, custom drawing callbacks, or third-party ASTs as convenience props.
- Do not embed or subset fonts, convert text to paths, read the filesystem, discover themes, call a browser/DOM for layout, or add dependencies. Standalone output is deterministic from explicit spec/options alone.
- External SVG does not inherit page theme tokens. Explicit theme modes must be truthful and portable; React is the live-token edition.
- Enhanced terminal rendering is opportunistic. The universal description is the correctness floor, not an embarrassing fallback to bypass.
- Preserve existing Component anatomy and generated-surface rules. Public symbols need documentation; CSS is namespaced/rooted/token-driven; `CHANGELOG.md` records the addition; no version bump or publication.
- After the final edit, run `discern_prepare`, commit the resulting clean tree, then run `discern_done` once. Keep the Catalogue server alive after the gate.

## Out of scope

- Markdown parser/model changes, interactive Markdown browser changes, fenced diagram syntax, source-file loading, URL fetching, or generated documentation assets in the Discern consumer.
- Diagram kinds other than `flow`, custom-kind plugins, an editor, drag/zoom/pan, animation, links, icons, rich text, images, gradients, or arbitrary ports.
- Perfect terminal resemblance to SVG, terminal pixel protocols, or terminal interaction.
- Font-metric/subsetting dependencies, Dagre/ELK/Graphviz/Mermaid/D2 integration, a release, version bump, or sibling-repository adoption.
