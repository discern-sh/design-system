## Background

Documentation charts have the same three forms diagrams do. Raw Markdown must stay portable, so a chart appears there as standard `![alt](path.svg)` syntax referencing an asset the consumer generated with `renderChartSvg` at its own build. Browser documentation benefits from a live token-themed `Chart`. `discern docs` and the interactive Markdown browser need `renderChartCli`, where an SVG file cannot communicate its values. ADR-0029 already solved this shape for diagrams: an explicit caller-supplied source→spec resource promotes an isolated standard image, the spec stays the accessibility authority, and no renderer reads files.

Charts must ride that same mechanism, not a copy of it. The landed resolver — `validateMarkdownDiagramResources` plus the isolated-image promotion in `markdown.model.ts` — carries matching, URL normalization through the already family-neutral `canonicalSafeUrlReference` (`src/url-reference.ts`), duplicate-source rejection, and alt/title equality. Duplicating that logic for charts would create a second promotion authority whose behaviour drifts from the first, so this wave first records and builds the resource **family**: one shared neutral resolver parameterized per family, with family-specific typing wrapping it. Diagram behaviour must not change at all — the existing `tests/markdown_diagram_test.tsx` suite stays green unmodified.

The alt contract makes this safe across data refreshes: `chartAltText(spec)` derives from title and summary **only, never from data values**, so regenerating an asset from updated data can never break Markdown alt equality unless the author edits the summary.

## Fixed integration contract

Use the smallest equivalent names that fit the live API, but preserve these semantics:

```ts
interface MarkdownChartResource {
  readonly source: string;
  readonly spec: ChartSpec;
}
```

- One shared neutral resolver serves both families. Matching, URL normalization, duplicate rejection, and alt/title equality live exactly once; per-family parameters supply the spec validator, canonical alt derivation, and block kind. A normalized source admitted by both the diagram and the chart collection is a duplicate and rejects deterministically — one image promotes to at most one block.
- React `MarkdownProps`, `MarkdownCliProps`, and each `MarkdownBrowserDocument` receive an optional readonly chart resource collection beside the existing `diagrams`. There is no global registry, resolver callback, filesystem root, fetch hook, or environment discovery.
- Promotion requires the established isolated-image shape: a paragraph or list item whose sole visible content is one image with a matching admitted source. Unregistered, inline, and mixed-phrasing images keep their current behaviour exactly.
- The image alt must equal `chartAltText(spec)` after the established text normalization; an image title, if present, must equal the spec summary. A mismatch rejects the whole Markdown render before partial output.
- A matching block stores the validated `ChartSpec` and normalized source as package-owned neutral data. React dispatches to `Chart`; CLI and the interactive browser dispatch to `renderChartCli` with the documented mode preference; neither reads the asset, parses SVG, nor repeats matching.
- The unused-resource policy stays what ADR-0029 recorded — valid unused entries are allowed for corpus-level reuse — and is identical for both families and all three callers.

## Constraints

- Standard Markdown remains standard: no chart fence, directive, MDX component, URL protocol, data-file ingestion, or parser plugin. The package performs no I/O — it never reads the referenced SVG, resolves a filesystem path, or fetches a URL.
- `ChartSpec` is the accessibility authority. `chartAltText` derives from title and summary only — never data values — and both projections consume one fully resolved neutral document; do not match resources separately inside `.tsx`, `.cli.ts`, or the interactive renderer, and do not weaken ADR-0019/0020's URL/control policies to make matching convenient.
- One resolver for both families. A second promotion path, a copied matching routine, or a chart-side reimplementation of duplicate/alt checks is a defect. Diagram behaviour must not change: bytes, tests, and public surface are all invariant, and `tests/markdown_diagram_test.tsx` stays green unmodified.
- `./chart`, `./cli`, and `./cli/interactive` remain React-free and deterministic. Zero new dependencies. No copied code from surveyed tools — independent implementation, with provenance recorded where a source materially shaped the result.
- Never hand-edit generated files: change sources and run codegen. Component styling stays token-driven and `discern`-namespaced. Preserve the seven binding rules in `map/00-orientation/design-principles.md`; override one only through an ADR.
- Public optional props are additive and documented; every public change lands in `CHANGELOG.md` under **Unreleased** in this wave. Never loosen a standard to pass.
- Work in focused atomic commits, one logical step each. After the final edit, run `discern_prepare`, commit the resulting clean tree, then run `discern_done` once on that committed HEAD. Keep the Catalogue server alive after the gate.
