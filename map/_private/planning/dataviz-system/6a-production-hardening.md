## Background

Feature waves prove the happy path of the thing they just built. This wave assumes the chart surface still fails in combinations: a denormal or `-0` value that survives validation and drifts a tick position; a `toFixed`-class double-rounding hiding inside one projection so SVG prints `0.61` where the CLI table prints `0.62`; a value at the `1e21` boundary where naive number-to-string switches to exponential notation mid-axis; a tick domain so tiny that accumulated floating-point error separates two byte-identical runs; an eighth-block or shade glyph that measures two cells under an ambiguous-width terminal and shears every frame after it; a faithful frame that quietly presents quantized geometry as exact; a stacked segment rounded away to nothing; a forced-colours browser where a series is suddenly distinguishable by nothing at all.

The diagram programme's wave 5 built guard classes for exactly this moment — corpus enrolment sweeps, codegen guards, conformance guards, determinism and neutrality proofs, SVG/browser/CLI/fuzz matrices, Markdown drift rejection, and release graphs. Charts must end this wave with guard coverage equal to that bar, plus the numeric-specific classes only charts have: float drift, formatter identity, quantization edges, and glyph geometry. The objective is not to add another feature. It is to make the existing contract release-worthy: a chart that cannot remain truthful within its supported envelope must refuse or fall back with a typed reason, never squeeze, crop, resample, or conceal a fact. The programme README's determinism, honesty, accessibility, and series-colour contracts bind every deliverable below.

## Deliverables

Work in small behavior-preserving audit/fix commits. When an audit finds a defect, cure the class at its owning authority — never a call site — and add the practical regression guard before moving on.

1. **Fuzz the numeric boundary deterministically.** Join the existing fixed-seed fuzz pattern — model `tests/diagram/fuzz_test.tsx`, whose seeded hostile specs must yield safe deterministic output or typed all-or-nothing failure at every projection — with numeric-hostile generation: denormals down to `Number.MIN_VALUE`, negative zero, values at and across the `1e21` formatting boundary, `NaN` and both infinities on every rejection path (smuggled through untyped runtime values as well as typed ones), pathological tick domains (spans tiny enough to stress float accumulation, spans of many orders of magnitude, reversed and zero-width domains, domains straddling zero), extreme series and point counts around every budget, explicit nulls in hostile positions, mutated and prototype-shaped spec objects, and hostile labels carrying control, bidi, markup, and XML-delimiter content. Every case must produce byte-deterministic safe output or one documented typed failure across SVG, React, CLI, and Markdown — never partial bytes, a hang, unbounded recursion, or an ambient exception. Probe the formatter authority directly for double-rounding defects of the `(0.615).toFixed(2) === "0.61"` class and for accumulated `min + i * step` drift of the `0.30000000000000004` class; the contract is scaled-decimal integer tick arithmetic with half-away-from-zero rounding, so any float-shaped construction the fuzzer exposes is a defect at the authority, not a tolerance to encode.
2. **Prove determinism across runs and formatter identity across surfaces.** Assert equal spec and options produce byte-equal SVG documents, chart scenes, descriptions, and CLI frames across repeated runs in fresh processes — model the diagram byte-stability tests in `tests/diagram/svg_test.ts` ("standalone SVG is deterministic, finite, and canonically ordered") and `tests/diagram/cli_test.ts` ("byte-stable and bounded across widths and capabilities"). Then prove the single-formatter contract instead of assuming it: for every corpus case, harvest the numerals actually printed in the SVG text nodes, the description's data table, and the CLI frames, and assert the same value renders the identical numeral string on every surface. A divergence means a second formatting path exists — the review loop's "second authority hidden inside a kind, projection, or the CLI" smell — and the cure is deleting the duplicate, never aligning two copies.
3. **Verify the scoped locale/Date guard and the glyph-geometry matrix.** Audit the release-test guard banning `Intl.NumberFormat`, `Intl.DateTimeFormat`, `toLocaleString`, `toFixed`, and `Date` construction from the chart graph and the numeric authorities: prove its coverage is derived mechanically from the module graph (so a kind folder added later cannot escape it) and that it spans every kind 5A added and every promoted shared numeric module, while leaving the scoped exemptions intact — `Intl.Segmenter` remains the landed grapheme authority in `src/cli/text.ts` and the interactive adapter legitimately reads the clock. Then build the glyph-geometry guard class for the new ramps: the horizontal and vertical eighth-block ramps, the shade ramp with its digit bins, and every per-series marker and fill glyph sit in East-Asian-Ambiguous ranges (`src/unicode/east-asian-width.ts` classifies them; commit `8f6cacd` fixed this exact defect class for existing glyphs; the wide-A ledger item in `discern/TODO.md` records the open exposure). Assert every ramp glyph measures one cell through the text authority, every mandatory ASCII pairing measures identically to its Unicode partner, and complete frames stay column-aligned across unicode and ascii charsets and the supported width policies at every capability — model the pairing discipline of `src/cli/triangles.ts` and the matrix style of `tests/diagram/cli_test.ts`.
4. **Run the full browser matrix over every chart corpus case.** Model `tests/diagram/browser_test.tsx` and reuse `scripts/browser.ts` and `scripts/browser-conformance-support.ts` — no new browser dependency. For every corpus case of every kind: bundled fonts present and absent so the system fallback wins, light and dark themes, narrow and wide containers, increased zoom, and an Axe-clean result. In forced-colours mode, prove the paired non-colour cues carry the meaning: every series remains distinguishable by its marker glyph, line treatment, or ordering when series colour is gone — a series distinguishable only by colour anywhere in the matrix is a release blocker, per the accessibility contract. Load explicit light, explicit dark, and adaptive standalone SVG both inline and through `<img>`, asserting intrinsic sizing, no clipped labels, no overflow outside the view box, and no external or active content.
5. **Sweep the CLI capability and width transition matrix for every kind and stance.** Model the generated matrix in `tests/diagram/cli_test.ts` ("preserves facts across every stance and viability boundary"): every kind, every declared stance, truecolour through ansi256, ansi16, and no-colour, unicode and ascii, at widths stepping across every declared envelope threshold. Prove tier honesty mechanically, not by inspection: exact kinds (`bar`, `distribution`, `slope`) print every authored value in every accepted frame; faithful kinds (`line`, `heatmap`, `scatter`) print their extremes exactly and declare their resolution in the frame (bin edges in the legend, corner extremes) — a faithful frame exceeding its declared tier is a defect, as is quantization presented as exact. Every typed decline routes to the full table fallback with the exceeded dimension and a practical remedy; nothing crops, abbreviates, or resamples at any transition. Test the quantization invariants per kind per charset: a nonzero value renders at least one eighth-block unit at Unicode and one full cell at ASCII; a sub-resolution stacked segment declines rather than rounding away; explicit nulls render as declared gaps visibly distinct from zero; scatter collisions render as counts and decline past nine; flat-series and rounding-tie rules match their pinned spec.

## Constraints

- This is a hardening wave, not an API expansion wave. Add a public option only when a demonstrated release blocker cannot be cured within the existing contract; record any consequential change in an ADR and the changelog.
- Hardening fixes land at the owning authority — the shared formatter, scale, glyph, scene, or description module — never as per-kind or per-projection patches. Tests are added, never weakened: no loosened assertion, no widened tolerance, no snapshot refreshed to hide a real change.
- Zero new dependencies, runtime or build. No copied code from surveyed tools — techniques are implemented independently, with provenance recorded where a source materially shaped the result.
- Never hand-edit generated files; change component metadata, kind sources, or codegen and regenerate. Preserve the seven design principles in `map/00-orientation/design-principles.md`; overriding one requires an ADR.
- Read-only audit fan-out is permitted, but every edit lands through this one worktree in focused, atomic commits — one logical step each.
- Never loosen a standard to pass the gate. After the final edit run `discern_prepare`, commit the resulting clean tree, then run `discern_done` once on the committed HEAD. Keep the Catalogue server alive after the gate.
