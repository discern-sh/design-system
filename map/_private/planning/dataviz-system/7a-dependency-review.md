## Background

The chart implementation deliberately starts and ships without a runtime or build dependency — a fixed programme contract, not an accident. That posture is even stronger here than in the diagram programme whose 6A review this wave mirrors: chart layout is deterministic arithmetic — scales, ticks, stacking, binning, quantization — not NP-hard graph layout, so the strongest diagram-side candidates (Dagre, ELK, Graphviz — graph solvers) are irrelevant to charts and must not be re-screened here. The chart-shaped temptations are the d3 micro-modules (`d3-scale`, `d3-shape`, `d3-array`), tick/number-format libraries, and statistics helpers. A dependency earns its cost only if the real release corpus and 6A hardening evidence expose a limitation that cannot be cured cleanly in the owned numeric authorities and the candidate materially improves that limitation while retaining deterministic synchronous Deno execution, package-owned specs/scenes/projections, terminal honesty, safe SVG, and acceptable distribution terms.

Two landed contracts raise the bar further, and the assessment must weigh them explicitly. First, the tick and formatting authorities run in scaled-decimal integer space (Heckbert 1-2-5 steps, half-away-from-zero rounding) and their exact output is pinned by byte-exact snapshots and the public closed format vocabulary — a candidate replacing them must either reproduce those bytes exactly or force a reviewed public-output change. Second, the release-test locale guard bans `Intl.NumberFormat`/`Intl.DateTimeFormat`, `toLocaleString`, `toFixed`, and `Date` construction from the chart graph, so any candidate leaning on those platform primitives fails hermeticity before benchmarking; the timeline kind's proleptic-Gregorian date parsing without `Date`, locale, timezone, or clock access (`map/25-diagrams/README.md:27`) is the standing model for what "deterministic" means here.

The Discern consumer is distributed under `FSL-1.1-ALv2`; this package is Apache-2.0. A package name, SPDX label, README claim, or secondary-source compatibility table is insufficient. Inspect the exact selected version's distributed licence files and complete resolved graph. Where licence interaction is genuinely uncertain, identify the uncertainty for owner/legal review and treat it as a blocker to adoption — not as permission.

External versions, maintenance, licences, and runtime behavior are time-sensitive. Browse current primary sources and record source URLs plus access dates. For technical claims use official repositories, release notes, package registries, documentation, and the candidate's own licence files; do not rely on this brief or the planning research as current authority.

This wave is independent of the diagram programme's own dependency review (`map/_private/planning/diagram-system/6a-dependency-review.md`, unstarted at authoring time). Neither review assumes the other's outcome or waits for it; record the diagram review's disposition at dispatch time in the assessment, and note that if either review ever lands changes touching the shared internal modules, normal trunk-merge discipline (`discern_update`) covers it. This wave scopes to chart-side problems only.

## Candidate frame

Start broad enough to falsify the shortlist, then spend benchmark effort only on candidates that survive the hard gates:

- the current bespoke scale/tick/format/glyph/quantization authorities (control);
- the current d3 micro-modules `d3-scale`, `d3-array`, and `d3-shape`, evaluated individually — never as a bundle;
- current maintained tick-selection or deterministic number-format libraries;
- current statistics helpers, only if 6A proved a defect in the owned binning or summary arithmetic;
- no-dependency owned algorithm improvements or precomputed tables as controls.

Full charting frameworks, browser/DOM/canvas renderers, grammar-of-graphics engines, external services, and Intl-or-Date-based formatters may be screened with current evidence but need not be benchmarked when they require a DOM/browser/process/network, generate presentation outside the package scene, cannot satisfy deterministic hermetic locale-free Deno execution, or have an incompatible/uncertain distribution story. Record the reason rather than repeating a stale reputation. Graph-layout engines are out of frame entirely — they solve a problem charts do not have.

## Hard gates

A candidate cannot receive an adoption recommendation unless the exact proposed integration can satisfy all of these:

1. Works in the supported Deno/JSR environment with explicit inputs and no network, filesystem, browser DOM, subprocess, clock, locale, or environment read at render time.
2. Equal input/version/options produce byte-equivalent results or a canonicalizable result across repeated fresh processes on supported platforms.
3. Remains behind package-owned `ChartSpec`, validation, `ChartScene`, SVG, React, description, and CLI contracts; no third-party AST/scale/shape object becomes public API.
4. Preserves synchronous public APIs unless a separately approved breaking ADR justifies otherwise. An async-only engine is not a transparent implementation detail.
5. Can be isolated to the smallest export/build graph so neutral consumers do not pay unrelated DOM, React, parser, binary, WASM, or data payloads.
6. The exact direct/transitive licence graph and bundled assets permit the intended package publication and use from the FSL-licensed Discern consumer, with all notice/source obligations identified. Uncertainty fails this gate pending qualified review.
7. Improves a measured release-corpus problem enough to justify download/build size, cold-start/compile cost, maintenance, upgrade surface, security exposure, and loss of owned control.

Quantify the affected corpus and severity. 2. **Verify current candidate identity and maintenance.** For each surviving candidate, record exact package/repository, current stable version, release date/cadence, runtime format, TypeScript support, Deno/JSR resolution behavior, browser/Node assumptions, API sync/async shape, declared and shipped licences, bundled assets, and direct/transitive graph. Link primary sources and retain reproducible commands or small output excerpts in the report without committing package caches.
3. **Audit licensing at the distributed artifact.** Download or inspect the exact registry tarball/release artifact in scratch space. Enumerate every runtime/build transitive package and bundled asset with its licence file, SPDX expression, copyright/notice obligations, source/reciprocity conditions, and any dual-licence choice. Assess compatibility separately for publishing this Apache-2.0 package and consuming it from `FSL-1.1-ALv2`. Mark "clear from authoritative text," "owner notice/action required," or "qualified legal review required"; never silently choose a dual-licence branch or infer compatibility from popularity.
4. **Run hermetic Deno probes.** From scratch config, test import with no ambient permissions, typecheck under this repository's strict flags, cold/warm execution, deterministic repeated output across fresh processes, locale independence (vary the host locale and confirm identical bytes), failure behavior, graph size, and whether the candidate touches globals/DOM/process/filesystem/network/`Intl`/`Date`. Test the exact integration layer proposed — not only the package's hello world. Record commands, Deno version, host facts that matter, and results.
5. **Benchmark the real release corpus.** Feed candidate adapters the same specs and constraints as the owned system without changing public APIs. Compare objective output quality (tick placement and count on the corpus domains, label precision, path geometry, bin edges, extremes), byte determinism against the pinned snapshots, output/graph size, initialization and representative render cost, and the amount of adapter/sanitizer/canonicalizer code required to hold the honesty rules (zero baselines, declared bins, no resampling, nonzero-never-empty). 6. **Evaluate statistics and format helpers only against a proven numeric defect.** If 6A found no tick, formatting, binning, or summary defect in the supported corpus, close those branches with that evidence rather than benchmarking them for completeness. Otherwise compare the owned fix, a precomputed-table approach, and the library, on the same total-cost terms as every other candidate.
7. **Score total cost, not feature count.** Produce a compact decision matrix covering problem solved, output improvement, deterministic behavior, sync/Deno fit, package graph and bytes, cold-start/build cost, security/maintenance surface, scene/API containment, terminal impact, accessibility impact, exact licence status, and removal/replacement cost. Give the bespoke baseline a row. Distinguish a candidate useful only for a future unsupported kind from one that improves today's supported contract.
8. **Write the dated assessment.** Add `map/_private/notes/chart-dependency-assessment.md` with executive recommendation, measured baseline problem, methods/reproduction commands, source-linked facts with access dates, licence matrix, benchmark results, uncertainties, a clear disposition for each candidate, and the recorded relationship to the diagram programme's own dependency review at dispatch time. 9. **Recommend exactly one next posture.** Choose among: retain the dependency-free implementation; run one narrower experiment because evidence is inconclusive; or propose one dependency-backed follow-up for a named measured limitation. If proposing adoption, write a **proposed**, not accepted, ADR describing the exact version boundary, isolation, licence/notice prerequisites, fallback/removal plan, API impact, and gates. Do not implement it or pre-empt owner/legal approval. If recommending no dependency, explain what future threshold would justify reopening the question; no ADR is required merely to memorialise that nothing changed.
10. **Leave a future build properly bounded.** If and only if adoption is recommended, include in the assessment a self-contained outline for a later implementation brief: exact owned module seam, tests/benchmarks that must improve, dependency/notice changes, fallback path, and public API non-goals.
