# Chart kind taxonomy evidence

This note records the read-only corpus check behind the fixed initial library (README contract: `bar` with grouped and proportion variants, `line`, `distribution`, `heatmap`, `scatter`, `slope`, and sparkline as a display Component, not a kind). Diagram wave 4A excluded charts explicitly (`map/_private/planning/diagram-system/_done/4a-diagram-kind-library.md`), so every case below is chart-shaped, not diagram-shaped. Source material lives in the sibling discern repository — its `project/map/`, `site/`, and engine paths are cited relative to that checkout; `src/components/...` paths are this package. Package examples stay generic and copy none of the sibling's prose or data.

No proposed kind is without a real case, so the contract's drop-by-evaporation clause fires for none. Scatter sits closest to the line and is flagged above; every other kind has two or more independent cases.

The corpus also holds quantitative material the proposed set correctly refuses or defers:

- **Boolean support and feature matrices** — the vendor capability grids in `project/map/_internal/cross-agent-behaviour-reference.md` and `project/map/_internal/agent-integration-coverage.md`, and the package's own ComparisonTable — are categorical, not magnitudes. They stay Table and ComparisonTable; `heatmap` must not absorb them.
- **Dated span plans** — the phase tables ("+30d", "+90–180d") in `project/map/_private/maintainer/discern-monetization-strategy.md` — are the diagram `timeline` kind's job, not a chart.
- **The task funnel** (starts → first green → accept, `project/map/20-quality-gate/patterns.md`) reads as an ordered `bar`; no dedicated funnel kind is justified.
- **Interval values** — the revenue bands ("$10–25k per engagement") in the monetization strategy — would need a non-zero-anchored length encoding that the honesty rules forbid for `bar`. A table serves them; refused for v1.
- **Signed add/remove netting** — Diffstat and practice stats' "changes that removed more than they added" — is the only waterfall-shaped material in the corpus, and it is thin. This endorses the README's existing `waterfall` deferral.
- **Marketing stat claims** — MetricsBand's "42% less rework" pattern (`src/components/marketing/metrics-band/metrics-band.examples.tsx`) — remain stat tiles, optionally paired with the sparkline Component; they are not chart specs.

The six kinds plus the sparkline Component therefore stand as proposed, with scatter held on notice. A case that needs dual axes, renderer-side binning, free coordinates, or an undated span is evidence that Chart is the wrong surface, not that the library needs another kind.
