# Dataviz system programme

Briefs for making charts and data visualisation a first-class, package-owned surface in `@discern-sh/design-system`: one typed quantitative `ChartSpec`; deterministic scales, ticks, and number formatting; tasteful token-driven SVG for React and standalone Markdown assets; and a first-class terminal projection whose lossless fallback is a real data table.

The programme follows the completed diagram-system programme (`map/_private/planning/diagram-system/`) and reuses its architecture wholesale: typed spec → validate/layout → closed scene → independent projections, generated kind enrolment, budgeted refusals, description-first accessibility, and byte-deterministic output. Charts are a sibling kind family, not new diagram kinds: wave 4A of that programme explicitly excluded charts, and the landed `DiagramScene` grammar (mandatory arrowheads, three middle-anchored text placements, a closed semantic paint set, overlap/crossing conformance proofs) is structurally wrong for marks, axes, and gridlines. The terminal research verdict is equally settled: charts build on the annotated-glyph camp — label plus eighth-block-scaled bar plus printed value — because it preserves numeric truth at every width, colour depth, and charset; braille canvases are refused permanently.

This is a package programme. Waves 0–6 make the chart surface complete and consumer-shaped but do not edit the sibling Discern product, publish a release, add a charting CLI, or create a general plotting language. The supporting research dossiers and critiques that shaped these briefs are recorded in the session that authored them; the binding conclusions all live in this README, the taxonomy evidence note, and the briefs.

## Implementation consequences

The following sharpen how the fixed contracts are enforced; they do not add a public surface or change the architecture above:

- Scene element granularity is decided once in the chart-boundary ADR: aggregate elements per series for path-shaped kinds (`line`, `scatter`), element-per-mark for countable kinds (`bar`, `distribution`) — conformance cost, id schemes, and description length all hinge on it.
- Chart budgets follow the diagram philosophy — measurable dimensions, named remedies — with chart-appropriate remedy vocabulary (reduce series, aggregate categories, split the figure, use a log scale once log exists). Initial numbers are proposed in each kind's brief and reviewed with that wave; the magnitude-span budget whose remedy names log ships together with the log scale in wave 5A, not before.
- Kind Metadata declares the CLI stance and honesty tier together; generated author guidance derives from both. An enhanced frame that exceeds its declared tier is a review defect, not a feature.
- The new glyph authorities (horizontal and vertical eighth-block ramps, shade ramp with digit bins, per-series marker and fill tables) carry mandatory ASCII pairings and their own glyph-geometry guard class — these ramps multiply the repository's proven Unicode cell-geometry defect class.
- One description authority feeds SVG `<desc>`, docs long-description, and the terminal fallback — the same facts through one authority, formatted per surface by the existing Theme, text, layout, and table machinery.
- `DataFigure` framing stays optional, matching the diagram posture; the chart surface exports derived legend data rather than auto-injecting a legend.
- Deferred by decision and recorded in `discern/TODO.md` when the relevant wave lands: a diverging palette, a `waterfall` kind, interactive chart behaviours (the behaviour-script standard's ceiling makes v1 strictly static), and inline sparklines in Markdown prose.

## Why the refactor wave exists, and why the public surface arrives in wave 3

Wave 1A touches no chart code: it generalizes `scripts/generate.ts` into a kind-family framework and promotes the family-neutral authorities (conformance geometry predicates, the conservative text-measurement layer, the canonical SVG document scaffold, the proleptic-Gregorian date parsing currently private to the timeline kind, snapshot/validation primitives, error bases, rounding and SVG number formatting, palette resolution, escaping, and the release-corpus framework) into shared internal modules with diagram-side re-exports. Its invariant is absolute: every diagram generated surface regenerates byte-identically and the entire diagram suite stays green. Isolating this wave keeps the landed subsystem's regression risk away from all new chart code.

Wave 2A then builds the chart foundation entirely internally — ADR, map page, numeric authorities, glyph authorities, palette spike and guards, `ChartScene`, and the `bar` kind — for the same reason diagram wave 1 stayed internal: publishing a Component in the foundation wave would either violate the fixed Component anatomy or make a temporary CLI exemption public history. Wave 3A lands the `./chart` entrypoint, the documented series tokens, the standalone SVG emitter, the React Component, and the rendered CLI Component together as one vertical slice, with its changelog entry.

## Downstream handoff after release

Discern adoption is intentionally not a brief in this folder. After wave 6A is reviewed and the owner releases, use `discern-delegate-work` in the Discern repository to create a consumer programme: pin the released version, author real typed chart specs beside their documentation authorities, generate committed SVG assets deterministically, supply source→spec resources to the web Markdown surface and every `MarkdownBrowserDocument`, prove web/raw/terminal equivalence, and run the consumer's licence, documentation, browser, and terminal gates. Re-read the live consumer before turning that outline into prompts.

## Landing authority

Every wave stops for owner review unless discern records a grant. After `discern_done` passes on the final committed tree, the agent runs `discern_accept`. A standing or per-worktree grant may land it; without one, the verb refuses without mutation and the agent reports the proof line and branch/worktree for review. Prose in a brief is never landing authority.

The planning package itself follows the same rule. It must land before `chart-1a` is dispatched, because each implementation wave moves its own committed brief into `_done/`.

## Review loop

When a wave reports green, review its branch diff against `main`, verify every deliverable and compatibility promise, rerun the gate against that worktree, inspect any SVG/CLI artifacts and Catalogue URL, and re-read the next unstarted brief against the API that actually landed. Look especially for:

- a second scale, tick, formatting, or scene authority hidden inside a kind, projection, or the CLI;
- float accumulation, `toFixed`, locale APIs, or `Date` construction leaking into chart numerics;
- an enhanced frame exceeding its declared honesty tier — quantization presented as exact, resolution undeclared, extremes unprinted;
- silent fact loss at quantization edges: zero-width nonzero bars, rounded-away stacked segments, overwritten scatter collisions, gaps conflated with zeros;
- misleading scale defaults: a truncated baseline, renderer-side binning, resampled series, min-relative scaling, or a dual axis smuggled in as an option;
- a series colour used without its paired non-colour cue, semantic state tones recruited as series colours, or a palette change without updating its pinned reference and rerunning the CVD/ANSI guards;
- accessibility prose, Markdown alt text, and terminal descriptions drifting apart, or alt text deriving from data values;
- a kind bypassing generated enrolment, omitting its stance or honesty tier, or a budget refusal without the exceeded dimension and a practical remedy;
- diagram behaviour changing at all during 1A (bytes, tests, public surface), or shared promotions copied instead of moved;
- hand-authored coordinates, raw SVG, or data-file ingestion presented as extensibility;
- React or a new dependency entering the neutral/CLI graph; copied algorithms without provenance;
- generated files hand-edited, tests weakened, or a consequential decision left outside an ADR.

Each completed wave moves its own brief into `_done/` in its final commit. After wave 6A lands and passes adversarial review, the surface is ready for the owner's release workflow and the separate Discern adoption programme.
